## v1 Requirements (All Shipped)

### Execution

- [x] **EXEC-01**: User can create an execution by submitting an objective, max bot count, allowed tools, budget cap (USD), and max runtime (minutes) — v1.0
- [x] **EXEC-02**: System returns an execution_id and initial status of "queued" upon execution creation — v1.0
- [x] **EXEC-03**: Execution transitions through lifecycle states: queued → running → paused → stopped → completed/failed — v1.0
- [x] **EXEC-04**: User can view the current status of any execution — v1.0
- [x] **EXEC-05**: System splits the objective into N independent parallelizable tasks and queues them for bot consumption — v1.0

### Bot Orchestration

- [x] **ORCH-01**: System spawns up to max_bots Docker containers when an execution transitions to running — v1.0
- [x] **ORCH-02**: Each bot claims tasks via atomic leasing (one task per bot at a time, no double-claiming) — v1.0
- [x] **ORCH-03**: Bot lease heartbeats are maintained; failed/expired leases result in task reassignment to another bot — v1.0
- [x] **ORCH-04**: Each bot container runs with no persistent filesystem, no direct internet access, CPU and memory capped — v1.0
- [x] **ORCH-05**: Bots automatically terminate after 5 minutes of idle time (no active task) — v1.0
- [x] **ORCH-06**: Bot lifecycle events (started, stopped, claimed task, completed task) are emitted to the event bus — v1.0

### Tool Gateway

- [x] **GATE-01**: Bots can only invoke tools by calling POST /tool.invoke through the Tool Gateway — no direct external access — v1.0
- [x] **GATE-02**: Tool Gateway enforces an allowlist; calls to tools not in the execution's allowed_tools list are rejected — v1.0
- [x] **GATE-03**: Tool Gateway validates argument schema (Zod) for every invocation; malformed arguments are rejected — v1.0
- [x] **GATE-04**: Tool Gateway enforces per-bot rate limits (tool calls/min, tokens/min); bots exceeding limits are blocked — v1.0
- [x] **GATE-05**: Tool Gateway logs every invocation with bot_id, tool, arguments, response summary, duration, and tokens used — v1.0
- [x] **GATE-06**: User can invoke llm_call tool — routes to configured LLM provider (multi-provider), response returned to bot — v1.0
- [x] **GATE-07**: User can invoke fetch_url tool — fetches URL content, domain allowlist enforced, content returned to bot — v1.0
- [x] **GATE-08**: User can invoke write_file tool — writes artifact to artifact store, path returned to bot — v1.0

### Guardrails

- [x] **GARD-01**: Execution stops automatically when cumulative spend reaches max_budget_usd (enforced via Redis atomic Lua script) — v1.0
- [x] **GARD-02**: Bot is revoked when it exceeds the token burn rate limit (max tokens/min), with event logged — v1.0
- [x] **GARD-03**: Bot is revoked when it exceeds the tool call rate limit (max tool calls/min), with event logged — v1.0
- [x] **GARD-04**: Guardrail watchdog detects and kills bots exhibiting loop/thrashing behavior (repetitive identical tool calls) — v1.0
- [x] **GARD-05**: Bot is terminated automatically after 5 minutes of idle time, with event logged — v1.0
- [x] **GARD-06**: All guardrail violations are captured as structured events: bot revoked, execution paused/stopped, reason, timestamp — v1.0

### Metering & Billing

- [x] **METR-01**: System captures metering events for every billing-relevant action: bot_started, bot_stopped, tool_invoked, execution_completed, budget_exceeded — v1.0
- [x] **METR-02**: System calculates bot-hours per execution as Σ(bot wall-clock runtime in hours) — v1.0
- [x] **METR-03**: System calculates estimated cost per execution using bot-hours × hourly rate + LLM token costs (provider-reported actuals) — v1.0
- [x] **METR-04**: User can see live bot-hours consumed, estimated cost, and remaining budget during an active execution — v1.0
- [x] **METR-05**: User can see historical executions with total cost, bot-hours, and task count per run on the Usage & Billing screen — v1.0

### Performance Intelligence

- [x] **PERF-01**: System computes per-bot efficiency metrics post-run: tasks/min, tokens/task, tool calls/task, idle ratio — v1.0
- [x] **PERF-02**: System computes per-bot reliability metrics post-run: success rate, retry rate, error frequency — v1.0
- [x] **PERF-03**: System computes per-bot cost efficiency post-run: cost per successful task — v1.0
- [x] **PERF-04**: System assigns each bot a composite performance score: Success Rate (40%) + Efficiency (30%) + Cost Efficiency (20%) + Stability (10%), normalized 0–100 — v1.0
- [x] **PERF-05**: Each bot is assigned a tier based on score: High (green, top tier), Medium (yellow), Low (red) — v1.0
- [x] **PERF-06**: Post-run execution report includes: total bots, total bot-hours, total cost, average bot score, top-performing bot, error distribution, cost per task — v1.0
- [x] **PERF-07**: User can view a bot leaderboard per execution showing each bot's tasks, runtime, score, and tier — v1.0

### DNA Capture

- [x] **DNA-01**: System identifies elite bot candidates post-run: score exceeds threshold AND above execution average by configured % AND low error rate — v1.0
- [x] **DNA-02**: System captures DNA for elite bots: system prompt, tool call sequence, argument patterns, retry strategy, decision branches, timing, token distribution — v1.0
- [x] **DNA-03**: DNA is stored as a versioned execution template, tagged by objective category — v1.0
- [x] **DNA-04**: DNA storage is PII-redacted and contains structural patterns only (no raw customer data) — v1.0

### UI — New Execution

- [x] **UI-01**: User can enter an objective (text), set max bots (slider), set budget cap ($), and select allowed tools (multi-select) on the New Execution screen — v1.0
- [x] **UI-02**: User can click "Deploy Crew" to submit the execution and be routed to the Live Execution View — v1.0

### UI — Live Execution View

- [x] **UI-03**: User sees current execution status (Running / Paused / Completed) on the Live Execution View — v1.0
- [x] **UI-04**: User sees active bot count, bot-hours consumed, budget remaining, and estimated cost — updated in real-time — v1.0
- [x] **UI-05**: User sees a live activity feed showing: bot claimed task, tool invoked, task completed, guardrail triggered — streamed via SSE — v1.0

### UI — Post-Execution Dashboard

- [x] **UI-06**: User sees execution summary after completion: total cost, total bot-hours, tasks completed, average score, top bot — v1.0
- [x] **UI-07**: User sees a bot leaderboard table with tier color indicators (High/Medium/Low) on the Post-Execution Dashboard — v1.0

### UI — Bot Detail View

- [x] **UI-08**: User can click any bot to see its detail view: tasks completed, runtime, token usage, tool calls, error count, performance score — v1.0
- [x] **UI-09**: Developer can expand an optional step trace in the bot detail view showing each step's prompt, response, tool, arguments, output summary, duration, tokens — v1.0

### UI — Usage & Billing

- [x] **UI-10**: User can see total bot-hours this month, estimated spend, list of historical executions, and cost per execution on the Usage & Billing screen — v1.0
