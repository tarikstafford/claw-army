# Requirements: Claw Bot Army — v2.0 The SOUL System

**Defined:** 2026-02-21
**Core Value:** Users deploy a crew of AI bots that gets measurably smarter with every run — behavioral constitutions evolve through a council-evaluated mutation engine, and the DNA library is the compounding moat no competitor can replicate without the run history.

---

## v2.0 Requirements

### SOUL — SOUL.md Infrastructure

- [ ] **SOUL-01**: Platform generates a unique SOUL.md document for each bot before VM spawn, containing 7 behavioral dimensions (identity/role, decision priorities, tool usage doctrine, risk tolerance, communication style, recovery behavior, ethical hard stops) and inviolable constitution directives that are never mutated away
- [ ] **SOUL-02**: Platform enforces a minimum of 3 agents per task category — execution is blocked with a plain explanation if budget is insufficient for minimum population; minimum is never reduced to fit a budget
- [ ] **SOUL-03**: Each soul document carries a content hash and generation counter, enabling full mutation lineage tracing from first Novice run to Artisan graduation
- [ ] **SOUL-04**: Platform maintains an archetype library of 6+ canonical soul templates (Cautious Verifier, Aggressive Executor, Creative Synthesizer, Structured Analyst, Collaborative Integrator, plus variants) used to seed populations for novel task categories

### SGEN — Soul Generation Engine

- [ ] **SGEN-01**: For known task categories, souls are generated via library-seeded mutation — top-performing historical souls queried as parents, mid-tier soul added as diversity injection parent
- [ ] **SGEN-02**: For novel task categories, souls are generated as an archetype spread using the library's canonical archetypes with light mutations to produce required population size
- [ ] **SGEN-03**: Soul generation applies 5 mutation operations: Substitution (replace directive with alternative), Amplification (strengthen directive specificity), Attenuation (soften over-triggering directive), Recombination (merge sections from two parents), Introduction (add novel directive from Pioneer annotations or human feedback)
- [ ] **SGEN-04**: Soul differentiation is enforced via embedding-based pairwise cosine similarity — any soul pair above the 0.85 threshold is flagged; the more recently mutated soul is remutated with a diversity instruction until all pairs are below threshold or maximum iterations reached
- [ ] **SGEN-05**: Constitution enforcement validates every generated soul against inviolable directives before deployment — souls violating constitution lines are rejected and regenerated; a population that cannot resolve violations after maximum iterations is flagged for human review before deployment

### DTRC — Decision Trace Collection

- [ ] **DTRC-01**: Agents annotate which soul directive drove each significant decision (tool call, reasoning branch, output step) at runtime — logged to decision_traces table with decision ID, decision type, directive referenced, attribution confidence, and outcome
- [ ] **DTRC-02**: Platform provides a post-hoc attribution fallback that compiles tool_invocations sequences into attribution reports when real-time annotation is unavailable from the OpenClaw runtime — both paths are built; whichever OpenClaw supports ships as primary
- [ ] **DTRC-03**: Decision traces are stored per agent per execution and retained for Council evaluation; a 90-day TTL archival policy is in place before the table reaches 5M rows

### CNCL — The Council

- [ ] **CNCL-01**: After each execution completes, 3 independent LLM judges (Performance Judge, Soul Analyst, Devil's Advocate) evaluate each agent's performance asynchronously via a dedicated council-queue BullMQ Worker (concurrency=5, separate from execution queue, with rate limiter)
- [ ] **CNCL-02**: Council judges produce outputs independently — no judge receives any other judge's output before producing its own; aggregation happens only after all three outputs are collected
- [ ] **CNCL-03**: Council judges use heterogeneous LLM model families to prevent self-enhancement bias — at minimum, the Devil's Advocate uses a different provider than the Performance Judge
- [ ] **CNCL-04**: Soul Analyst performs counterfactual verification of self-reported directive attribution — for each claimed directive driver, the Soul Analyst evaluates whether the decision trace would have differed without that directive; counterfactual score takes precedence over self-report when they disagree; disagreement rate is tracked as a system health metric
- [ ] **CNCL-05**: Council produces a weighted verdict per agent with confidence score: Performance Judge 50%, Soul Analyst 35%, Devil's Advocate 15% confidence deflator; a strong unresolved Devil's Advocate argument automatically escalates to human review regardless of aggregate score
- [ ] **CNCL-06**: Each agent receives one of 5 verdict types with a plain-language summary: Promote, Maintain, Monitor, Demote, Retire; confidence score and human confirmation requirement flag are attached to each verdict

### CONF — Human Confirmation Gate

- [ ] **CONF-01**: Promote and Retire verdicts require human confirmation via POST /verdicts/:verdictId/confirm before God Layer execution — Maintain, Monitor, and Demote verdicts execute automatically
- [ ] **CONF-02**: Confirmation prompt surfaces at least one concrete evidence item — a specific tool call sequence or the Devil's Advocate argument where one exists — before the confirm button appears
- [ ] **CONF-03**: Rejection is framed as a positive contribution ("Your feedback teaches the army") — rejection prompt and confirm prompt receive equivalent visual weight
- [ ] **CONF-04**: Platform tracks time-on-confirmation-screen; per-user confirmation rates above 95% across 10+ confirmations surface a calibration warning to the operator

### GODL — God Layer + DNA Library

- [ ] **GODL-01**: God Layer BullMQ Worker processes confirmed verdicts on a dedicated soul-verdicts queue — executes class transitions, DNA library writes, mutation cycle preparation, and negative signal register updates
- [ ] **GODL-02**: DNA Library entry contains: full SOUL.md document, task category tag, agent class at time of write, composite fitness score with dimension breakdown, causal attribution report summary, council verdict summary with confidence scores, human confirmation timestamp, mutation lineage (parent soul IDs + operations applied), and run metadata
- [ ] **GODL-03**: DNA Library writes are versioned — each write creates a new version linked to its predecessor; no write overwrites an existing entry; full evolutionary lineage from Novice to Artisan graduation is traceable
- [ ] **GODL-04**: Runs below minimum confidence threshold or lacking human confirmation (where required) are written to a provisional register — referenced but not used to seed future populations until confirmed by subsequent qualifying runs
- [ ] **GODL-05**: Retirements and below-benchmark runs are written to a negative signal register — the mutation algorithm queries this register to identify which directive combinations and mutation paths produced poor outcomes, using it as a constraint layer on future soul generation
- [ ] **GODL-06**: Pioneer events (first confirmed run in a novel task category) trigger benchmark instantiation — baseline set from first run metrics, benchmark matures after 3 confirmed comparable runs, thin data flag removed after 5 confirmed runs, standard promotion thresholds activate after 3 confirmed runs
- [ ] **GODL-07**: God Layer holds an execution-scoped Redis lock on the category soul library during active campaigns to prevent mid-run library mutations from affecting agents in flight; God Layer evaluates the `bot_souls` snapshot recorded at execution start (not the current library state)

### CLAS — Agent Class System

- [ ] **CLAS-01**: Each bot has an agent class (Novice, Understudy, Artisan) tracked per task category — class is domain-specific; an Artisan at lead generation is a Novice at CRM recovery if it has no prior runs in that category
- [ ] **CLAS-02**: Novice → Understudy promotion requires: minimum 2 confirmed above-benchmark runs in the task category, at least 1 human confirmation, council confidence score above 0.65, no unresolved Devil's Advocate arguments above severity threshold
- [ ] **CLAS-03**: Understudy → Artisan promotion requires: minimum 5 confirmed above-benchmark runs (no more than 1 below-benchmark in qualifying window), multiple human confirmations, council confidence score above 0.80, causal attribution confirming soul directives as primary performance drivers, Devil's Advocate arguments specifically overruled in council record; triggers user notification and full soul lineage write to DNA Library
- [ ] **CLAS-04**: Demotion triggers after 2 consecutive below-benchmark runs with council confidence above 0.70; Soul Analyst confirms underperformance is soul-driven (not context-driven) before demotion executes; if context-driven, a Monitor verdict is issued and next run is observed before reconsidering
- [ ] **CLAS-05**: Retirement triggers after confirmed demotion followed by 2 further below-benchmark runs, or after a catastrophic failure event (budget overrun, guardrail violation, minimum quality threshold breach); soul is permanently preserved in the library with full directive activation history and mutation lineage as negative signal
- [ ] **CLAS-06**: Pioneer events receive a permanent Pioneer designation in the library entry and are surfaced to users as meaningful notifications; Pioneer attribution is recorded regardless of subsequent class progression

### UIEX — UI Extensions

- [ ] **UIEX-01**: Post-run leaderboard displays each bot's agent class, tier badge (Novice / Understudy / Artisan), council verdict summary, and pioneer flag alongside existing performance metrics and cost
- [ ] **UIEX-02**: Pending Promote and Retire verdict notifications appear in the UI with a confirmation panel that surfaces at least one concrete evidence item before confirm/reject controls are available
- [ ] **UIEX-03**: SSE pushes narrative lifecycle event notifications to connected users for promotion, demotion, retirement, and pioneer events with human-readable descriptions ("Agent 7 has been promoted to Understudy after three successful lead generation campaigns")
- [ ] **UIEX-04**: Army Builder pre-execution UI identifies task categories in the submitted objective, displays available agent class mix per category, shows library-depth rationale ("47 confirmed runs — recommending 2 Artisans and 1 Understudy"), and presents a budget breakdown with three composition tiers (full / 75% / minimum viable at 3 Novices per task)
- [ ] **UIEX-05**: Army Builder enforces the minimum 3-agent-per-task constraint — execution is blocked with a plain explanation if minimum viable composition exceeds budget, never silently reduced

## Out of Scope

| Feature | Reason |
|---------|--------|
| User-editable raw soul text | Anti-feature — corrupts algorithmically-generated evolutionary space and makes lineage attribution impossible |
| Fine-tuning model weights from soul data | Requires RLHF infrastructure; out of scope for v2.0 |
| Real-time Council evaluation during execution | Council requires the complete decision trace; mid-run evaluation produces garbage attribution |
| 5+ agent class tiers | Research confirms 3 tiers is the RPG engagement optimum; more creates choice paralysis and slows the progression feedback loop |
| Continuous automated promotion without human gate | Miscalibrated council verdicts would silently degrade the DNA Library — human confirmation is the ground truth circuit breaker |
| All Council members from the same model family | Self-enhancement bias makes the Devil's Advocate ineffective — heterogeneous families are an architectural requirement |
| Agent marketplace / soul trading | Requires significant DNA Library depth first; long-term play, not v2.0 |
| Army composition sharing | Post-validation feature |
| DNA export (user-facing) | Internal tool only in v2.0; user-facing in v3.0 |
| Per-run soul mutation | Insufficient run count produces noisy signal — minimum 3–5 confirmed runs before Council eligibility enforced |
