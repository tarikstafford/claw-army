    4. Create `tsconfig.base.json` with the internal packages strategy:
       ```json
       {
         "compilerOptions": {
           "strict": true,
           "target": "ES2022",
           "module": "NodeNext",
           "moduleResolution": "NodeNext",
           "customConditions": ["@claw/source"],
           "declaration": true,
           "declarationMap": true,
           "composite": true,
           "esModuleInterop": true,
           "skipLibCheck": true,
           "forceConsistentCasingInFileNames": true,
           "resolveJsonModule": true,
           "isolatedModules": true,
           "noUncheckedIndexedAccess": true
         }
       }
       ```

    5. Create `.env.example` with:
       ```
       DATABASE_URL=postgresql://postgres:postgres@localhost:5432/clawdb
       REDIS_URL=redis://localhost:6379
       GCP_PROJECT_ID=claw-army-dev
       PUBSUB_EMULATOR_HOST=localhost:8085
       ```

    6. Create `packages/db/package.json`:
       ```json
       {
         "name": "@claw/db",
         "version": "0.0.1",
         "private": true,
         "type": "module",
         "main": "./src/index.ts",
         "types": "./src/index.ts",
         "exports": {
           ".": {
             "@claw/source": "./src/index.ts",
             "default": "./dist/index.js"
           }
         },
         "scripts": {
           "generate": "drizzle-kit generate",
           "migrate": "drizzle-kit migrate",
           "studio": "drizzle-kit studio"
         },
         "dependencies": {
           "drizzle-orm": "0.45.1",
           "pg": "^8.18.0",
           "dotenv": "^16.4.0"
         },
         "devDependencies": {
           "drizzle-kit": "0.31.9",
           "tsx": "^4.19.0",
           "@types/pg": "^8.11.0",
           "typescript": "^5.9.3"
         }
       }
       ```
       Note: Use the internal packages strategy — `main` and `types` point to `.ts` source files directly to avoid the Drizzle [IsDrizzleTable] monorepo bug (see RESEARCH.md Pitfall 2).

    7. Create `packages/db/tsconfig.json` extending the base config:
       ```json
       {
         "extends": "../../tsconfig.base.json",
         "compilerOptions": {
           "rootDir": "./src",
           "outDir": "./dist"
         },
         "include": ["src/**/*.ts"]
       }
       ```

    8. Create `packages/db/drizzle.config.ts`:
       ```typescript
       import 'dotenv/config';
       import { defineConfig } from 'drizzle-kit';

       export default defineConfig({
         out: './migrations',
         schema: './src/schema/**/*.ts',
         dialect: 'postgresql',
         dbCredentials: {
           url: process.env.DATABASE_URL!,
         },
       });
       ```

    9. Create `packages/db/src/client.ts`:
       ```typescript
       import 'dotenv/config';
       import { drizzle } from 'drizzle-orm/node-postgres';
       import * as schema from './schema/index.js';

       export const db = drizzle(process.env.DATABASE_URL!, { schema });
       export type Database = typeof db;
       ```

    10. Create `packages/db/src/index.ts` that re-exports everything:
        ```typescript
        export { db, type Database } from './client.js';
        export * from './schema/index.js';
        ```

    11. Update `.gitignore` to include: `node_modules/`, `dist/`, `.env`, `.env.local`, `*.tsbuildinfo`.

    12. Run `pnpm install` from repo root to verify workspace resolution succeeds.

  <action>
    Create all six Drizzle schema files in `packages/db/src/schema/`. Each file exports the table definition, enum(s) if any, and inferred `$inferSelect` and `$inferInsert` types.

    **Schema Design Decisions (from ROADMAP.md requirements and RESEARCH.md):**
    - All monetary values stored as `integer` (cents) — NEVER float. Research Open Question 3 resolved: use integer cents.
    - All timestamps use `{ withTimezone: true, precision: 3 }` for sub-second accuracy and timezone safety.
    - All primary keys are `uuid().primaryKey().defaultRandom()`.
    - Use `pgEnum` for all enumerated status columns.
    - Add indexes on foreign keys and frequently-queried columns.

    **1. `executions.ts`** — Execution lifecycle (EXEC requirements):
    - `id`: uuid PK
    - `status`: pgEnum `execution_status` = ['queued', 'running', 'paused', 'stopped', 'completed', 'failed']
    - `objective`: text, not null
    - `maxBots`: integer('max_bots'), not null
    - `budgetCapCents`: integer('budget_cap_cents'), not null — monetary value in cents
    - `runtimeLimitSeconds`: integer('runtime_limit_seconds'), not null
    - `allowedTools`: text('allowed_tools').array(), not null
    - `createdAt`, `updatedAt`: timestamps
    - Exports: `executions`, `executionStatusEnum`, `Execution`, `NewExecution`

    **2. `tasks.ts`** — Task queue with lease semantics (ORCH requirements):
    - `id`: uuid PK
    - `executionId`: uuid FK → executions.id, onDelete cascade
    - `status`: pgEnum `task_status` = ['pending', 'claimed', 'completed', 'failed']
    - `description`: text, not null
    - `result`: text, nullable — task output/result
    - `claimedByBotId`: uuid, nullable
    - `leaseExpiresAt`: timestamp, nullable
    - `attemptCount`: integer, default 0
    - `createdAt`, `updatedAt`: timestamps
    - Indexes: `execution_id`, `status`, composite `(execution_id, status)` for claim queries
    - Exports: `tasks`, `taskStatusEnum`, `Task`, `NewTask`

    **3. `bots.ts`** — Bot lifecycle (ORCH requirements):
    - `id`: uuid PK
    - `executionId`: uuid FK → executions.id, onDelete cascade
    - `status`: pgEnum `bot_status` = ['spawning', 'idle', 'working', 'stopping', 'stopped', 'failed']
    - `containerId`: varchar(255), nullable — Docker container ID
    - `imageTag`: varchar(255), not null
    - `startedAt`: timestamp, nullable
    - `stoppedAt`: timestamp, nullable
    - `lastHeartbeatAt`: timestamp, nullable
    - `tasksClaimed`: integer, default 0
    - `tasksCompleted`: integer, default 0
    - `tasksFailed`: integer, default 0
    - `createdAt`, `updatedAt`: timestamps
    - Indexes: `execution_id`, `status`
    - Exports: `bots`, `botStatusEnum`, `Bot`, `NewBot`

    **4. `billing-events.ts`** — Billing metering (METR requirements):
    - `id`: uuid PK
    - `executionId`: uuid FK → executions.id, onDelete cascade
    - `botId`: uuid, nullable
    - `eventType`: pgEnum `billing_event_type` = ['bot_started', 'bot_stopped', 'tool_invoked', 'execution_completed', 'budget_exceeded']
    - `amountCents`: integer, nullable — cost in cents
    - `tokenCount`: integer, nullable — for LLM invocations
    - `metadata`: jsonb, nullable — flexible event-specific data
    - `occurredAt`: timestamp, not null, defaultNow
    - Indexes: `execution_id`, `event_type`, `occurred_at`
    - Exports: `billingEvents`, `billingEventTypeEnum`, `BillingEvent`, `NewBillingEvent`

    **5. `telemetry.ts`** — Performance metrics (PERF requirements):
    - `id`: uuid PK
    - `executionId`: uuid FK → executions.id, onDelete cascade
    - `botId`: uuid FK → bots.id, onDelete cascade
    - `metricName`: varchar(255), not null — e.g. 'tasks_per_minute', 'tokens_per_task', 'success_rate'
    - `metricValue`: numeric('metric_value', { precision: 12, scale: 6 }), not null — high precision for rates
    - `computedAt`: timestamp, not null, defaultNow
    - Indexes: `execution_id`, `bot_id`, composite `(bot_id, metric_name)`
    - Exports: `telemetry`, `Telemetry`, `NewTelemetry`

    **6. `dna-store.ts`** — DNA capture (DNA requirements):
    - `id`: uuid PK
    - `botId`: uuid, not null
    - `executionId`: uuid FK → executions.id, onDelete cascade
    - `objectiveCategory`: varchar(255), not null
    - `version`: integer, not null, default 1
    - `compositeScore`: numeric('composite_score', { precision: 5, scale: 2 }), not null
    - `dnaPayload`: jsonb('dna_payload').$type<DnaPayload>(), not null
      Define `DnaPayload` interface with: `systemPromptTemplate`, `toolCallSequence`, `argumentPatterns`, `retryStrategy`, `timingProfile`, `tokenDistribution`
    - `capturedAt`: timestamp, not null, defaultNow
    - Indexes: `execution_id`, `bot_id`, `objective_category`, composite `(objective_category, version)`
    - Exports: `dnaStore`, `DnaPayload`, `DnaStore`, `NewDnaStore`

    **7. `index.ts`** — Re-export barrel:
    ```typescript
    export * from './executions.js';
    export * from './tasks.js';
    export * from './bots.js';
    export * from './billing-events.js';
    export * from './telemetry.js';
    export * from './dna-store.js';
    ```

    **8. Generate and verify migration:**
    - Start a local PostgreSQL (use Docker: `docker run --name claw-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=clawdb -p 5432:5432 -d postgres:16-alpine`)
    - Create `.env` in `packages/db/` with `DATABASE_URL=postgresql://postgres:postgres@localhost:5432/clawdb`
    - Run `pnpm --filter @claw/db generate` to produce the SQL migration
    - Run `pnpm --filter @claw/db migrate` to apply it
    - Verify all 6 tables exist: `docker exec claw-pg psql -U postgres -d clawdb -c "\dt"`
    - Commit the generated migration files in `packages/db/migrations/`

    **IMPORTANT:** Use `numeric` (not float/real) for monetary precision and metric values. Use `integer` for cents. Never use JavaScript `number` for money stored in the database.
  </action>

    - `pnpm --filter @claw/db generate` produces migration SQL file(s) in `packages/db/migrations/`
    - `pnpm --filter @claw/db migrate` applies migration with zero errors
    - `docker exec claw-pg psql -U postgres -d clawdb -c "\dt"` shows all 6 tables
    - `docker exec claw-pg psql -U postgres -d clawdb -c "\d executions"` shows correct columns and types
    - `docker exec claw-pg psql -U postgres -d clawdb -c "SELECT enum_range(NULL::execution_status)"` returns the 6 statuses
  </verify>
