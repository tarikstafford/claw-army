**src/main.ts:**

The stub bot is a simple BullMQ Worker process. It:
1. Reads environment variables: `BOT_ID`, `EXECUTION_ID`, `REDIS_URL`, `DATABASE_URL`
2. Creates an ioredis connection with `maxRetriesPerRequest: null`
3. Creates a BullMQ Worker for queue `'claw-tasks'` with:
   - `lockDuration: 30_000`
   - `stalledInterval: 15_000`
   - `maxStalledCount: 2`
   - `concurrency: 1`
4. The processor function:
   a. Record `const claimStartMs = Date.now()`
   b. Logs "Claiming task {taskId}"
   c. Updates Postgres: `tasks SET status='claimed', claimedByBotId=BOT_ID, leaseExpiresAt=now+30s, attemptCount=attemptCount+1 WHERE id=taskId`
   d. Publish `task_claimed` event: `publishTaskClaimed({ type: 'task_claimed', taskId, botId: BOT_ID, executionId: EXECUTION_ID, timestamp: new Date().toISOString() })`
   e. Simulates work: `await new Promise(r => setTimeout(r, 1000 + Math.random() * 1000))` (1-2 second random delay)
   f. Updates Postgres: `tasks SET status='completed', result='Stub completion', updatedAt=now WHERE id=taskId`
   g. Updates bot row: increment `tasksCompleted` counter
   h. Publish `task_completed` event: `publishTaskCompleted({ type: 'task_completed', taskId, botId: BOT_ID, executionId: EXECUTION_ID, durationMs: Date.now() - claimStartMs, timestamp: new Date().toISOString() })`
   i. Logs "Completed task {taskId}"
   j. Returns the result string

**Pub/Sub setup in stub-bot main.ts:**

The stub-bot creates its own lightweight publisher (it cannot import the execution-service's publisher.ts since it's a separate container):

```typescript
import { PubSub } from '@google-cloud/pubsub';
import {
  taskClaimedEventSchema,
  taskCompletedEventSchema,
  type TaskClaimedEvent,
  type TaskCompletedEvent,
} from '@claw/event-schemas';

const pubsub = new PubSub({ projectId: process.env.GCP_PROJECT_ID ?? 'claw-local' });
const TASK_EVENTS_TOPIC = 'task-events';

async function publishTaskClaimed(event: TaskClaimedEvent): Promise<void> {
  try {
    taskClaimedEventSchema.parse(event);
    await pubsub.topic(TASK_EVENTS_TOPIC).publishMessage({
      data: Buffer.from(JSON.stringify(event)),
    });
  } catch (err) {
    console.error('[stub-bot] Failed to publish task_claimed:', err);
  }
}

async function publishTaskCompleted(event: TaskCompletedEvent): Promise<void> {
  try {
    taskCompletedEventSchema.parse(event);
    await pubsub.topic(TASK_EVENTS_TOPIC).publishMessage({
      data: Buffer.from(JSON.stringify(event)),
    });
  } catch (err) {
    console.error('[stub-bot] Failed to publish task_completed:', err);
  }
}
```

5. Attaches `worker.on('error', ...)` handler
6. Attaches `worker.on('completed', ...)` handler to log completions
7. Logs "Stub bot {BOT_ID} ready, waiting for tasks..."
8. On `SIGTERM`: gracefully close the worker (`worker.close()`), close ioredis connection, exit

**Important:** The worker's concurrency is 1 — one task at a time per bot. BullMQ's atomic locking ensures no two workers claim the same job. When the bot claims a task in BullMQ, it also updates the Postgres `tasks` row to reflect the claim (dual-write from the bot side).

Update the existing `setImmediate` block (from Plan 02-02) to add bot spawning and completion polling after planning:

```typescript
setImmediate(async () => {
  try {
    // 1. Plan tasks (stub — no LLM) [from 02-02]
    const plannedTasks = planObjective(objective, maxBots);

    // 2. Dual-write: Postgres first, then BullMQ [from 02-02]
    for (const planned of plannedTasks) {
      const result = await db.insert(tasks).values({
        executionId,
        description: planned.description,
        status: 'pending',
      }).returning({ id: tasks.id });

      if (result.length > 0) {
        const taskRow = result[0]!;
        await addTaskToQueue({
          taskId: taskRow.id,
          executionId,
          description: planned.description,
        });
      }
    }

    // 3. Transition to 'running' [from 02-02]
    const transitioned = await transitionExecution(executionId, 'queued', 'running');
    if (!transitioned) {
      fastify.log.error({ executionId }, 'Failed to transition to running');
      return;
    }

    // 4. Spawn bots [NEW from 02-03/02-04]
    await spawnBotsForExecution(executionId, maxBots);
    fastify.log.info({ executionId, botCount: maxBots, taskCount: plannedTasks.length }, 'Bots spawned, execution running');

    // 5. Start QueueEvents listener to keep lastTaskClaimedAt fresh [NEW from 02-03 revision]
    // This prevents the idle checker from killing bots that are actively processing tasks.
    startQueueEventListener();

    // 6. Start idle checker and completion polling [NEW from 02-03/02-04]
    startIdleChecker();
    startCompletionPoller(executionId);
  } catch (err) {
    fastify.log.error({ err, executionId }, 'Failed during execution pipeline');
    await transitionExecution(executionId, 'queued', 'failed').catch(() => {});
    await transitionExecution(executionId, 'running', 'failed').catch(() => {});
  }
});
```
