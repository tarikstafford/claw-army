  <action>
    In services/ui, run:
      pnpm add @auth/sveltekit

    This installs @auth/sveltekit (^1.11.1 or latest stable). Use the version resolved by pnpm — do not pin manually unless pnpm fails.

    Create services/ui/src/auth.ts:
      import { SvelteKitAuth } from '@auth/sveltekit';
      import Google from '@auth/sveltekit/providers/google';

      export const { handle, signIn, signOut } = SvelteKitAuth({
        providers: [Google],
        // AUTH_SECRET, AUTH_GOOGLE_ID, AUTH_GOOGLE_SECRET are auto-read from env
        // AUTH_TRUST_HOST is automatically true on Vercel; set it in local .env for dev
      });

    Create services/ui/src/hooks.server.ts:
      export { handle } from './auth';

    Create or update services/ui/src/app.d.ts. If the file already exists, merge the App namespace augmentation. If it does not exist, create it:
      // See https://svelte.dev/docs/kit/types#app.d.ts
      // for information about these interfaces
      declare global {
        namespace App {
          // interface Error {}
          interface Locals {
            auth(): Promise<import('@auth/sveltekit').Session | null>;
          }
          // interface PageData {}
          // interface PageState {}
          // interface Platform {}
        }
      }
      export {};

    Create services/ui/src/routes/auth/[...auth]/+server.ts (create the directories auth/ and [...auth]/ if they do not exist):
      export { GET, POST } from '../../../auth';

    WHY catch-all route: Auth.js registers its own handler for /auth/callback/google, /auth/signin, /auth/signout, etc. The catch-all [...auth] route delegates all these paths to Auth.js's handle exports.

    WHY '../../../auth' (three levels): The route is at src/routes/auth/[...auth]/+server.ts — three directories up from the route file reaches src/, where auth.ts lives. The path must use extensionless import (no .ts) per SvelteKit conventions.
  </action>

  <action>
    Create or update services/ui/.env.example. If the file exists, append to it. If not, create it.

    Add the following block (do not include actual secrets — only placeholder values):

      # Auth.js Google OAuth
      # Generate AUTH_SECRET with: openssl rand -base64 32
      AUTH_SECRET=your-secret-here

      # Google OAuth credentials
      # Set up at: Google Cloud Console -> APIs & Services -> Credentials
      # Authorized redirect URI for local dev: http://localhost:5173/auth/callback/google
      AUTH_GOOGLE_ID=your-google-client-id
      AUTH_GOOGLE_SECRET=your-google-client-secret

      # Required for non-Vercel environments (local dev)
      AUTH_TRUST_HOST=true

      # URL of execution-service for server-side calls (not the /api proxy)
      # Server actions run on Vercel and must call the service directly
      EXECUTION_SERVICE_URL=http://34.136.15.56:3001

    Also update services/execution-service/.env.example if it exists, or create it:

      # Auth.js shared secret — must match exactly what services/ui uses
      # The execution-service uses this to verify Auth.js session tokens
      AUTH_SECRET=your-secret-here

    WHY EXECUTION_SERVICE_URL: Server actions in SvelteKit run on Vercel serverless functions. They cannot call /api/executions (which is a Vercel rewrite proxy). They must call the execution-service URL directly. This var is needed in Plan 05.

    WHY AUTH_TRUST_HOST: Vercel automatically sets AUTH_TRUST_HOST=true. Local dev needs it explicitly or Auth.js throws "Host must be trusted" errors.
  </action>
