**Constants:**
```
EMBEDDING_MODEL = openai.embeddingModel('text-embedding-3-small')  // 1536 dimensions -- matches bot_souls.embedding column
SIMILARITY_THRESHOLD = 0.85
MIN_POPULATION = 3
MAX_MUTATION_ITERATIONS = 5
MUTATION_OPERATIONS_FULL = ['substitution', 'amplification', 'attenuation', 'recombination', 'introduction']
MUTATION_OPERATIONS_LIGHT = ['substitution', 'attenuation']
MUTATION_TEMPERATURE_KNOWN = 0.4
MUTATION_TEMPERATURE_NOVEL = 0.2
```

**Imports:**
- `{ generateText, embedMany, cosineSimilarity }` from `'ai'`
- `{ openai }` from `'@ai-sdk/openai'`
- `{ db, botSouls, bots }` from `'@claw/db'`
- `{ eq, and, desc, isNotNull, isNull, sql }` from `'drizzle-orm'`
- `{ createHash }` from `'node:crypto'`
- `type { SoulDimension }` from `'@claw/shared-types'`

**Public export -- single entry point:**
```typescript
export async function generateSoulPopulation(
  executionId: string,
  objective: string,
  populationSize: number,
): Promise<Array<{ soulId: string; soulContent: string }>>
```

**Pipeline implementation inside generateSoulPopulation:**

1. **classifyTaskCategory(objective):** Internal function. Use `generateText` with `openai('gpt-4o-mini')`, temperature 0.1. System prompt: classify objective into a short category label (3-5 words, lowercase, hyphenated). Parse result: `text.trim().toLowerCase().replace(/\s+/g, '-')`. Return the category string.

2. **Determine known vs novel path:** Query `bot_souls` for rows matching `taskCategory` that have a `botId` (non-archetype historical souls). If >= 1 historical soul exists, use KNOWN path. Otherwise, NOVEL path. Store the result as `const isNovelPath: boolean`.

3. **KNOWN path (SGEN-01):** Query top-5 historical souls by joining `botSouls` with `bots` on `botSouls.botId = bots.id`, ordering by `bots.compositeScore DESC`, where `botSouls.taskCategory = taskCategory` and `botSouls.botId IS NOT NULL`. Then query 1 mid-tier diversity parent: same query but `OFFSET 2 LIMIT 1` (skip top-2, take the 3rd-ranked as diversity). Build parent pool = top-5 + diversity parent. For each soul in populationSize, pick a parent via round-robin from the pool.

4. **NOVEL path (SGEN-02):** Query all archetypes: `db.select().from(botSouls).where(eq(botSouls.isArchetype, true))`. Round-robin assign archetypes as parents: `archetypes[i % archetypes.length]`.

5. **Mutation (SGEN-03) -- path-conditional behavior:**

   The mutation step differs between known and novel paths to satisfy SGEN-02's "light mutations" requirement for novel categories. Novel categories use archetype parents that already represent distinct behavioral profiles; aggressive mutation would destroy the archetype spread that is the entire point of SGEN-02.

   **KNOWN path:** Apply one of all 5 mutation operations, cycling through `MUTATION_OPERATIONS_FULL[i % 5]`. Use temperature `MUTATION_TEMPERATURE_KNOWN` (0.4). This allows full behavioral exploration from proven parents.

   **NOVEL path (light mutations per SGEN-02):** Apply one of only 2 operations, cycling through `MUTATION_OPERATIONS_LIGHT[i % 2]` (Substitution and Attenuation only). Use temperature `MUTATION_TEMPERATURE_NOVEL` (0.2). Substitution swaps a single directive, Attenuation softens one -- both are conservative operations that preserve the archetype's core identity while still producing differentiation. Amplification, Recombination, and Introduction are excluded because they add specificity, merge profiles, or inject novelty that would erode the archetype spread.

   Each mutation is an LLM call via `generateText` with `openai('gpt-4o-mini')`. The system prompt specifies:
   - The mutation operation type and its specific instruction (see RESEARCH.md Pattern 8 for the 5 operation descriptions)
   - Explicit instruction: "The following Constitution lines are INVIOLABLE. They must appear VERBATIM in your output. Do not modify, remove, or rephrase them:" followed by the parent's `constitutionDirectives` array joined by newlines
   - The user prompt is the parent's `soulContent`
   - The response is the full mutated SOUL.md content

   For `recombination` specifically (known path only): requires TWO parents. Pick parent A as the assigned parent and parent B as the next parent in the pool (wrap around). Pass both soul contents to the LLM.

   Implementation pattern:
   ```typescript
   const operations = isNovelPath ? MUTATION_OPERATIONS_LIGHT : MUTATION_OPERATIONS_FULL;
   const temperature = isNovelPath ? MUTATION_TEMPERATURE_NOVEL : MUTATION_TEMPERATURE_KNOWN;
   const operation = operations[i % operations.length];
   ```

6. **Constitution validation (SGEN-05):** After each mutation, call `validateConstitution(soulContent, constitutionDirectives)`. This checks that every directive string from the parent's `constitutionDirectives` array appears verbatim in the mutated `soulContent` using `soulContent.includes(directive)`. If validation fails, regenerate (re-call the mutation LLM) up to `MAX_MUTATION_ITERATIONS`. If max iterations exceeded, set `humanReviewFlag = true` on the soul and use the last generated content (log a warning).

7. **Embedding generation (SGEN-04):** After all souls are mutated and validated, call `embedMany({ model: EMBEDDING_MODEL, values: souls.map(s => s.soulContent) })`. This returns `{ embeddings: number[][] }` where each embedding is 1536 dimensions.

8. **Pairwise differentiation enforcement (SGEN-04):** Loop through all pairs `(i, j)` where `i < j`. Compute `cosineSimilarity(embeddings[i], embeddings[j])`. If similarity > `SIMILARITY_THRESHOLD`:
   - Re-mutate soul `j` with an additional diversity instruction prepended to the system prompt: "IMPORTANT: The previous mutation produced a soul too similar to another soul in the population. Apply a MORE AGGRESSIVE mutation that changes at least 2 behavioral dimensions significantly."
   - Re-embed soul `j` only (single `embed()` call)
   - Re-check ALL pairs involving soul `j`
   - Track iteration count per pair. After `MAX_MUTATION_ITERATIONS` per pair, set `humanReviewFlag = true` on the offending soul and proceed.

9. **Persist to database:** For each soul, compute `contentHash = createHash('sha256').update(soulContent, 'utf8').digest('hex')`. Parse the mutated soul content to extract dimensions (use a simple section-header parser that reads ## Identity and Role, ## Decision Priorities, etc. and extracts the text under each header as the dimension value). Insert into `botSouls`:
   ```typescript
   const [inserted] = await db.insert(botSouls).values({
     executionId,
     taskCategory,
     soulContent,
     contentHash,
     generation: parentSoul.generation + 1,
     parentSoulId: parentSoul.id,
     dimensions: parsedDimensions,
     constitutionDirectives: parentSoul.constitutionDirectives,
     embedding: embeddings[i],
     isArchetype: false,
   }).returning({ id: botSouls.id });
   ```

10. **Return:** `Array<{ soulId: inserted.id, soulContent }>` with exactly `populationSize` entries.

- `validateConstitution(soulContent: string, directives: string[]): { valid: boolean; violations: string[] }`
- `parseDimensions(soulContent: string): SoulDimension` -- extracts dimension text from markdown headers
