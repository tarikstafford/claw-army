**executions.ts -- Budget enforcement + soul generation wiring:**

1. **Budget enforcement (SOUL-02):** Two layers of enforcement -- custom guard for a human-readable message, plus schema minimum as defense-in-depth.

   First, change the TypeBox schema: `maxBots: Type.Integer({ minimum: 3, maximum: 20 })`. This keeps schema-level defense-in-depth.

   Second, add a **custom guard** at the TOP of the POST `/` handler body, BEFORE any other logic. This guard runs before schema validation produces a generic error, providing the plain human-readable explanation required by SOUL-02:
   ```typescript
   const MIN_POPULATION = 3;

   // SOUL-02: Custom guard for human-readable minimum population message.
   // TypeBox schema also enforces minimum:3 as defense-in-depth, but its
   // error message is a generic JSON Schema validation string.
   if (body.maxBots < MIN_POPULATION) {
     return reply.code(400).send({
       error: `A minimum of ${MIN_POPULATION} bots is required to maintain a meaningfully differentiated soul population. Increase maxBots to at least ${MIN_POPULATION}.`,
     });
   }
   ```

   Note: Because Fastify validates the TypeBox schema BEFORE the handler runs, the custom guard acts as a belt-and-suspenders fallback. If Fastify's schema validation runs first, it will already reject with a 400. However, if schema validation behavior changes or is bypassed (e.g., during testing with `inject`), the custom guard provides the explicit plain-language message. Place the guard at the top of the handler regardless, so the intent is clear in the code.

   Additionally, add a 400 response schema to handle both validation and custom guard errors:
   ```typescript
   400: Type.Object({
     error: Type.String(),
   }),
   ```
