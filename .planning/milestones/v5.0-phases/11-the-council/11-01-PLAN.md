Create the `services/execution-service/src/council/` directory with three judge modules. Each judge follows the same structure: Zod output schema, system prompt constant, context-to-prompt builder function, and single exported async evaluation function. All three use the AI SDK 6 pattern: `generateText` + `Output.object({ schema })`.

**CRITICAL:** Each judge receives only `CouncilContext` (from `../queue/council-queue`). No judge receives another judge's output. Independence is structural.

**CRITICAL:** Use `generateText` + `Output.object({ schema })` — NOT `generateObject` (deprecated in ai@6).

**A. performance-judge.ts**

1. Define `PerformanceJudgeOutputSchema` (Zod):
   - `verdictType`: z.enum(['Promote', 'Maintain', 'Monitor', 'Demote', 'Retire'])
   - `confidence`: z.number().min(0).max(1) — how confident the judge is in the verdict
   - `summary`: z.string() — plain-language verdict summary (CNCL-06)
   - `reasoning`: z.string() — evidence-based reasoning
   - `keyMetrics`: z.object({ successRate: z.number(), compositeScore: z.number(), tier: z.string() })

2. Export type `PerformanceJudgeOutput = z.infer<typeof PerformanceJudgeOutputSchema>`.

3. System prompt `PERFORMANCE_JUDGE_SYSTEM`: You are the Performance Judge on a council evaluating AI agent performance. Your role is to assess the agent's task execution effectiveness based on quantitative metrics. Evaluate success rate (tasks completed vs claimed), composite score, tier ranking, and decision quality. You must recommend one of five verdict types: Promote (exceptional, ready for advancement), Maintain (solid, keep current status), Monitor (concerning patterns, needs watching), Demote (poor performance, reduce responsibilities), Retire (fundamentally ineffective, remove from rotation). Be evidence-driven. Cite specific metrics in your reasoning.

4. `buildPerformancePrompt(ctx: CouncilContext): string` — formats bot metrics, telemetry metrics, decision trace summary (count by type, count by outcome), soul content excerpt (first 500 chars if available), task category.

5. Export `async function runPerformanceJudge(ctx: CouncilContext): Promise<PerformanceJudgeOutput>` — calls `generateText` with `anthropic('claude-sonnet-4-6')`, `Output.object({ schema: PerformanceJudgeOutputSchema })`, temperature 0.2.

6. If `output` is null (schema validation failed), throw an error: `'Performance Judge returned null output — schema validation failed'`.

**B. soul-analyst.ts**

1. Define `SoulAnalystOutputSchema` (Zod):
   - `directiveAttributionVerification`: z.array(z.object({
       decisionId: z.string(),
       directiveReferenced: z.string(),
       selfReportedConfidence: z.number(),
       counterfactualScore: z.number().min(0).max(1) — 0 means directive was NOT causal,
       counterfactualOverrides: z.boolean() — true when delta exceeds threshold,
       reasoning: z.string(),
     }))
   - `overallSoulAlignment`: z.number().min(0).max(1)
   - `verdictType`: z.enum(['Promote', 'Maintain', 'Monitor', 'Demote', 'Retire'])
   - `confidence`: z.number().min(0).max(1)
   - `summary`: z.string()
   - `disagreementRate`: z.number().min(0).max(1) — proportion of traces where counterfactual overrides self-report

2. Export type `SoulAnalystOutput = z.infer<typeof SoulAnalystOutputSchema>`.

3. Define constant `COUNTERFACTUAL_OVERRIDE_THRESHOLD = 0.25`.

4. System prompt `SOUL_ANALYST_SYSTEM`: You are the Soul Analyst on a council evaluating AI agent performance. Your unique role is counterfactual verification of directive attribution. For each decision where the agent claims a soul directive influenced its behavior, you must evaluate: "Would this decision have been meaningfully different if this specific directive had NOT been present in the agent's soul constitution?" Score each claim from 0.0 (directive had NO causal influence — agent would have done the same thing regardless) to 1.0 (directive was the primary driver of this specific decision). When your counterfactual score disagrees with the agent's self-reported confidence by more than 0.25, flag it as an override — this means the agent's self-attribution is unreliable for that decision. Also assess overall soul alignment: how well did the agent's actual behavior match its soul constitution as a whole? Recommend a verdict type based on soul integrity and attribution reliability.

5. `buildSoulAnalystPrompt(ctx: CouncilContext): string` — formats soul content in full, constitution directives as numbered list, and ONLY the decision traces where `attributionConfidence` is not null AND `parseFloat(attributionConfidence) > 0.5` AND `directiveReferenced` is not null. Cap at 20 traces (take the first 20 after filtering). If no qualifying traces exist, include a note: "No high-confidence directive attributions to verify. Evaluate overall soul alignment only."

6. Export `async function runSoulAnalyst(ctx: CouncilContext): Promise<SoulAnalystOutput>`:
   - Call `generateText` with `anthropic('claude-sonnet-4-6')`, `Output.object({ schema: SoulAnalystOutputSchema })`, temperature 0.2.
   - If `output` is null, throw: `'Soul Analyst returned null output — schema validation failed'`.
   - Post-process: for each item in `output.directiveAttributionVerification`, compute `counterfactualOverrides` as `Math.abs(item.counterfactualScore - item.selfReportedConfidence) > COUNTERFACTUAL_OVERRIDE_THRESHOLD`. Override the LLM's value with this computed value (the threshold logic is deterministic, not LLM-dependent).
   - Recompute `disagreementRate`: count of items where `counterfactualOverrides === true` divided by total items. If zero items, disagreementRate = 0.
   - Return the output with corrected `counterfactualOverrides` and `disagreementRate`.

**C. devils-advocate.ts**

1. Define `DevilsAdvocateOutputSchema` (Zod):
   - `challenges`: z.array(z.object({
       claim: z.string() — what the agent or other evidence claims,
       counterArgument: z.string() — why this might be wrong,
       severity: z.enum(['minor', 'moderate', 'strong']),
     }))
   - `strongUnresolvedArgument`: z.boolean() — true when any challenge has severity 'strong' (CNCL-05: triggers human review escalation)
   - `verdictType`: z.enum(['Promote', 'Maintain', 'Monitor', 'Demote', 'Retire'])
   - `confidence`: z.number().min(0).max(1) — LOW confidence means strong challenges remain (acts as deflator in weighted aggregation)
   - `summary`: z.string()

2. Export type `DevilsAdvocateOutput = z.infer<typeof DevilsAdvocateOutputSchema>`.

3. System prompt `DEVILS_ADVOCATE_SYSTEM`: You are the Devil's Advocate on a council evaluating AI agent performance. Your role is adversarial: actively challenge the evidence that the agent performed well. Look for alternative explanations for apparent success (easy tasks, favorable conditions, luck). Question whether directive attributions are genuine or post-hoc rationalization. Identify potential risks of promoting this agent. Your challenges should be specific and evidence-based, not generic skepticism. Rate each challenge's severity: minor (nitpick, unlikely to matter), moderate (legitimate concern, warrants monitoring), strong (serious issue that should block promotion or trigger demotion). If you have at least one 'strong' severity challenge that the evidence cannot resolve, set strongUnresolvedArgument to true — this will escalate the verdict to human review. Your confidence score should be LOW when strong challenges remain (this deflates the overall verdict confidence). Use a different analytical lens than a performance-focused evaluation.

4. `buildDevilPrompt(ctx: CouncilContext): string` — formats bot metrics, decision traces (all of them, not filtered — the DA needs the full picture including failed/rejected decisions), soul content, task category. Emphasize failures and rejected tool calls in the prompt formatting.

5. Export `async function runDevilsAdvocate(ctx: CouncilContext): Promise<DevilsAdvocateOutput>`:
   - Call `generateText` with `google('gemini-2.5-flash')`, `Output.object({ schema: DevilsAdvocateOutputSchema })`, temperature 0.5 (higher for adversarial creativity).
   - If `output` is null, throw: `'Devil\'s Advocate returned null output — schema validation failed'`.
   - Post-process: recompute `strongUnresolvedArgument` deterministically as `output.challenges.some(c => c.severity === 'strong')`. Override the LLM's value (structural guarantee).
   - Return the output with corrected `strongUnresolvedArgument`.
