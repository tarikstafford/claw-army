Create `services/execution-service/src/routes/verdicts.ts` as a `FastifyPluginAsyncTypebox` plugin (following the exact pattern from `bots.ts`). Import from `@sinclair/typebox`, `@fastify/type-provider-typebox`, `@claw/db`, and `drizzle-orm`.

Implement four endpoints:

**1. GET /pending** — List pending Promote/Retire verdicts
- Query: `db.select({...}).from(councilVerdicts).where(and(inArray(councilVerdicts.verdictType, ['Promote', 'Retire']), eq(councilVerdicts.status, 'pending'))).orderBy(councilVerdicts.createdAt)`
- Select columns: id, botId, executionId, verdictType, weightedConfidenceScore, verdictSummary, hasUnresolvedDevilsAdvocate, createdAt
- TypeBox response schema: `Type.Array(Type.Object({...}))` with appropriate types for each field
- weightedConfidenceScore is `numeric(4,3)` in Postgres — cast to `Number()` in the response map

**2. GET /:verdictId** — Get single verdict with full evidence
- Params schema: `Type.Object({ verdictId: Type.String({ format: 'uuid' }) })`
- Query by id: `db.select().from(councilVerdicts).where(eq(councilVerdicts.id, verdictId))`
- Return all evidence columns: id, botId, executionId, verdictType, status, weightedConfidenceScore, verdictSummary, hasUnresolvedDevilsAdvocate, devilsAdvocateOutput, performanceJudgeOutput, soulAnalystOutput, requiresHumanConfirmation, createdAt
- 404 if not found
- Cast weightedConfidenceScore to Number()

**3. POST /:verdictId/confirm** — Confirm a pending verdict
- Params: `{ verdictId: Type.String({ format: 'uuid' }) }`
- Body: `{ userId: Type.String(), timeOnScreenMs: Type.Integer({ minimum: 0 }) }`
- Guard: UPDATE WHERE `id = verdictId AND status = 'pending' AND verdictType IN ('Promote', 'Retire')`
- Set: `{ status: 'confirmed', confirmedAt: new Date(), confirmedBy: body.userId, timeOnScreenMs: body.timeOnScreenMs, updatedAt: new Date() }`
- Use `.returning({ id: councilVerdicts.id })` for idempotency check
- If 0 rows returned: `reply.code(409).send({ error: 'Verdict already resolved or not eligible for confirmation' })`
- On success: `reply.send({ ok: true })`

**4. POST /:verdictId/reject** — Reject a pending verdict
- Same params and body shape as confirm (userId + timeOnScreenMs)
- Guard: UPDATE WHERE `id = verdictId AND status = 'pending' AND verdictType IN ('Promote', 'Retire')`
- Set: `{ status: 'rejected', confirmedBy: body.userId, timeOnScreenMs: body.timeOnScreenMs, updatedAt: new Date() }`
- Use `.returning({ id: councilVerdicts.id })` — 0 rows → 409
- On success: `reply.send({ ok: true })`

**5. GET /calibration** — Per-user confirmation rate
- Query params: `{ userId: Type.String() }` via `querystring` schema
- Query: `db.select({ status: councilVerdicts.status }).from(councilVerdicts).where(and(eq(councilVerdicts.confirmedBy, userId), inArray(councilVerdicts.status, ['confirmed', 'rejected'])))`
- Compute: `total = results.length`, `confirmed = results.filter(r => r.status === 'confirmed').length`, `rate = total > 0 ? confirmed / total : 0`, `warningTriggered = total >= 10 && rate > 0.95`
- Response: `{ total, confirmed, rate, warningTriggered }`

Export as `verdictsRoutes`.

Then modify `services/execution-service/src/app.ts`:

2. Register: `app.register(verdictsRoutes, { prefix: '/verdicts' });` — place after the admin routes registration, with a comment `// Verdict confirmation gate (Phase 12)`.

Key implementation notes:
- Use `inArray` from drizzle-orm for the verdictType filter (import alongside `eq`, `and`)
- The `desc` function from drizzle-orm is NOT needed — `orderBy(councilVerdicts.createdAt)` defaults to ASC which is correct for chronological listing
- All TypeBox schemas should use `Type.String({ format: 'uuid' })` for UUID fields, `Type.Number()` for numeric, `Type.Boolean()` for booleans
- For JSONB columns (devilsAdvocateOutput, performanceJudgeOutput, soulAnalystOutput), use `Type.Unknown()` in the response schema — the frontend will type-narrow these
