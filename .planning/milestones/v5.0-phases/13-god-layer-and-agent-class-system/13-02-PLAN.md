  <implementation>
    Implement `computeClassTransition` as a pure function with no imports (no DB, no Redis).

    **Counter update logic (always runs first, before transition evaluation):**
    - If `isAboveBenchmark`: increment `aboveBenchmarkCount`, reset `consecutiveBelowCount` to 0.
    - If NOT `isAboveBenchmark`: increment `belowBenchmarkCount`, increment `consecutiveBelowCount`.
    - If `hasHumanConfirmation`: increment `humanConfirmationCount`.

    **Transition evaluation (after counter update, using updated counters):**
    - If `currentClass === 'Retired'`: return `{ type: 'none' }`.
    - If `verdictType === 'Retire'` AND `isSoulDriven`: return `{ type: 'retire' }`, set `currentClass: 'Retired'`.
    - If `verdictType === 'Demote'`:
      - Guard: `consecutiveBelowCount >= 2 AND confidence > 0.70 AND isSoulDriven` — if ALL met, demote to Novice (reset all counters). If `isSoulDriven = false`, return `{ type: 'none' }` (CLAS-04 Monitor treatment).
    - If `verdictType === 'Promote'` AND `currentClass === 'Novice'`:
      - Guard: `aboveBenchmarkCount >= 2 AND humanConfirmationCount >= 1 AND confidence > 0.65 AND !hasUnresolvedDA AND benchmarkMature`. If ALL met, promote to Understudy.
    - If `verdictType === 'Promote'` AND `currentClass === 'Understudy'`:
      - Guard: `aboveBenchmarkCount >= 5 AND belowBenchmarkCount <= 1 AND humanConfirmationCount >= 2 AND confidence > 0.80 AND benchmarkMature`. If ALL met, promote to Artisan, record `artisanGraduated: true` in return value.
    - Otherwise: `{ type: 'none' }`.

    **Return type:** `{ newState: ClassState; transition: ClassTransition; artisanGraduated?: boolean }`.

    The `artisanGraduated` flag is a convenience for the God Layer worker to know when to fire the graduation notification.

    Use Vitest for tests (`describe`/`it`/`expect`). The test file imports only from `class-machine.ts`. No mocks needed — pure function testing.
  </implementation>
