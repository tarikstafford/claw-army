    - Wrap the Node.js install in an idempotent guard: `if ! command -v node &>/dev/null; then ... fi`
    - Wrap OpenClaw install in: `if ! command -v openclaw &>/dev/null; then npm install -g openclaw@latest; fi`

    **Validation before onboard (BOT-02):**
    - After the install block, validate:
      a. `command -v openclaw` succeeds — if not, capture error and jump to failure POST
      b. `openclaw --version` runs successfully — capture version string for the success payload
    - Replace `set -euo pipefail` with `set -uo pipefail` (remove `-e`) so the script can handle errors itself using explicit checks rather than crashing silently. Add a `trap` to catch unexpected exits:
      ```bash
      FAILURE_REASON=""
      trap 'if [[ -n "$FAILURE_REASON" ]]; then post_failure; fi' EXIT
      ```
    - Define a `post_failure` shell function near the top that does:
      ```bash
      post_failure() {
        curl -X POST "$EXECUTION_SERVICE_URL/bots/$BOT_ID/ready" \
          -H "Content-Type: application/json" \
          -d "{\"success\": false, \"error\": \"$FAILURE_REASON\"}" \
          --retry 3 --retry-delay 5 --retry-connrefused --max-time 30 || true
      }
      ```

    **Success/failure payload (BOT-02):**
    - On successful OpenClaw Gateway health check, change the final curl POST to include:
      ```json
      {
        "success": true,
        "internalIp": "$INTERNAL_IP",
        "port": $GATEWAY_PORT,
        "gatewayToken": "$GATEWAY_TOKEN",
        "openclawVersion": "$OPENCLAW_VERSION"
      }
      ```
    - At each failure point (Node.js install, OpenClaw install, Secret Manager fetch, onboard command, gateway health check), set `FAILURE_REASON="Human-readable description"` and `exit 1` (the trap calls post_failure).

    **Error handling specifics:**
    - Node.js install failure: `FAILURE_REASON="Failed to install Node.js 22 — apt-get exited with code $?"`
    - OpenClaw install failure: `FAILURE_REASON="Failed to install openclaw npm package — npm exited with code $?"`
    - Secret Manager failure: `FAILURE_REASON="Failed to fetch LLM API key from Secret Manager (secret: $LLM_API_KEY_SECRET)"`
    - Onboard failure: `FAILURE_REASON="openclaw onboard command failed — exit code $?"`
    - Health check timeout: `FAILURE_REASON="OpenClaw Gateway did not become healthy within ${MAX_WAIT}s"`

    **Important:** Keep the existing `soulContentB64` / SOUL.md write logic intact. Keep all existing env vars. The `buildStartupScript` function signature and `LaunchBotVMOptions` interface do NOT change.

    Also update the TypeBox schema for the POST `/:botId/ready` body in `gce-bot-launcher.ts` — wait, that's in `routes/bots.ts` which is Plan 02. Here, only update the shell script template.
