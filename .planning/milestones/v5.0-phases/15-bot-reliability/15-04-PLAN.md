<objective>
Fix the spawn timeout status overwrite bug: when `startSpawnTimeoutChecker` transitions a
timed-out bot to `status='failed'` in the database, the subsequent call to `stopBot()` must
NOT overwrite that status with `'stopped'`.

Purpose: Without this fix, bots that time out during spawn show as "stopped" in the UI
instead of "failed" — the user loses the human-readable failure reason (BOT-04 requirement).

Output: Patched `bot-orchestrator.ts` where spawn-timeout bots retain `status='failed'`
and `errorMessage` through the full cleanup flow.
</objective>

  <action>
**The bug (lines 372-383):** `startSpawnTimeoutChecker` correctly writes `status='failed'`
and `errorMessage` to the DB at line 376, then calls `await stopBot(entry.botId, 'failed')`
at line 383. But `stopBot()` at line 213 unconditionally writes
`{ status: 'stopped', stoppedAt: new Date(), updatedAt: new Date() }`, overwriting the
'failed' status that was just set.

**Fix — add an optional `options` parameter to `stopBot`:**

1. Change the `stopBot` signature from:
   ```ts
   export async function stopBot(
     botId: string,
     reason: 'completed' | 'terminated' | 'failed' | 'idle_timeout',
   ): Promise<void>
   ```
   to:
   ```ts
   export async function stopBot(
     botId: string,
     reason: 'completed' | 'terminated' | 'failed' | 'idle_timeout',
     options?: { skipDbUpdate?: boolean },
   ): Promise<void>
   ```

2. Wrap the existing DB update block (line 211-214) in a conditional:
   ```ts
   if (!options?.skipDbUpdate) {
     await db
       .update(bots)
       .set({ status: 'stopped', stoppedAt: new Date(), updatedAt: new Date() })
       .where(eq(bots.id, botId));
   }
   ```

3. In `startSpawnTimeoutChecker` (line 383), change:
   ```ts
   await stopBot(entry.botId, 'failed');
   ```
   to:
   ```ts
   await stopBot(entry.botId, 'failed', { skipDbUpdate: true });
   ```

This approach is preferred over bypassing `stopBot` entirely because:
- It keeps all cleanup logic (WS disconnect, VM terminate, unregister, publish event) in one place
- Existing callers (idle_timeout, completed, terminated) are unaffected — they don't pass options
- The DB update is already done by the timeout checker; `stopBot` just needs to do the rest

**Do NOT change any other behavior in stopBot or startSpawnTimeoutChecker.**
