  <name>Task 1: Create ring-leader-runs Drizzle schema with two tables and status enum</name>
  <files>packages/db/src/schema/ring-leader-runs.ts</files>
  <action>
Create `packages/db/src/schema/ring-leader-runs.ts` with:

**1. ring_leader_status enum:**
```
pgEnum('ring_leader_status', ['assembling', 'spawning', 'coordinating', 'synthesizing', 'completed', 'failed'])
```
- `assembling`: soul library search + population assembly
- `spawning`: agents being launched
- `coordinating`: real-time execution monitoring
- `synthesizing`: producing run synthesis
- `completed` / `failed`: terminal states

**2. ring_leader_runs table:**
- `id`: uuid PK defaultRandom
- `executionId`: uuid NOT NULL FK to executions.id (onDelete cascade)
- `soulId`: uuid nullable (logical FK to bot_souls.id -- no explicit ref to avoid circular, same pattern as bots.soulId)
- `status`: ring_leader_status NOT NULL default 'assembling'
- `missionBrief`: jsonb NOT NULL -- stores RingLeaderMissionBrief (objective, task_graph, tool_grants, budget_cap, runtime_limit, campaign_type, run_id)
- `populationManifest`: jsonb nullable -- stores PopulationManifest[] (one per task). Null until assembly complete.
- `runState`: jsonb nullable -- stores live run state object (elapsed_time, budget_consumed, task_states, drift_score, anomalies). Updated during coordination.
- `synthesis`: jsonb nullable -- stores RingLeaderSynthesis. Null until synthesis phase.
- `startedAt`: timestamp with timezone, precision 3, nullable
- `completedAt`: timestamp with timezone, precision 3, nullable
- `createdAt`: timestamp with timezone, precision 3, NOT NULL defaultNow
- `updatedAt`: timestamp with timezone, precision 3, NOT NULL defaultNow

Indexes:
- `ring_leader_runs_execution_id_idx` on executionId
- `ring_leader_runs_soul_id_idx` on soulId
- `ring_leader_runs_status_idx` on status

Export: `RingLeaderRun` (inferSelect), `NewRingLeaderRun` (inferInsert)

**3. ring_leader_fitness table:**
- `id`: uuid PK defaultRandom
- `ringLeaderRunId`: uuid NOT NULL FK to ringLeaderRuns.id (onDelete cascade). Add unique constraint -- one fitness record per run.
- `coordinationScore`: jsonb NOT NULL -- 4-dimension breakdown: { collectiveOutcome: number, driftPrevention: number, reallocationEffectiveness: number, budgetManagement: number }
- `soulSelectionScore`: jsonb NOT NULL -- 5-dimension breakdown: { librarySearchQuality: number, differentiationEffectiveness: number, mutationDecisionQuality: number, pioneerHandling: number, selectionRetrospectiveQuality: number }
- `compositeScore`: numeric(5,2) NOT NULL -- weighted: coordination 60% + soul selection 40%
- `soulSelectionLog`: jsonb nullable -- full population manifest snapshot for the run
- `librarySearchQueries`: jsonb nullable -- search queries per task, results, selections
- `selectionRetrospective`: text nullable -- Ring Leader's own assessment
- `pioneerTasksHandled`: integer NOT NULL default 0
- `mutationOperationsApplied`: integer NOT NULL default 0
- `mutationSuccessRate`: numeric(4,3) nullable -- fraction, 0.000 to 1.000
- `createdAt`: timestamp with timezone, precision 3, NOT NULL defaultNow

Indexes:
- `ring_leader_fitness_run_id_idx` on ringLeaderRunId
- `ring_leader_fitness_composite_score_idx` on compositeScore
- unique constraint on ringLeaderRunId

Export: `RingLeaderFitness` (inferSelect), `NewRingLeaderFitness` (inferInsert)

Follow existing patterns exactly: import from 'drizzle-orm/pg-core', use the (t) => [] index syntax (same as bot-souls.ts), reference executions via import.
