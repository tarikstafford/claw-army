**Export function `generatePioneerPopulation(taskDescription: string, taskCategory: string, requiredTools: string[]): Promise<SelectedSoul[]>`:**

(SOUL-06) When library search returns insufficient results for a task, generate 5 archetypal souls across the behavioral spread.

1. **Query existing archetypes** from `bot_souls` where `is_archetype = true` (same as `queryArchetypes()` in soul-generator.ts). These are the 5 seed archetypes.

2. **If archetypes exist:** For each of the 5 archetypes, use `generateText` from `ai` with `openai('gpt-4o-mini')` to create a task-specialized variant. System prompt:
   ```
   You are a soul architect. Given a base archetype SOUL.md and a task description, create a specialized variant that retains the archetype's core behavioral personality but adapts its Decision Priorities and Tool Usage Doctrine to excel at the specific task.

   Task: {taskDescription}
   Required tools: {requiredTools.join(', ')}

   Return the complete SOUL.md document. Preserve all Constitution/Ethical Hard Stops lines VERBATIM.
   ```
   Temperature: 0.3 (moderate diversity while staying on-archetype).

3. **If no archetypes exist:** Use `generateText` to create 5 souls from scratch with distinct behavioral profiles. System prompt should request 5 different behavioral archetypes (analytical, creative, cautious, aggressive, balanced) specialized for the task. Generate them one at a time.

4. **Embed all 5 generated souls** using `embedMany` from `ai` with `openai.embeddingModel('text-embedding-3-small')`.

5. **Persist to bot_souls table:** Insert each soul with:
   - `isArchetype: false`
   - `taskCategory`: the provided taskCategory
   - `generation: 1`
   - `parentSoulId`: the archetype's ID if generated from archetype, null if from scratch
   - `embedding`: the generated embedding
   - `humanReviewFlag: false`

   - Compute `contentHash` using SHA-256 (same pattern as soul-generator.ts).

   - `selectionRationale`: "Pioneer generation: archetype-derived variant for novel task category '{taskCategory}'"
   - `differentiationScore`: compute pairwise and set to minimum distance from nearest sibling
   - `soulContent`: the generated content
   - `embedding`: the embedding array

**Part A: Create `assemble-population.ts`**

This is the top-level orchestrator that coordinates library search, pool selection, pioneer generation, and manifest assembly for ALL tasks in the mission brief's task graph.

**Export function `assemblePopulation(ringLeaderRunId: string, missionBrief: RingLeaderMissionBrief): Promise<PopulationManifest[]>`:**

1. **Classify task categories:** For each `TaskGraphNode` in `missionBrief.taskGraph.tasks`, call `classifyTaskCategory` (create a local helper or extract from soul-generator.ts). Use `generateText` with `openai('gpt-4o-mini')` to classify `node.description` into a standardized category label — same pattern as soul-generator.ts.

2. **For each task node**, execute the following pipeline:

   a. **Search library:** Call `searchSoulLibrary` with:
      - `taskDescription`: node.description
      - `taskCategory`: classified category
      - `requiredTools`: node.requiredTools
      - `taskComplexity`: node.complexity
      - `campaignType`: missionBrief.campaignType
      - `requiredPopulation`: node.recommendedPopulation

   b. **Determine path:** If search returns fewer than `node.minPopulation` results (SOUL-06 trigger), use pioneer path. Otherwise, use library path.

   c. **Library path:** Call `selectFromPool` with the search results and `requiredPopulation: node.recommendedPopulation`. If `varianceIntent` is warranted (same task assigned to diverse souls — SOUL-07), set `varianceIntent` to a descriptive string like "Multi-soul variance: {N} differentiated souls for '{node.description}' to maximize behavioral coverage". Otherwise null.

   d. **Pioneer path:** Call `generatePioneerPopulation(node.description, taskCategory, node.requiredTools)`. Set `pioneerFlag: true` on the manifest.

   e. **Optional mutation pass (SOUL-05):** If the task is 'high' complexity and the selected population has >= 2 souls, apply `applyPreDeploymentMutation` to the lowest-ranked selected soul with operation 'amplification' and rationale "High-complexity task: amplifying lowest-ranked soul to increase specialist focus". Update the soul's `mutationApplied` and `soulContent` fields.

3. **Build PopulationManifest per task:**
   ```typescript
   {
     taskId: node.taskId,
     taskDescription: node.description,
     assignedSouls: selectedSouls.map(s => ({
       soulId: s.soulId,
       agentClass: s.agentClass,
       source: s.source,
       parentSoulId: s.parentSoulId,
       mutationApplied: s.mutationApplied,
       selectionRationale: s.selectionRationale,
       differentiationScore: s.differentiationScore,
     })),
     pioneerFlag: isPioneerPath,
     varianceIntent: varianceIntent,
   }
   ```

4. **Persist to DB:** Update `ring_leader_runs` row with the assembled `PopulationManifest[]` in the `populationManifest` JSONB column. Also update status from 'assembling' to 'spawning' and set `updatedAt`.

5. **Return** the `PopulationManifest[]`.
