**Modify `assemble-population.ts`:**

After the `for` loop that builds all PopulationManifest entries (line ~199, before the DB persist step), insert a budget validation gate:

1. Import `validateBudget` from `./budget-validator`
2. After manifests are fully built, call `validateBudget(manifests, missionBrief.budgetCapCents)`
3. If `result.funded === false`:
   - Log `[assemble-population] BUDGET SHORTFALL: estimated minimum cost ${result.minimumRequiredCents}c exceeds budget cap ${missionBrief.budgetCapCents}c (shortfall: ${result.shortfallCents}c)`
   - Update `ring_leader_runs` row: set `status='failed'`, persist a JSONB `runState` field containing `{ budgetShortfall: true, shortfallCents, minimumRequiredCents, budgetCapCents, warnings }` for downstream consumers (API, UI)
   - Throw a new `BudgetShortfallError` (custom error class, define at top of file) with message: `Budget cap of ${budgetCapCents}c cannot fund minimum populations (${result.minimumRequiredCents}c needed, shortfall: ${result.shortfallCents}c). Scope down tasks or increase budget.`
   - This throw will propagate to the `.catch` in ring-leader-spawner.ts which already handles errors by setting status='failed'
4. If `result.funded === true` but `result.warnings.length > 0`:
   - Log each warning at `console.warn` level
   - Use `result.manifests` (the reduced manifests) instead of the original `manifests` for the DB persist
   - Persist warnings into ring_leader_runs row alongside the manifests (add `budgetWarnings` to the `.set()` call — store as part of `runState` JSONB: `{ budgetWarnings: result.warnings }`)
5. If `result.funded === true` and no warnings: proceed as before with original manifests

The key change to the existing flow: the `manifests` variable used in the final DB persist should be `result.manifests` (which is either the original or the reduced set). The status transition to 'spawning' only happens when funded=true.

**Modify `ring-leader-spawner.ts`:**

The existing `.catch` handler in `ring-leader-spawner.ts` (line ~93) already sets `status='failed'` on any error from `assemblePopulation`. Enhance it:

1. Check if the error is a `BudgetShortfallError` (instanceof check)
2. If budget shortfall: log at `warn` level (not `error`) since this is an expected constraint, not a bug. The ring_leader_runs row already has the details set by assemble-population.ts — no additional DB write needed.
3. For non-budget errors: keep existing behavior (log at `error` level, set status='failed')

Export the `BudgetShortfallError` class from `assemble-population.ts` so `ring-leader-spawner.ts` can import it for the instanceof check.

**DB note on runState:** The `ring_leader_runs` table has a `runState` JSONB column (added in Phase 24). Use it to store budget-related metadata. This is consistent with the pattern of using JSONB for evolving Ring Leader state (per decision from Phase 24-01).

Run `tsc --noEmit` to verify types compile. Commit: `feat(27-02): wire budget validation into population assembly pipeline`
