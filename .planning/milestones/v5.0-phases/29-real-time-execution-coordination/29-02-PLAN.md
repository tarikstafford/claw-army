Create intelligence-router.ts implementing COORD-02:

1. **`createIntelligenceRouter()`** — factory function returning a `CoordinationModule` with `name: 'intelligence-router'`.

2. **`execute(ctx: CoordinationContext)`** implementation:
   - Track which sessions have already been scanned for intelligence (module-level Set per runId to avoid re-processing).
   - For each session in the registry with status `'completed'`:
     - If already processed, skip
     - Query the tasks table for that session's task row (WHERE `claimedByBotId = session.botId AND status = 'completed'`), retrieve the `result` field
     - If result is null or empty, skip
     - **Relevance check**: For each OTHER task in the mission brief's task graph that is NOT the same task and has status 'active' (has active agents):
       - Use a simple keyword overlap heuristic: tokenize the result and the target task description into lowercase word sets, compute Jaccard similarity. If similarity > 0.15 (low threshold — err on the side of routing), consider it relevant.
       - NOTE: A future enhancement could use embedding similarity, but keyword overlap is sufficient for v1 and avoids embedding API calls on every poll.
     - For each relevant target task, create an intelligence routing record:
       - Insert or update a row in the `tasks` table with a special `ringLeaderTaskId` prefixed with `intel:` to distinguish intelligence signals from regular task results. Use `description` = "Intelligence routed from {sourceTaskId}" and `result` = the source task's result text (truncated to 2000 chars).
       - Log via `logCoordinationEvent` with an `IntelligenceRoutingEvent` payload (from `@claw/event-schemas`): fromAgentSessionId, toAgentSessionId (pick first active agent on target task), fromTaskId, toTaskId, signalSummary (first 200 chars of result), routingRationale (Jaccard score + keyword overlap description).
     - Mark session as processed in the Set.

3. **Edge cases**:
   - If a task has no active agents (all completed or failed), skip routing to it
   - If source result is extremely long (>5000 chars), truncate to first 2000 for the intelligence signal
   - Wrap entire execute in try/catch — intelligence routing failure is non-fatal (log WARN, continue)

Import: CoordinationContext, CoordinationModule from coordination-loop.ts; logCoordinationEvent from coordination-events.ts; IntelligenceRoutingEvent from @claw/event-schemas; db, tasks from @claw/db; eq, and from drizzle-orm.
