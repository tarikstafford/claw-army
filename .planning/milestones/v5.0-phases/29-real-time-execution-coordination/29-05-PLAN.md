  <name>Task 1: Budget projection and tiered degradation module</name>
  <files>services/execution-service/src/services/budget-degradation.ts</files>
  <action>
Create budget-degradation.ts implementing COORD-08:

1. **`createBudgetDegradation()`** — factory returning a `CoordinationModule` with `name: 'budget-degradation'`.

2. **Module-level state** per runId:
   - `currentTier: BudgetDegradationTier` — starts at 'normal'
   - `lastTierChangeAt: number` — debounce tier changes (no more than one per 60s)

3. **`execute(ctx: CoordinationContext)`** implementation:

   **A. Project budget consumption to run end:**
   - `elapsedSeconds = ctx.runState.elapsedTimeSeconds`
   - `runtimeLimitSeconds = ctx.missionBrief.runtimeLimitSeconds`
   - `budgetConsumed = ctx.runState.budgetConsumedCents`
   - `budgetCap = ctx.missionBrief.budgetCapCents`
   - If elapsedSeconds < 10 or budgetConsumed === 0, skip projection (insufficient data)
   - `burnRate = budgetConsumed / elapsedSeconds` (cents per second)
   - `projectedTotalCents = burnRate * runtimeLimitSeconds`
   - `consumedPercent = budgetConsumed / budgetCap`
   - `projectedOverrunPercent = projectedTotalCents > budgetCap ? ((projectedTotalCents - budgetCap) / budgetCap) : null`

   **B. Determine degradation tier:**
   Use `consumedPercent` thresholds:
   - `consumedPercent >= 0.95` -> `'hard_stop'` (BUDGET_HARD_STOP_THRESHOLD from shared-types)
   - `consumedPercent >= 0.85` -> `'wrap_up'`
   - `consumedPercent >= 0.70` -> `'consolidate'`
   - `consumedPercent >= 0.55` -> `'deprioritize'`
   - Otherwise -> `'normal'`

   Also consider projected overrun:
   - If `projectedOverrunPercent !== null && projectedOverrunPercent > 0.20` AND current tier is 'normal' -> escalate to 'deprioritize' (early warning based on projection)

   **C. Apply tier transition:**
   - If `newTier !== currentTier` AND more than 60s since lastTierChangeAt:
     - Log via `logCoordinationEvent` with `BudgetDegradationEvent` payload: previousTier, newTier, budgetConsumedPercent, projectedOverrunPercent, description
     - Description format: "Budget degradation: {previousTier} -> {newTier}. Consumed {percent}% of {budgetCap}c. {projected overrun details if applicable}."
     - Add "Budget tier: {newTier}" to `ctx.runState.anomalies` (only for tiers above 'normal')
     - Update currentTier and lastTierChangeAt

   **D. Hard stop enforcement:**
   - If tier is `'hard_stop'`:
     - Add "HARD STOP: Budget at 95%+ cap — coordination loop will terminate" to anomalies
     - The coordination loop's termination check (in 29-01) should detect this anomaly and trigger run termination. For now, just set the anomaly — the loop's existing "all tasks complete" check plus this anomaly flag is sufficient for v1.

Import: CoordinationContext, CoordinationModule from coordination-loop.ts; logCoordinationEvent from coordination-events.ts; BudgetDegradationEvent, BudgetDegradationTier from @claw/event-schemas; BUDGET_HARD_STOP_THRESHOLD from @claw/shared-types.
