  <action>
Create `soul-selection-scorer.ts` that exports `scoreSoulSelectionQuality()`.

**Params interface (SoulSelectionScoringParams):**
- synthesis: RingLeaderSynthesis (contains soulSelectionRetrospective, taskSummary, pioneerEvents)
- manifests: PopulationManifest[] (contains soul assignments, differentiation scores, sources, mutations)
- missionBrief: RingLeaderMissionBrief (for task graph context)

**Return type:** SoulSelectionScore (from @claw/shared-types)

**Implementation approach — single LLM call (same pattern as soul-analyst.ts):**

1. Define a Zod output schema for 5 dimension scores (each z.number().min(0).max(1)):
   - librarySearchQuality
   - differentiationEffectiveness
   - mutationDecisionQuality
   - pioneerHandling
   - selectionRetrospectiveQuality

2. Build a prompt that provides the LLM with:
   - Task graph summary: each task with complexity, required tools, recommended population
   - Per-task manifest data: for each manifest, list assigned souls with agentClass, source, parentSoulId, mutationApplied, selectionRationale, differentiationScore, pioneerFlag
   - Population sizing: number of souls per task vs recommended population
   - Mutation summary: count of mutations applied, types of mutations, which tasks had mutated souls
   - Pioneer summary: which tasks were flagged as pioneer, how many pioneer events (from synthesis.pioneerEvents)
   - Soul class distribution: count of Artisan/Understudy/Novice across all manifests
   - Soul source distribution: count of library/generated/mutated across all manifests
   - Ring Leader's own selection retrospective (synthesis.soulSelectionRetrospective)
   - Task outcomes: from synthesis.taskSummary — which tasks completed, which failed, top performing soul IDs

3. System prompt: "You are the Soul Analyst evaluating a Ring Leader's soul selection quality. Score five dimensions on a 0 to 1 scale. Assess whether the Ring Leader made effective selection decisions that contributed to run success."

4. Scoring rubric in prompt:
   - librarySearchQuality: Did the Ring Leader find relevant souls from the library? High differentiation scores across library-sourced souls indicate good search. Low scores if most souls are generated (pioneer) when library had options. 1.0 = diverse, class-appropriate library selections for all tasks.
   - differentiationEffectiveness: Are assigned souls within each task sufficiently different? Average differentiationScore across manifests. 1.0 = all souls have differentiationScore > 0.3. Below 0.5 = many near-duplicate selections.
   - mutationDecisionQuality: Were mutations applied judiciously? Mutations should target high-complexity tasks. Excessive mutations (>50% of souls) or no mutations on complex tasks both reduce score. 1.0 = targeted mutations on the right tasks.
   - pioneerHandling: For pioneer tasks, were archetypal souls well-distributed across behavioral spread? Pioneer flag present only on genuinely novel tasks. 1.0 = pioneer decisions appropriate, 0.5 if no pioneer tasks existed (neutral).
   - selectionRetrospectiveQuality: Did the Ring Leader's self-assessment (soulSelectionRetrospective) accurately identify which selections worked and which did not? Compare retrospective claims against actual task outcomes. 1.0 = accurate self-assessment referencing specific outcomes.

5. Use `generateText` + `Output.object` with the Zod schema (temperature 0.2). Use `resolveModel()` with env var `SOUL_SELECTION_SCORER_MODEL` defaulting to `claude-sonnet-4-6`.

6. On LLM failure: return a fallback SoulSelectionScore with deterministic estimates:
   - librarySearchQuality: (count of source='library' souls / total souls), clamped 0-1
   - differentiationEffectiveness: average differentiationScore across all manifests, clamped 0-1
   - mutationDecisionQuality: 0.5 (neutral)
   - pioneerHandling: 0.5 if pioneer tasks exist, 0.5 if none (always neutral on fallback)
   - selectionRetrospectiveQuality: 0.5 (neutral — cannot evaluate qualitative content without LLM)

7. Log: `[soul-selection-scorer] Scored runId={runId} search={n} diff={n} mutation={n} pioneer={n} retrospective={n}`

Import pattern: only import types from @claw/shared-types and resolveModel from lib/resolve-model.ts. No circular dependency risk.
