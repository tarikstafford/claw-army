
**Four check functions (module-level, outside adminRoutes):**

1. `checkGCE()` — Call `gceClient.list({ project: GCP_PROJECT_ID, zone: GCP_ZONE })`. The `list()` method returns an async iterable (not an array). Consume just the first page: use `gceClient.list({ project: GCP_PROJECT_ID, zone: GCP_ZONE, maxResults: 1 })` to minimize overhead. Return `{ ok: true, instanceCount: N }`. On error (expected in local dev without GCP credentials), return `{ ok: false, error: String(err) }`.

2. `checkCloudSQL()` — `await db.execute(sql\`SELECT 1\`)`. Return `{ ok: true, latencyMs }` measuring `Date.now()` before/after. On error, return `{ ok: false, error: String(err) }`.

3. `checkRedis()` — Create a fresh `IORedis` connection with `{ connectTimeout: 2000, lazyConnect: true }`, call `.connect()` then `.ping()`, disconnect in finally block. Return `{ ok: true, latencyMs }` or `{ ok: false, error }`. Use a fresh connection (not a singleton) to test actual connectivity — disconnect after use.

4. `checkBullMQ()` — Call `taskQueue.getJobCounts('waiting', 'active', 'failed')`. Return `{ ok: true, counts }` or `{ ok: false, error }`.

**Handler inside adminRoutes:**

```typescript
app.get('/health', async (_request, reply) => {
  const [gce, cloudSQL, redis, bullMQ] = await Promise.allSettled([
    checkGCE(),
    checkCloudSQL(),
    checkRedis(),
    checkBullMQ(),
  ]);

  const extract = (r: PromiseSettledResult<any>) =>
    r.status === 'fulfilled' ? r.value : { ok: false, error: String(r.reason) };

  const subsystems = {
    gce: extract(gce),
    cloudSQL: extract(cloudSQL),
    redis: extract(redis),
    bullMQ: extract(bullMQ),
  };

  const allHealthy = Object.values(subsystems).every((s: any) => s.ok);
  return reply.code(allHealthy ? 200 : 503).send({
    status: allHealthy ? 'healthy' : 'degraded',
    subsystems,
  });
});
```

Use `Promise.allSettled` (NOT `Promise.all`) — health checks must all complete even if one throws (Anti-pattern from research).

Do NOT add TypeBox response schema to the GET /health handler — the dynamic shape (optional fields like latencyMs, counts, error, instanceCount per subsystem) makes strict TypeBox schema burdensome. Just return the JSON directly. Fastify will serialize it fine.
