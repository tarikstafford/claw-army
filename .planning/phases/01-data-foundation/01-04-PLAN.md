  <files>

  <action>
    Create the Docker network isolation configuration that mirrors the production architecture.

    **Architecture:**
    - `bot-internal` network: `internal: true`, bridge driver — bots live here, NO internet access
    - `external` network: regular bridge driver — internet access
    - Bot container: attached ONLY to `bot-internal`
    - Tool Gateway stub: attached to BOTH `bot-internal` and `external` — reachable from bots AND can reach internet

    **1. Create `infra/docker/bot-isolation/Dockerfile.bot-test`:**
    ```dockerfile
    FROM alpine:3.20
    # Install network diagnostic tools for egress testing
    RUN apk add --no-cache curl wget bind-tools netcat-openbsd
    # Keep container running for exec-based tests
    CMD ["sleep", "infinity"]
    ```

    **2. Create `infra/docker/bot-isolation/Dockerfile.gateway-stub`:**
    ```dockerfile
    FROM alpine:3.20
    RUN apk add --no-cache netcat-openbsd curl
    # Simple HTTP listener on port 8080 that echoes back request info
    # This simulates the Tool Gateway endpoint
    EXPOSE 8080
    CMD ["sh", "-c", "while true; do echo -e 'HTTP/1.1 200 OK\r\nContent-Type: text/plain\r\n\r\nGateway OK' | nc -l -p 8080; done"]
    ```

    **3. Create `infra/docker/bot-isolation/docker-compose.yml`:**
    ```yaml
    services:
      bot-test:
        build:
          context: .
          dockerfile: Dockerfile.bot-test
        networks:
          - bot-internal
        # No ports exposed — completely isolated
        # CPU and memory limits simulate production bot constraints
        deploy:
          resources:
            limits:
              cpus: '0.5'
              memory: 256M

      tool-gateway-stub:
        build:
          context: .
          dockerfile: Dockerfile.gateway-stub
        networks:
          - bot-internal
          - external
        ports:
          - "8080:8080"

    networks:
      bot-internal:
        internal: true
        driver: bridge
      external:
        driver: bridge
    ```

    Key behaviors of `internal: true` (from RESEARCH.md Pattern 4):
    - Containers on the internal network can communicate with each other
    - No default route is configured — no path to internet
    - Firewall rules drop traffic to/from other networks
    - Docker embedded DNS still resolves internal container names

    **IMPORTANT:** Do NOT use `--network none` — that blocks ALL networking including container-to-container. The bot needs to reach the Tool Gateway via container networking.
  </action>
  <verify>
    - `docker compose -f infra/docker/bot-isolation/docker-compose.yml build` succeeds
    - `docker compose -f infra/docker/bot-isolation/docker-compose.yml up -d` starts both containers
    - `docker compose -f infra/docker/bot-isolation/docker-compose.yml ps` shows both running
    - `docker compose -f infra/docker/bot-isolation/docker-compose.yml down` cleans up
  </verify>
  <done>
    Docker Compose file creates two networks (internal + external) and two services (bot-test on internal only, tool-gateway-stub on both). Both containers build and start successfully.

  <name>Task 2: Create and run automated egress test script</name>
  <files>

  <action>
    Create a comprehensive egress test script that validates all isolation constraints.

    **Create `infra/docker/bot-isolation/egress-test.sh`:**

    ```bash
    #!/usr/bin/env bash
    set -euo pipefail

    # Egress test for bot network isolation
    # Tests that bot containers cannot reach external hosts
    # but CAN reach the Tool Gateway stub

    COMPOSE_FILE="$(dirname "$0")/docker-compose.yml"
    PASS=0
    FAIL=0
    TOTAL=0

    # Colors
    RED='\033[0;31m'
    GREEN='\033[0;32m'
    YELLOW='\033[0;33m'
    NC='\033[0m'

    pass() { ((PASS++)); ((TOTAL++)); echo -e "${GREEN}[PASS]${NC} $1"; }
    fail() { ((FAIL++)); ((TOTAL++)); echo -e "${RED}[FAIL]${NC} $1"; }
    info() { echo -e "${YELLOW}[INFO]${NC} $1"; }
    ```

    The script must test ALL of the following from inside the bot-test container:

    **Test 1 — TCP to external IP is blocked:**
    ```bash
    # Attempt TCP connection to a known external IP (Google DNS 8.8.8.8:443)
    # Expected: connection refused or timeout (exit code != 0)
    docker compose -f "$COMPOSE_FILE" exec -T bot-test \
      sh -c "nc -z -w 3 8.8.8.8 443" 2>/dev/null && fail "..." || pass "..."
    ```

    **Test 2 — TCP to external hostname is blocked:**
    ```bash
    # Attempt HTTP request to google.com
    # Expected: connection fails
    docker compose -f "$COMPOSE_FILE" exec -T bot-test \
      sh -c "wget -T 3 -q -O /dev/null https://google.com" 2>/dev/null && fail "..." || pass "..."
    ```

    **Test 3 — DNS resolution of external hostname (informational):**
    ```bash
    # Test DNS resolution of external hostname
    # Note from RESEARCH.md Pitfall 3: Docker embedded DNS MAY still resolve external names
    # even on internal networks. The key is that the resolved IP is not ROUTABLE.
    # This test documents the behavior — resolution may succeed but connections won't.
    docker compose -f "$COMPOSE_FILE" exec -T bot-test \
      sh -c "nslookup google.com 2>/dev/null" && info "DNS resolves (expected — IP not routable)" || pass "DNS resolution blocked"
    ```

    **Test 4 — Bot CAN reach Tool Gateway stub (container-to-container):**
    ```bash
    # Attempt HTTP request to tool-gateway-stub on internal network
    # Expected: 200 OK with "Gateway OK" body
    docker compose -f "$COMPOSE_FILE" exec -T bot-test \
      sh -c "wget -T 3 -q -O - http://tool-gateway-stub:8080" 2>/dev/null | grep -q "Gateway OK" && pass "..." || fail "..."
    ```

    **Test 5 — Gateway CAN reach external hosts (dual-network verification):**
    ```bash
    # Verify the gateway can reach the internet (it's on the external network)
    # Expected: success (exit code 0)
    docker compose -f "$COMPOSE_FILE" exec -T tool-gateway-stub \
      sh -c "wget -T 5 -q -O /dev/null https://google.com" 2>/dev/null && pass "..." || fail "..."
    ```

    **Test 6 — Bot cannot reach host network services:**
    ```bash
    # Attempt to reach the Docker host gateway (typically 172.17.0.1)
    # Expected: blocked
    docker compose -f "$COMPOSE_FILE" exec -T bot-test \
      sh -c "nc -z -w 3 host.docker.internal 80" 2>/dev/null && fail "..." || pass "..."
    ```

    **Script flow:**
    1. Print header with test explanation
    2. Build and start containers: `docker compose -f "$COMPOSE_FILE" up -d --build`
    3. Wait for containers to be healthy (sleep 3)
    4. Run all 6 tests
    5. Print summary table (N passed, M failed, K total)
    6. Tear down: `docker compose -f "$COMPOSE_FILE" down`
    7. Exit with code 0 if all required tests pass (tests 1,2,4 are required; test 3 is informational; tests 5,6 are required)

    Make the script executable: `chmod +x infra/docker/bot-isolation/egress-test.sh`

    Run the test: `./infra/docker/bot-isolation/egress-test.sh`

    Expected output:
    ```
    === Bot Network Isolation Egress Test ===

    [PASS] TCP to external IP (8.8.8.8:443) blocked
    [PASS] HTTP to external hostname (google.com) blocked
    [INFO] DNS resolves external names (expected — resolved IP not routable)
    [PASS] Bot can reach Tool Gateway stub (HTTP 200)
    [PASS] Gateway can reach external hosts (google.com)
    [PASS] Bot cannot reach host network

    === Results: 5/5 passed, 0 failed ===
    ```
