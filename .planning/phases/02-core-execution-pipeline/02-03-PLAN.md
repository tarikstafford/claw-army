**src/orchestrator/bot-registry.ts:**

In-memory Map tracking active bot containers. This is the single source of truth for which bots are currently running in this process.

```typescript
import type { Container } from 'dockerode';

export interface BotEntry {
  botId: string;
  executionId: string;
  containerId: string;
  container: Container;
  startedAt: number;         // Date.now()
  lastTaskClaimedAt: number; // Date.now() — updated when bot claims a task
}
```

Exports:
1. `botRegistry` — `new Map<string, BotEntry>()` (keyed by botId)
2. `registerBot(entry: BotEntry)` — adds entry to the map
3. `unregisterBot(botId: string)` — deletes entry from the map
4. `getBot(botId: string)` — returns `BotEntry | undefined`
5. `getBotsForExecution(executionId: string)` — filters and returns all entries for a given execution
6. `getActiveBotCount(executionId: string)` — returns count of bots for an execution (for max_bots enforcement)

**src/orchestrator/jwt.ts:**

Short-lived JWT for bot authentication using jose.

```typescript
import * as jose from 'jose';
```

- `JWT_SECRET` — derived from `process.env.BOT_JWT_SECRET`. If not set, use a default dev secret (e.g., `'claw-dev-secret-do-not-use-in-prod'`) with a console.warn. Encode with `new TextEncoder().encode(secret)`.

Exports:
1. `mintBotJwt(botId: string, executionId: string): Promise<string>` — Signs a JWT with `{ botId, executionId }` payload, `sub: botId`, `alg: 'HS256'`, `exp: '15m'` (15-minute expiry). Returns the signed token string.
2. `verifyBotJwt(token: string): Promise<{ botId: string; executionId: string }>` — Verifies the token, extracts botId and executionId from payload. Throws on invalid/expired token.

**src/events/publisher.ts:**

Pub/Sub event publisher with Zod validation before publishing. Uses `PUBSUB_EMULATOR_HOST` for local dev (from docker-compose.dev.yml).

```typescript
import { PubSub } from '@google-cloud/pubsub';
import {
  botStartedEventSchema,
  botStoppedEventSchema,
  type BotStartedEvent,
  type BotStoppedEvent,
} from '@claw/event-schemas';
```

- Create `pubsub` instance: `new PubSub({ projectId: process.env.GCP_PROJECT_ID ?? 'claw-local' })`. When `PUBSUB_EMULATOR_HOST` is set, the client automatically routes to the local emulator.

- Topic name constant: `BOT_EVENTS_TOPIC = 'bot-events'`, `EXECUTION_EVENTS_TOPIC = 'execution-events'`

Exports:
1. `publishBotStarted(event: BotStartedEvent)` — Validates with `botStartedEventSchema.parse(event)`, publishes JSON to `bot-events` topic.
2. `publishBotStopped(event: BotStoppedEvent)` — Validates with `botStoppedEventSchema.parse(event)`, publishes JSON to `bot-events` topic.
3. `publishExecutionStatusChanged(event)` — Validates with `executionStatusChangedEventSchema.parse(event)`, publishes to `execution-events` topic.

Each publish function:
1. Validates the event payload with the corresponding Zod schema (parse throws on invalid)
2. Converts to JSON Buffer: `Buffer.from(JSON.stringify(event))`
3. Publishes via `pubsub.topic(topicName).publishMessage({ data })`
4. Wraps in try/catch — log errors but don't throw (event emission should not crash the orchestrator). Use `console.error` for now; the Fastify logger is not available in this module.

Also add `import { executionStatusChangedEventSchema, type ExecutionStatusChangedEvent } from '@claw/event-schemas'` for execution events.

**src/orchestrator/bot-orchestrator.ts:**

The main orchestrator module that spawns, manages, and terminates bot containers.

```typescript
import Docker from 'dockerode';
import { randomUUID } from 'node:crypto';
import { db, bots } from '@claw/db';
import { eq } from 'drizzle-orm';
import { mintBotJwt } from './jwt';
import { botRegistry, registerBot, unregisterBot, getActiveBotCount, getBotsForExecution } from './bot-registry';
import { publishBotStarted, publishBotStopped } from '../events/publisher';
```

**Docker client:**
```typescript
const docker = new Docker({
  socketPath: process.env.DOCKER_SOCKET_PATH ?? '/var/run/docker.sock',
});
```

Per RESEARCH.md Pitfall 3: macOS Docker Desktop 4.18+ may put the socket at `$HOME/.docker/run/docker.sock`. The env variable override handles this.

**Constants:**
- `IDLE_TIMEOUT_MS = 5 * 60 * 1000` (5 minutes — per ORCH-05)
- `IDLE_CHECK_INTERVAL_MS = 30_000` (check every 30 seconds)
- `BOT_IMAGE = process.env.BOT_IMAGE ?? 'claw-stub-bot:latest'`
- `BOT_NETWORK = process.env.BOT_NETWORK ?? 'bot-internal'`
- `BOT_MEMORY_LIMIT = 512 * 1024 * 1024` (512 MB)
- `BOT_CPU_LIMIT = 1_000_000_000` (1 CPU in nanocpus)

**Exports:**

1. `spawnBot(executionId: string): Promise<{ botId: string; containerId: string }>`:
   - Generate `botId = randomUUID()`
   - Mint JWT: `const jwt = await mintBotJwt(botId, executionId)`
   - Insert bot row in Postgres: `db.insert(bots).values({ id: botId, executionId, status: 'spawning', imageTag: BOT_IMAGE }).returning()`
   - Create container via dockerode:
     ```
     docker.createContainer({
       Image: BOT_IMAGE,
       name: `claw-bot-${botId}`,
       Env: [
         `BOT_ID=${botId}`,
         `EXECUTION_ID=${executionId}`,
         `BOT_JWT=${jwt}`,
         `REDIS_URL=${process.env.REDIS_URL ?? 'redis://localhost:6379'}`,
         `DATABASE_URL=${process.env.DATABASE_URL}`,
       ],
       HostConfig: {
         Memory: BOT_MEMORY_LIMIT,
         NanoCpus: BOT_CPU_LIMIT,
         NetworkMode: BOT_NETWORK,
         AutoRemove: true,
       },
     })
     ```
   - Start container: `container.start()`
   - Get containerId: `container.inspect()` -> `info.Id`
   - Update bot row: set `status: 'idle'`, `containerId`, `startedAt: new Date()`
   - Register in bot registry: `registerBot({ botId, executionId, containerId, container, startedAt: Date.now(), lastTaskClaimedAt: Date.now() })`
   - Publish event: `publishBotStarted({ type: 'bot_started', botId, executionId, timestamp: new Date().toISOString(), metadata: { imageTag: BOT_IMAGE, containerId } })`
   - Return `{ botId, containerId }`

2. `stopBot(botId: string, reason: 'completed' | 'terminated' | 'failed' | 'idle_timeout'): Promise<void>`:
   - Get entry from registry
   - Call `entry.container.stop({ t: 5 })` (5-second SIGTERM grace period). Wrap in try/catch — container may already be stopped.
   - Update bot row in Postgres: `status: 'stopped'`, `stoppedAt: new Date()`
   - Unregister from bot registry
   - Publish event: `publishBotStopped({ type: 'bot_stopped', botId, executionId: entry.executionId, timestamp: new Date().toISOString(), reason })`

3. `spawnBotsForExecution(executionId: string, maxBots: number): Promise<void>`:
   - Get current bot count: `getActiveBotCount(executionId)`
   - Calculate how many to spawn: `Math.max(0, maxBots - currentCount)`
   - Spawn bots in parallel: `Promise.allSettled(Array.from({ length: toSpawn }, () => spawnBot(executionId)))`
   - Log any failed spawns

4. `startIdleChecker(): NodeJS.Timeout`:
   - Returns `setInterval(async () => { ... }, IDLE_CHECK_INTERVAL_MS)`
   - Inside: iterate `botRegistry.entries()`, check `Date.now() - entry.lastTaskClaimedAt > IDLE_TIMEOUT_MS`
   - For each idle bot: call `stopBot(entry.botId, 'idle_timeout')`
   - Wrap each stop in try/catch to prevent one failure from blocking others

5. `stopIdleChecker(timer: NodeJS.Timeout): void`:
   - Calls `clearInterval(timer)`

**Error handling:** All dockerode calls should be wrapped in try/catch. If container creation or start fails, update bot row to 'failed' status and don't register in the bot registry. Log errors with enough context (botId, executionId, error message).

**Note about AutoRemove:** With `AutoRemove: true`, the container is automatically removed when it exits. No explicit `container.remove()` is needed. However, `container.stop()` may throw `409 Conflict` if the container already exited — catch and ignore this.
