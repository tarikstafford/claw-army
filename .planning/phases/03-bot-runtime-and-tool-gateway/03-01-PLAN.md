<objective>
Create the Tool Gateway service scaffold with the POST /tool.invoke endpoint, JWT authentication, tool allowlist enforcement, Zod v4 argument validation, per-bot Redis rate limiting, and audit logging to a new tool_invocations database table.

Purpose: The Tool Gateway is the sole external interface for bot containers. This plan builds the full enforcement pipeline (auth, allowlist, schema validation, rate limiting, audit logging) so that Plan 03-02 only needs to plug in the tool implementations.

**Step 2: Create middleware/auth.ts — JWT verify-only mode.**

Use `@fastify/jwt` with `fastify-plugin`. Read `BOT_JWT_SECRET` from env. If missing, throw and exit (NOT a console.warn fallback — this is the security boundary). Register `@fastify/jwt` with the secret. Decorate `fastify.authenticate` as an async preHandler that calls `request.jwtVerify()`. On failure, return 401 with `{ success: false, error: 'Unauthorized' }`.

Add TypeScript type augmentation for `FastifyInstance.authenticate` and `FastifyRequest.user` (with `botId: string; executionId: string` in the JWT payload).

**Step 3: Create middleware/rate-limit.ts — Per-bot rate limiting.**

Create a separate ioredis connection (NOT shared with BullMQ — use default settings, no maxRetriesPerRequest:null). Read REDIS_URL from env.

Create TWO `RateLimiterRedis` instances:
- `callsLimiter`: 60 points per 60 seconds, keyPrefix `rl:calls`
- `tokensLimiter`: 100,000 points per 60 seconds, keyPrefix `rl:tokens`

Export `checkCallRateLimit(botId: string)` — wraps `callsLimiter.consume(botId, 1)` in try/catch. On `RateLimiterRes` throw, return `{ allowed: false, retryAfter }`. On success, return `{ allowed: true }`.

Export `consumeTokens(botId: string, tokens: number)` — wraps `tokensLimiter.consume(botId, tokens)`. On `RateLimiterRes`, throw a structured error with `code: 'TOKEN_RATE_LIMIT'` and `retryAfter`. This is called AFTER llm_call returns (consume-after-return pattern per locked user decision #2).

Export `checkTokenRateLimit(botId: string)` — wraps `tokensLimiter.consume(botId, 0)` (zero-cost check) to verify if bot is already over token limit BEFORE dispatching. If the bot has previously exceeded the limit and the window hasn't reset, this will throw RateLimiterRes.

**CRITICAL:** `rate-limiter-flexible` `.consume()` THROWS `RateLimiterRes` on limit exceeded (it does NOT return a result object). Must use `if (err instanceof RateLimiterRes)` in catch blocks.

**Step 4: Create services/allowlist.ts.**

Export `checkAllowlist(executionId: string, toolName: string)` — queries `executions` table for the `allowedTools` column where `id = executionId`. Returns `{ allowed: true }` if `toolName` is in the array, or `{ allowed: false, allowedTools: [...] }` if not. Use Drizzle `db.select()` with `eq()` from `@claw/db`.

**Step 5: Create services/audit-log.ts.**

Export `writeAuditLog(entry: { executionId, botId, toolName, invocationId, rejected, rejectionReason?, durationMs?, promptTokens?, completionTokens?, totalTokens?, requestSummary?, responseSummary? })` — inserts a row into `toolInvocations` table using Drizzle `db.insert()`. For `requestSummary` and `responseSummary`, truncate large values (e.g., stringify and slice to 2000 chars) before inserting as jsonb.

Wrap the insert in try/catch — audit log failures must NOT crash the request handler. Log errors to console.error.

**Step 6: Create routes/tool-invoke.ts — POST /tool.invoke.**

Register as a Fastify plugin (`FastifyPluginAsyncTypebox`). The route pipeline is:

1. **JWT auth** — `preHandler: [fastify.authenticate]`
2. **Loose body schema** — TypeBox `Type.Object({ toolName: Type.String(), botId: Type.String(), executionId: Type.String(), invocationId: Type.String(), timestamp: Type.String(), args: Type.Unknown() })`
3. **Allowlist check** — call `checkAllowlist(executionId, toolName)`. If not allowed, write audit log (rejected: true, reason: 'not_in_allowlist'), return 403.
4. **Call rate limit** — call `checkCallRateLimit(botId)`. If not allowed, write audit log (rejected: true, reason: 'rate_limit_exceeded'), return 429 with retryAfter.
5. **Token rate limit pre-check** — call `checkTokenRateLimit(botId)`. If already over token limit, write audit log (rejected: true, reason: 'token_rate_limit_exceeded'), return 429.
6. **Zod validation** — dispatch on `toolName` string to select the correct schema from `@claw/tool-contracts` (`llmCallRequestSchema`, `fetchUrlRequestSchema`, `writeFileRequestSchema`). Call `.safeParse(body)`. If failed, write audit log (rejected: true, reason: 'schema_validation_failed'), return 422 with Zod issues. If toolName is unknown, return 400.
7. **Tool dispatch** — for now, return 501 with `{ success: false, error: 'Tool not implemented' }` for all three tools. Plan 03-02 plugs in real implementations.
8. **Audit log** — write success audit log entry with durationMs.
9. **Return** — `{ success: true, result, durationMs }`

**Step 7: Create app.ts — Fastify app factory.**

Export `buildApp()` that creates a Fastify instance with TypeBoxTypeProvider, registers the auth plugin, registers the tool-invoke routes, and adds a `GET /health` endpoint (no auth). Follow the execution-service `buildApp` pattern.

**Step 8: Create main.ts — Entry point.**

Import dotenv/config. Call `buildApp()`. Listen on `process.env.PORT ?? 3002` (Tool Gateway uses port 3002). Log startup message.
