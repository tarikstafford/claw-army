**Create services/tool-gateway/src/tools/llm-call.ts:**

Export `executeLlmCall(req: LlmCallRequest)` that:
1. Resolves the LLM provider model from `req.args.model` using a `resolveModel()` function:
   - `gpt-*` or `o1*` or `o3*` prefix -> `openai(modelId)`
   - `claude-*` prefix -> `anthropic(modelId)`
   - `gemini-*` prefix -> `google(modelId)`
   - Default: `openai(modelId)` (will error at API level if unrecognized)
2. Calls `generateText({ model, messages: req.args.messages, maxOutputTokens: req.args.maxTokens, temperature: req.args.temperature })` from the `ai` package.
3. Returns `{ content: result.text, model: result.response.modelId, promptTokens: result.usage.inputTokens, completionTokens: result.usage.outputTokens, totalTokens: result.usage.totalTokens }`.

**CRITICAL AI SDK 6 field names:** `result.usage.inputTokens` and `result.usage.outputTokens` (NOT promptTokens/completionTokens). Verify against the installed TypeScript types. The response schema in `@claw/tool-contracts` uses `promptTokens`/`completionTokens` as the field names in the contract — the mapping from SDK fields to contract fields happens here.

Import types from `@claw/tool-contracts`: `LlmCallRequest`.

**Create services/tool-gateway/src/tools/fetch-url.ts:**

Export `executeFetchUrl(req: FetchUrlRequest)` that:
1. Parses `new URL(req.args.url)` — throws on malformed URL (caught by route handler).
2. Checks domain allowlist: read `FETCH_URL_DOMAIN_ALLOWLIST` from env (comma-separated). If the list is non-empty and `url.hostname` is NOT in the list, throw an error: `Domain ${url.hostname} not in fetch_url allowlist`.
3. Performs `fetch(req.args.url, { method: req.args.method, headers: req.args.headers, body: req.args.body, signal: AbortSignal.timeout(30_000) })`.
4. Reads response as ArrayBuffer. Truncates at 1MB (`1_000_000` bytes). Converts to utf-8 string.
5. Collects response headers into a `Record<string, string>`.
6. Returns `{ statusCode: response.status, headers, body, truncated: rawBytes.byteLength > MAX_BODY_BYTES }`.

**IMPORTANT:** Use `new URL().hostname` (not `.host` which includes port, not string matching). This correctly handles URL credential injection attacks per research pitfall #5.

**Create services/tool-gateway/src/tools/write-file.ts:**

Export `executeWriteFile(req: WriteFileRequest)` that:
1. Generates `artifactId = randomUUID()`.
2. Sanitizes the path: use `path.basename(req.args.path)` to strip all directory separators. This prevents path traversal attacks (`../../etc/passwd`). Do NOT use the full `req.args.path` in any `join()`.
3. Creates directory `ARTIFACT_ROOT/artifactId/` using `mkdir({ recursive: true })`. `ARTIFACT_ROOT` from env, default `/tmp/claw-artifacts`.
4. Writes content: if `req.args.encoding === 'base64'`, decode from base64 first. Otherwise write as utf-8 string.
5. Returns `{ artifactId, path: targetPath, sizeBytes: Buffer.byteLength(content) }`.

Import types from `@claw/tool-contracts`: `WriteFileRequest`.

3. In the dispatch section (step 7 from Plan 03-01), replace the 501 returns with:

```typescript
let result: unknown;
let tokenCount: number | undefined;

try {
  if (toolName === 'llm_call') {
    const llmResult = await executeLlmCall(parsed.data as LlmCallRequest);
    result = llmResult;
    tokenCount = llmResult.totalTokens;
  } else if (toolName === 'fetch_url') {
    result = await executeFetchUrl(parsed.data as FetchUrlRequest);
  } else if (toolName === 'write_file') {
    result = await executeWriteFile(parsed.data as WriteFileRequest);
  }
} catch (err) {
  // Tool execution failed — log and return 500
  const durationMs = Date.now() - startMs;
  await writeAuditLog({ ...commonFields, rejected: false, durationMs, responseSummary: { error: (err as Error).message } });
  return reply.code(500).send({ success: false, error: (err as Error).message });
}
```

4. **After successful dispatch**, if `toolName === 'llm_call'` and `tokenCount` is defined, call `consumeTokens(botId, tokenCount)`. Wrap in try/catch — if the consume throws a TOKEN_RATE_LIMIT error, the CURRENT call still succeeds (per locked user decision #2: consume-after-return). Log the token consumption to audit log but do NOT fail the response.

5. Write the success audit log entry including `durationMs`, `promptTokens`, `completionTokens`, `totalTokens` (extracted from llm_call result if applicable), and `responseSummary` (truncated result).

6. Return `{ success: true, result, durationMs }`.

**Token rate limit flow recap (per locked user decision #2):**
- BEFORE dispatch: `checkTokenRateLimit(botId)` rejects if bot is ALREADY over limit from a previous call.
- AFTER dispatch (llm_call only): `consumeTokens(botId, tokenCount)` records the tokens used. If this pushes over the limit, the CURRENT call still returns successfully. The NEXT call will be blocked by the pre-check.
