**Step 2: Create src/tools/gateway-proxy.ts — thin HTTP proxy.**

Export `callGateway(toolName: string, args: unknown)` that:
1. Reads `TOOL_GATEWAY_URL` from env (default: `http://tool-gateway:3002`).
2. Reads `BOT_JWT`, `BOT_ID`, `EXECUTION_ID` from env.
3. POSTs to `${TOOL_GATEWAY_URL}/tool.invoke` with:
   - Headers: `Content-Type: application/json`, `Authorization: Bearer ${BOT_JWT}`
   - Body: `{ toolName, botId: BOT_ID, executionId: EXECUTION_ID, invocationId: randomUUID(), timestamp: new Date().toISOString(), args }`
4. Parses JSON response. If `!data.success`, throws `new Error(data.error ?? 'Tool invocation failed')`.
5. Returns `data.result`.

This function is intentionally thin. All enforcement (auth, allowlist, rate limiting, schema validation) happens in the Tool Gateway. The bot is an untrusted caller.

**Step 3: Create src/reasoning-loop.ts — AI SDK generateText loop.**

Export `runReasoningLoop(taskDescription: string)` that:
1. Reads `LLM_MODEL` from env (default: `gpt-4o-mini`). Resolves the model using the same provider routing logic as the gateway: `gpt-*` -> `openai()`, `claude-*` -> `anthropic()`, `gemini-*` -> `google()`.
2. Calls `generateText` from `ai` package with:
   - `model`: resolved from env
   - `system`: `'You are a task-execution agent. Complete the given task using the available tools. When the task is done, respond with a summary of what you accomplished.'`
   - `prompt`: `taskDescription`
   - `tools`: Three tool definitions using `tool()` from `ai`:
     - `llm_call`: parameters from `@claw/tool-contracts` llmCallRequestSchema `.shape.args` (reuse the Zod schema for the args portion), execute calls `callGateway('llm_call', args)`
     - `fetch_url`: parameters from fetchUrlRequestSchema.shape.args, execute calls `callGateway('fetch_url', args)`
     - `write_file`: parameters from writeFileRequestSchema.shape.args, execute calls `callGateway('write_file', args)`
   - `stopWhen: stepCountIs(20)` — maximum 20 tool-call iterations per task
   - `onStepFinish`: log step type and tool call count

**CRITICAL AI SDK 6 API:** Use `stopWhen: stepCountIs(N)` (NOT `maxSteps`). Import `stepCountIs` from `ai`. Also `tool` from `ai`.

3. Returns `result.text` — the model's final text output after all tool calls complete.

**Step 4: Create src/main.ts — BullMQ Worker entry point.**

1. Import `dotenv/config`.
2. Read `BOT_ID`, `EXECUTION_ID`, `REDIS_URL` from env.
3. Parse `REDIS_URL` into `{ host, port }` plain object (same pattern as stub-bot). Add `maxRetriesPerRequest: null` for BullMQ worker connection requirement.
4. Create BullMQ `Worker` on queue `'claw-tasks'`:

   - `lockDuration: 300_000` (5 minutes — real LLM calls take time, per research recommendation)
   - `concurrency: 1` (one task at a time per bot)

Replace the synchronous stub `planObjective(objective, maxTasks)` with an async function:

```typescript
export async function planObjective(objective: string, maxTasks = 3): Promise<PlannedTask[]> {
  // Read model from env, default to gpt-4o-mini for cost efficiency
  const modelId = process.env.PLANNER_MODEL ?? 'gpt-4o-mini';
  const model = resolveModel(modelId); // same provider routing as bot-worker

  const { text } = await generateText({
    model,
    system: `You are a task decomposition agent. Given a high-level objective, break it into ${maxTasks} independent, parallelizable subtasks. Each subtask should be self-contained and completable by a single AI agent with access to tools (llm_call, fetch_url, write_file). Return ONLY a JSON array of objects with a "description" field for each subtask. No other text.`,
    prompt: objective,
    temperature: 0.3, // low temperature for consistent decomposition
  });

  // Parse the LLM response as JSON array
  try {
    const parsed = JSON.parse(text);
    if (!Array.isArray(parsed)) throw new Error('Not an array');
    return parsed.slice(0, maxTasks).map((item: { description?: string }) => ({
      description: item.description ?? String(item),
    }));
  } catch {
    // Fallback: if LLM output isn't valid JSON, split into numbered subtasks (stub behavior)
    console.warn('[planner] LLM output was not valid JSON, falling back to stub decomposition');
    return Array.from({ length: maxTasks }, (_, i) => ({
      description: `${objective.trim()} (subtask ${i + 1} of ${maxTasks})`,
    }));
  }
}
```

Add `resolveModel()` helper (same logic as bot-worker — import from shared location or duplicate for now). Import `generateText` from `ai` and provider packages.
