## Spacing Scale

> **Project exception — locked design system tokens.** The Akasa design system uses a custom spacing scale (4, 8, 14, 20, 28, 40, 60px) that intentionally departs from the standard 8-point grid. These values are defined in both `akasa-design-guide-v2.md §5.1` (CSS variables reference) and `services/ui/src/app.css` (installed tokens). They are not misconfiguration — they reflect the product's editorial rhythm. Do not remap to 8-point multiples.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | 4px | Icon gaps, inline tight padding |
| `--space-sm` | 8px | Compact element spacing, badge padding |
| `--space-md` | 14px | Default element spacing, form field gaps |
| `--space-lg` | 20px | Card padding, section internal padding |
| `--space-xl` | 28px | Section outer padding, grid gaps |
| `--space-2xl` | 40px | Major section breaks, section horizontal padding |
| `--space-3xl` | 60px | Page-level vertical rhythm |

**Section padding** (per design guide §5.2):

| Class | Value | When to use |
|-------|-------|-------------|
| `.section` | `28px 40px` | Standard page sections |
| `.section-tight` | `20px 40px` | Compact sections within a page |

**Card padding** (per design guide §5.3):

| Class | Value | When to use |
|-------|-------|-------------|
| `.card` | `18px 20px` | Default card |
| `.card-compact` | `14px 16px` | Cards inside grids |

**NavBar height exception:** 44px fixed (not on scale). This is the established touch-target minimum. Already in NavBar.svelte.

## Typography

> **Project exception — six type levels.** The Akasa design system specifies six font size levels across three font families. This is intentional: Press Start 2P has two sub-scales (6px eyebrow/status and 7px tag), DM Sans has three (11px caption, 13px UI, 16px body), and Cormorant Garamond has two (18px card title, clamp(26px–38px) page display). All six are defined in `akasa-design-guide-v2.md §4.2` type scale and are in active use across the Phase 3 component library. The checker's 4-level maximum does not apply to this project's multi-font-family system.

> **Project exception — weight 500 for `<strong>`.** The design guide (`akasa-design-guide-v2.md §4.2`) explicitly specifies `font-weight: 500` for `.t-body strong` and similar emphasis elements within body copy. This is a deliberate mid-weight step between regular (400) and semibold (600), used only for inline emphasis inside body prose. Weight 500 is reserved for this single use case — `<strong>` within DM Sans body copy. All other weights remain 400 or 600.

Source: `akasa-design-guide-v2.md §4`, `services/ui/src/app.css`, DS-04.

| Role | Font | Size | Weight | Line Height | When to use |
|------|------|------|--------|-------------|-------------|
| Body | DM Sans | 16px | 400 | 1.65 | All paragraph text, descriptions, form help text (base body from app.css) |
| Body prose / longform | DM Sans | 14px | 400 | 1.8 | Accordion body text, modal body, panel body — uses `.t-body` class |
| UI / small body | DM Sans | 13px | 400 | 1.5 | Table cells, input labels, form fields, sub-captions |
| Caption | DM Sans | 11px | 400 | 1.55 | Supporting metadata, timestamps, secondary labels (italic) |
| Card title / heading | Cormorant Garamond | 18px | 600 | 1.2 | Card titles, section headings, agent names in detail views |
| Page display | Cormorant Garamond | clamp(26px, 3.5vw, 38px) | 600 | 1.1 | Page-level titles (INDRA briefing header, OFFICE header) |
| Tag / label | Press Start 2P | 6–7px | 400 | n/a | Status badges, tier badges, nav tabs, eyebrows, metric labels |

**Weights in use:** 400 (regular), 500 (body emphasis only — `<strong>` within DM Sans prose), and 600 (semibold — Cormorant headings, CTAs). No other weights.

**Emphasis rule:** `<strong>` within body copy uses weight 500 and `--bo-text` (Back Office) or `--ink` (Front Office). This is the only valid use of weight 500. Never use bold for decorative purposes.

**Cormorant minimum:** 16px. Never use Cormorant Garamond below 16px.

**Press Start 2P maximum:** 8px. Never use Press Start 2P above 8px or for readable sentences.

## Route and Page Interaction Contract

### `/auth` — Sign-in page

- Single full-viewport page, Front Office mode, no NavBar
- Centered sign-in card: Akasa wordmark + gem logo, "Sign in with Google" button
- Button style: `--fo-plum` fill, white text, DM Sans 13px weight 600
- No email/password inputs — Google OAuth only (D-02)
- After sign-in: redirect to `/indra` (D-04)

### `/indra` — Fleet briefing

- Full-width layout below 44px NavBar
- **Focal point:** INDRA identity bar — Akasa gem logo + "INDRA" wordmark in Cormorant Garamond 18px, plum color, centered at top of content area above the fleet stats row. This anchors the CEO briefing metaphor and gives the eye a single point of entry before scanning the data.
- Fleet stats row: MetricTile components for agent count by status (idle/working/complete), total karma, daily cost
- Activity feed: chronological list of recent events (agent state changes, task completions)
- Pending approvals section: action-item list style (approve/dismiss inline, no separate page)
- Data: loaded in `+page.server.ts` from `GET /companies/:id/dashboard` and `GET /companies/:id/activity`
- Empty state: no MetricTile values animate in — show "—" placeholder, not zero
- WebSocket events update agent status counts reactively without page reload

### `/office` — Operational management

- Two-panel layout: left sub-nav (agents / issues / goals / projects) + right content area
- Sub-nav style: vertical sidebar, 160px wide, sticky, items use Press Start 2P 6px labels
- Active sub-section: `--accent` fill on nav item
- Agent list (`/office/agents`): MechanicCard grid, 3 columns on desktop, 1 on mobile
- Agent detail (`/office/agents/:id`): full-width detail with tier badge, status, assigned tasks, soul summary
- Agent create (`/office/agents/new`): SlidePanel or full page form — executor to decide based on form length
- Issues (`/office/issues`): table layout, sortable columns (status, priority, assignee, created)
- Issue detail (`/office/issues/:id`): header + comments thread using Accordion for older comments
- Goals and projects: list + detail pattern matching issues
- Data: loaded in `+page.server.ts` for each sub-route

### `/chat` — Message threads

- Two-panel layout: left thread list (240px, sidebar), right message panel
- Thread list items: agent avatar with identity color, thread subject, last message preview truncated
- Message panel: ChatBubble components, auto-scroll to latest, typing indicator on WebSocket typing event
- Message input: fixed to bottom of right panel, DM Sans 14px, send on Enter (Shift+Enter for newline)
- Real-time: new messages pushed via WebSocket (D-14, D-15)

### `/sanctum` — Costs and metrics

- Metric tile grid: daily cost, total tokens consumed, active agents, session count
- Costs section: table of recent cost entries by agent and date
- Evolution placeholder: section header visible with "Coming in Phase 5" state (not hidden)
- Back Office mode available via nav toggle — SANCTUM is the primary use case for Back Office in Phase 4

### `/api/[...path]` (proxy)

- No UI. Retargets from Fastify to Paperclip Express (`PAPERCLIP_URL` env var).

## Copywriting Contract

Source: `akasa-design-guide-v2.md §10`, DS-12.

| Element | Copy | Notes |
|---------|------|-------|
| Primary CTA - sign in | "Sign in with Google" | Sentence case, no em dash |
| Primary CTA - create agent | "Add agent" | Verb + noun, lowercase |
| Primary CTA - send message | "Send message" | Verb + noun pattern — do not shorten to "Send" |
| Primary CTA - create issue | "New issue" | Adjective + noun |
| Empty state - agents list | "No agents yet. Add your first agent to start working." | Sentence case, "working" not "running" |
| Empty state - issues | "No issues assigned. Indra will route tasks here as your crew works." | References Indra as task router |
| Empty state - activity feed | "No recent activity. Your crew's work will appear here." | "crew", not "agents" or "bots" |
| Empty state - chat | "No threads yet. Start a conversation with Indra or a crew member." | "crew member" not "agent" |
| Empty state - costs | "No cost data yet. Costs appear as your crew works." | |
| Error - API failure | "Something went wrong. Try refreshing - if this keeps happening, check your connection." | Hyphen not em dash |
| Error - auth failure | "Could not sign in. Make sure you're using your Google account and try again." | |
| Error - 404 page | "Nothing here. Head back to the briefing." | Link to `/indra` |
| Loading states | No spinner text needed — use skeleton loaders (blank card shapes in `--bg2`) | Not "Loading..." |
| Destructive - delete agent | Confirm with: "Remove agent? This can't be undone." Button label: "Remove" | Modal, not inline |
| Destructive - leave chat thread | No confirmation required — non-destructive |
| Agent status labels | "working", "idle", "done", "waiting" | Lowercase, DM Sans, no capitalization |
| Karma references | "Karma" when noun, "karma" when lowercase in sentences | Never "score", "points", or "rating" |
| Mode labels | "Front Office", "Back Office" | Never "Light Mode", "Dark Mode", "Screenplay", "Director's Cut" |

**Voice rules (from design guide §10.1):**
- Sentence case everywhere — not Title Case
- No em dashes — use hyphen with spaces or restructure
- Agents "work", "complete", "act" — never "run" or "execute" as description of state
- Indra speaks in short sentences when generating automated messages

## Page State Reference

Every page that loads data from `+page.server.ts` must handle these three states visually:

| State | Visual treatment |
|-------|----------------|
| Loading | Skeleton loaders — blank `--bg2` rectangles in card shapes, no spinner, no text |
| Empty | Empty state illustration-free: eyebrow label (Press Start 2P 6px) + heading (Cormorant 18px) + body copy (DM Sans 13px) + optional CTA button |
| Error | Error color `--error` inline message, DM Sans 13px, problem + next step copy |
| Populated | Live data, WebSocket subscription active |

**Skeleton loader dimensions:** Match the target content shape. Agent card skeleton: same dimensions as MechanicCard. Metric tile skeleton: same dimensions as MetricTile. No animated shimmer — static `--bg2` fill is sufficient.

## Accessibility Contract

| Requirement | Implementation |
|-------------|---------------|
| Focus rings | Visible on all interactive elements — use `outline: 2px solid --accent-m` |
| Color alone | Never convey state with color alone — pair with label text or icon |
| NavBar keyboard | Tab order: logo, tabs in order (INDRA, OFFICE, CHAT, SANCTUM), gear icon, mode toggle |
| Gear icon | `aria-label="Settings"` on the gear icon button — required because it has no visible text label |
| Error messages | Associated with field via `aria-describedby` |
| Loading states | `aria-busy="true"` on skeleton container |
| Modal | Focus trap via Modal component (already implemented in Phase 3) |
