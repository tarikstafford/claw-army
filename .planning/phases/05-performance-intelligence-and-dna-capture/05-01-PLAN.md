**Step 2: Create metrics-computer.ts (PERF-01, PERF-02, PERF-03).**

Create `services/execution-service/src/performance/metrics-computer.ts`.

Export `computeBotMetrics(executionId: string, botId: string): Promise<BotMetrics>`.

`BotMetrics` interface:
```typescript
interface BotMetrics {
  botId: string;
  tasksCompleted: number;
  tasksFailed: number;
  totalTasks: number;
  successRate: number;           // 0-1 ratio
  totalCostCents: number;        // integer cents
  costPerTaskCents: number;      // integer cents per successful task (0 if none completed)
  totalTokens: number;
  tokensPerTask: number;         // 0 if no tasks completed
  toolCallsPerTask: number;      // 0 if no tasks completed
  totalToolCalls: number;
  botHours: number;              // from telemetry
  tasksPerMinute: number;        // tasks_completed / (bot_hours * 60), or 0
  totalRetries: number;          // SUM(attempt_count) - COUNT(*) for tasks with attempt_count > 1
  errorRate: number;             // 0-1 ratio of (failed_tasks + rejected_tool_calls) / total_actions
  idleRatio: number;             // estimated idle time / total runtime
}
```

**CRITICAL: Do NOT read from `bots.tasksCompleted` or `bots.tasksFailed` — these are always 0.**

Data sources:
- Task counts: `SELECT COUNT(*) FROM tasks WHERE claimed_by_bot_id = $botId AND status = 'completed'` and `status = 'failed'` (Drizzle `count()` + `eq` + `and`).
- Cost: `SELECT COALESCE(SUM(amount_cents), 0) FROM billing_events WHERE bot_id = $botId AND event_type = 'tool_invoked'` (Drizzle `sum()` on billingEvents).
- Token usage: `SELECT COALESCE(SUM(total_tokens), 0) FROM tool_invocations WHERE bot_id = $botId AND rejected = false`.
- Tool call count: `SELECT COUNT(*) FROM tool_invocations WHERE bot_id = $botId AND rejected = false`.
- Rejected calls: `SELECT COUNT(*) FROM tool_invocations WHERE bot_id = $botId AND rejected = true`.
- Bot hours: `SELECT metric_value FROM telemetry WHERE bot_id = $botId AND metric_name = 'bot_hours'` (single row, numeric).
- Retries: `SELECT COALESCE(SUM(attempt_count), 0) FROM tasks WHERE claimed_by_bot_id = $botId` — retries = sum(attempt_count) - total_tasks.

Use Drizzle ORM queries with `sql<number>` template literals matching the guardrail-watchdog.ts aggregation pattern: `sql<number>\`cast(count(*) as int)\``.

Guard all divisions by zero:
- `costPerTaskCents`: if `tasksCompleted === 0`, return 0
- `tokensPerTask`: if `tasksCompleted === 0`, return 0
- `toolCallsPerTask`: if `tasksCompleted === 0`, return 0
- `tasksPerMinute`: if `botHours === 0`, return 0
- `successRate`: if `totalTasks === 0`, return 0
- `idleRatio`: if `botHours === 0`, return 0

For idleRatio: estimate active time as `(totalToolCalls * avgDurationMs) / (botHours * 3600000)`. Query `AVG(duration_ms)` from tool_invocations for the bot. `idleRatio = 1 - activeRatio`, clamped to [0, 1].

**Step 3: Create score-engine.ts (PERF-04, PERF-05).**

Create `services/execution-service/src/performance/score-engine.ts`.

Export `computeScoresForExecution(executionId: string): Promise<void>`.

This function:
1. Loads all bots for the execution: `SELECT id FROM bots WHERE execution_id = $executionId`.
2. Calls `computeBotMetrics(executionId, botId)` for each bot.
3. **Normalizes** each component across all bots in the execution:
   - `success_rate_score = successRate * 100` (already 0-100 after * 100, no cross-bot normalization needed — it's an absolute percentage).
   - `efficiency_score`: Composite of tasks/min, tokens/task (inverted — fewer is better), tool_calls/task (inverted), idle_ratio (inverted). Normalize each sub-metric against execution min/max, then average. **Guard**: if `max === min`, return 100.
   - `cost_efficiency_score`: Invert cost_per_task: `(maxCost - botCost) / (maxCost - minCost) * 100`. **Guard**: if `maxCost === minCost`, return 100. If `tasksCompleted === 0`, score is 0.
   - `stability_score`: `(1 - errorRate) * 100`. Absolute, no cross-bot normalization.
4. Computes weighted composite: `(success * 0.40 + efficiency * 0.30 + cost_efficiency * 0.20 + stability * 0.10)`. Weights from env vars: `SCORE_WEIGHT_SUCCESS` (default 40), `SCORE_WEIGHT_EFFICIENCY` (default 30), `SCORE_WEIGHT_COST` (default 20), `SCORE_WEIGHT_STABILITY` (default 10). Normalize weights to sum to 1.
5. Assigns tier: `composite >= TIER_HIGH_THRESHOLD (default 75)` -> 'high', `>= TIER_MEDIUM_THRESHOLD (default 40)` -> 'medium', else 'low'. Thresholds from env vars.
6. **Idempotency guard**: Before computing, check `SELECT COUNT(*) FROM telemetry WHERE execution_id = $executionId AND metric_name = 'success_rate_score'`. If > 0, skip (already computed). Log and return.
7. **Stores** four telemetry rows per bot (matching billing-engine.ts recordBotHours pattern):
   ```typescript
   await db.insert(telemetry).values([
     { executionId, botId, metricName: 'success_rate_score', metricValue: successRateScore.toFixed(6) },
     { executionId, botId, metricName: 'efficiency_score', metricValue: efficiencyScore.toFixed(6) },
     { executionId, botId, metricName: 'cost_efficiency_score', metricValue: costEfficiencyScore.toFixed(6) },
     { executionId, botId, metricName: 'stability_score', metricValue: stabilityScore.toFixed(6) },
   ]);
   ```
8. **Updates** bots table:
   ```typescript
   await db.update(bots)
     .set({ compositeScore: composite.toFixed(2), tier })
     .where(eq(bots.id, botId));
   ```
