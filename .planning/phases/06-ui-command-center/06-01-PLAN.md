**SSE route (`services/execution-service/src/routes/sse.ts`):**

Create a Fastify plugin exporting `sseRoutes` (FastifyPluginAsyncTypebox) that registers `GET /:id/events` with `{ sse: true }`.

Implementation following RESEARCH.md Option A (per-connection Pub/Sub subscription):

1. Import `PubSub` from `@google-cloud/pubsub` and `randomUUID` from `node:crypto`
2. Instantiate PubSub with `projectId: process.env.GCP_PROJECT_ID ?? 'claw-local'`
3. On each SSE connection:
   - Generate a unique connection ID via `randomUUID().slice(0, 8)`
   - Create temporary subscriptions on 4 topics: execution-lifecycle, task-lifecycle, bot-lifecycle, guardrail-events
   - Subscription name format: `sse-{executionId.slice(0,8)}-{connId}-{topicName}`
   - For each subscription, attach a message handler that:
     a. Parses message data as JSON
     b. Checks `payload.executionId === request.params.id` — if no match, `message.ack()` and return
     c. If match and `reply.sse.isConnected`, call `reply.sse.send({ event: payload.type, data: JSON.stringify(payload) })`
     d. `message.ack()` on success, `message.nack()` on parse error
4. Register cleanup on BOTH `reply.sse.onClose()` AND `request.raw.on('close', ...)` (Pitfall 7: abnormal disconnects):
   - Remove all listeners from subscriptions
   - `await Promise.allSettled(subs.map(s => s.close()))`
   - `await Promise.allSettled(subs.map(s => s.delete().catch(() => {})))` — wrap delete in try/catch for emulator compatibility (Pitfall 4)
   - Use a `cleanedUp` boolean flag to prevent double cleanup

Topic name env vars must match publisher.ts constants: `EXECUTION_LIFECYCLE_TOPIC`, `TASK_LIFECYCLE_TOPIC`, `BOT_LIFECYCLE_TOPIC`, `GUARDRAIL_EVENTS_TOPIC`.

TypeBox params schema: `Type.Object({ id: Type.String({ format: 'uuid' }) })`.

**Metrics route (`services/execution-service/src/routes/metrics.ts`):**

Create a Fastify plugin exporting `metricsRoutes` (FastifyPluginAsyncTypebox) that registers `GET /:id/metrics`.

1. Import `db`, `bots` from `@claw/db`, `eq`, `and`, `sql` from `drizzle-orm`
2. Import `Redis` from `ioredis` — create a singleton IORedis client (`REDIS_URL` env var, `enableOfflineQueue: true`)
3. For each request:
   - Verify execution exists (same pattern as other routes — getExecution, 404 if not found)
   - Query active bot count: `SELECT COUNT(*) FROM bots WHERE execution_id = :id AND status IN ('spawning', 'idle', 'working')`
   - Query total bot-hours from telemetry: `SELECT SUM(metric_value) FROM telemetry WHERE execution_id = :id AND metric_name = 'bot_hours'`
   - Read Redis keys `budget:spend:{executionId}` and `budget:cap:{executionId}` using `redis.mget()`
   - Return JSON: `{ activeBotCount, totalBotHours, spentCents, budgetCapCents, remainingCents, estimatedCostCents }`
   - `remainingCents = budgetCapCents - spentCents` (floor at 0)
   - `estimatedCostCents = spentCents` (live estimate equals current spend for MVP)
4. Budget values from Redis are strings — parse with `parseInt(value ?? '0', 10)`

CRITICAL: Read budget from Redis (not DB billing_events SUM) — Redis is the authoritative live counter (see RESEARCH.md Pitfall 5).

TypeBox response schema: all fields as `Type.Integer()` except `totalBotHours` as `Type.Number()`.

2. Import `db`, `bots`, `toolInvocations` from `@claw/db`
3. For each request:

   - Return: `{ bot: { id, status, compositeScore, tier, startedAt: createdAt, stoppedAt: updatedAt (if stopped) }, metrics, steps }`

5. TypeBox params: `{ botId: Type.String({ format: 'uuid' }) }`

This fulfills UI-08 (bot metrics) and UI-09 (step trace data).

**Billing routes (`services/execution-service/src/routes/billing.ts`):**

Create a Fastify plugin exporting `billingRoutes` (FastifyPluginAsyncTypebox) with two endpoints:

**GET /history** — list all executions with rolled-up cost, bot-hours, task count:
1. Import `db`, `executions`, `billingEvents`, `telemetry`, `tasks` from `@claw/db`
2. Query all executions ordered by createdAt DESC
3. For each execution, compute:
   - `totalCostCents`: SUM(billing_events.amount_cents) WHERE execution_id AND event_type = 'tool_invoked'
   - `totalBotHours`: SUM(telemetry.metric_value) WHERE execution_id AND metric_name = 'bot_hours'
   - `taskCount`: COUNT(tasks) WHERE execution_id AND status = 'completed'
4. Use a single query with correlated subselects (following report-builder.ts pattern) rather than N+1:
   ```sql
   SELECT e.id, e.objective, e.status, e.created_at,
     (SELECT COALESCE(SUM(be.amount_cents), 0) FROM billing_events be WHERE be.execution_id = e.id AND be.event_type = 'tool_invoked') as total_cost_cents,
     (SELECT COALESCE(SUM(t.metric_value), 0) FROM telemetry t WHERE t.execution_id = e.id AND t.metric_name = 'bot_hours') as total_bot_hours,
     (SELECT COUNT(*) FROM tasks tk WHERE tk.execution_id = e.id AND tk.status = 'completed') as task_count
   FROM executions e ORDER BY e.created_at DESC
   ```
   Use Drizzle `sql` template literal for the subselects.
5. Return array of `{ executionId, objective, status, createdAt, totalCostCents, totalBotHours, taskCount }`

**GET /summary** — monthly totals:
1. Query: SUM(bot_hours) and SUM(cost) across all executions where `created_at >= first day of current month`
2. Use `new Date()` to compute first-of-month in the query:
   ```typescript
   const now = new Date();
   const monthStart = new Date(now.getFullYear(), now.getMonth(), 1);
   ```
3. Return: `{ monthlyBotHours, monthlySpendCents, executionCount }`

This fulfills UI-10, METR-04 (display portion), and METR-05.
