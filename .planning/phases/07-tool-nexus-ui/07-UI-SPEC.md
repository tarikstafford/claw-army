## World Assignment

Tool Nexus UI renders in the **Back Office** world (`body.back-office`).

**Rationale:** Design guide §2 states Director's Cut is "Used for: … integrations." Research §Pitfall 5 confirmed: "Tool Nexus pages should default to Back Office (body.back-office)." Design guide color table explicitly maps Rose to "contractors, Tool Nexus, temporary."

The `/tools` route layout must apply `body.back-office` on mount and remove it on unmount via a Svelte `$effect()`.

## Typography

All sizes from the established design guide §4. Tool Nexus is a Back Office surface — DM Sans is primary, Cormorant Garamond for section heads, Press Start 2P for status tags only.

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Body | DM Sans | 14px | 400 | 1.8 | Tool descriptions, webhook payload text, log entries |
| UI text | DM Sans | 13px | 400 | 1.5 | Buttons, inputs, table cells, form labels |
| Section heading | Cormorant Garamond | 18px | 600 | 1.2 | Category headers (CRM, Communication, Data), page section titles |
| Status tag | Press Start 2P | 7px | 400 | 1.0 | Status badges only: CONNECTED, EXPIRED, ERRORED, RATE LIMITED, DISCONNECTED |

Weight set: 400 (regular) + 600 (semibold). No other weights permitted.

Caption/metadata text (last-used timestamp, log timestamps): DM Sans 11px, weight 400, line-height 1.55, color `var(--bo-caption)`.

**Source:** design guide §4.2, STATE.md Phase 03 decisions (Press Start 2P 6-8px rule)

## Color

Tool Nexus is a Back Office world surface. All colors reference `--bo-*` tokens.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `--bo-bg` | `#06050E` | Page background, tool catalog background |
| Secondary (30%) | `--bo-card` | `#100F20` | Tool cards, status panel, log rows, form containers |
| Accent (10%) | `--bo-rose` | `#F472B6` | Tool Nexus accent — specific elements listed below |
| Destructive | `--error` | `#f87171` | Disconnect confirmation, connection error state |

**Accent (`--bo-rose`) reserved exclusively for:**
- Section heading "TOOLS" in the nav bar tab
- Category section label underline/indicator
- "Connect" CTA button border (not fill — use transparent background with rose border)
- Tool Nexus page header title accent dot or underline
- Active tab indicator on the CATALOG / MY TOOLS / WEBHOOKS tab bar

**Semantic status colors (not accent):**
- `connected` → `--bo-teal` (`#2DD4BF`) — execution/active semantic meaning
- `expired` → `--bo-amber` (`#FBBF24`) — needs attention
- `rate_limited` → `--bo-amber` (`#FBBF24`) — same as expired
- `errored` → `--error` (`#f87171`) — system error
- `disconnected` → `--bo-faint` (`rgba(236, 232, 255, 0.24)`) — inactive

**Text colors:**
- Primary text: `--bo-text` (`#ECE8FF`)
- Secondary / descriptions: `--bo-muted` (`rgba(236, 232, 255, 0.52)`)
- Captions / timestamps: `--bo-caption` (`rgba(236, 232, 255, 0.42)`)
- Faint labels: `--bo-faint` (`rgba(236, 232, 255, 0.24)`)

Border: `--bo-border` (`rgba(148, 110, 255, 0.13)`) default, `--bo-bhi` on hover/active states.

**Source:** `app.css` lines 22-36, RESEARCH.md §Pattern 4, design guide §3.1

## Layout Contract

Three tabs rendered as a horizontal tab bar immediately below the global NavBar:

```
[ CATALOG ]  [ MY TOOLS ]  [ WEBHOOKS ]
```

- Font: Press Start 2P, 7px, letter-spacing 0.10em
- Active tab: border-bottom 2px solid `--bo-rose`, color `--bo-text`
- Inactive tab: color `--bo-faint`, no border
- Tab bar background: `--bo-bg`, border-bottom: `1px solid var(--bo-border)`
- Tab height: 44px (touch target compliance)
- Tab padding: 0 `--space-xl` (28px horizontal)

### Tool Catalog Grid (`/tools/catalog`)

- Layout: CSS grid, `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))`
- Category section heading: Cormorant Garamond 18px, weight 600, color `--bo-text`, `margin-bottom: var(--space-md)`
- Category separator: `--space-xl` (28px) between category groups
- Page padding: `--space-2xl` (40px) top, `--space-xl` (28px) horizontal

### Tool Card

- Background: `--bo-card`
- Border: `1px solid var(--bo-border)`
- Border-radius: `--radius-lg` (8px)
- Hover: border-color `--bo-bhi`, card lifts with `transform: translateY(-2px)`, transition `0.15s ease`
- Internal padding: `--space-lg` (20px)
- Tool name: DM Sans 13px, weight 400, color `--bo-text`
- Tool description: DM Sans 13px, weight 400, color `--bo-muted`, margin-top `--space-xs`
- Category label: Press Start 2P 7px, color `--bo-faint`, margin-bottom `--space-sm`
- Connect button: min-height 44px, border `1px solid var(--bo-rose)`, color `--bo-rose`, background transparent, DM Sans 13px weight 400, border-radius `--radius-md`
- Connect button hover: background `rgba(244, 114, 182, 0.08)`, transition `0.15s ease`
- Status badge: rendered in top-right corner of card when connected

### Tool Belt List (`/tools/belt`)

- Layout: vertical list with `gap: var(--space-sm)` (8px)
- Each row: `--bo-card` background, `--space-lg` padding, `--radius-md` border-radius

Two sub-sections stacked vertically:

## Interaction Contract

### OAuth Connect Flow

1. User clicks "Connect" on a tool card
2. `window.location.href` redirects to `/api/akasa/tool-connections/oauth/:toolId/start?userId=...`
3. Provider OAuth page opens (full page redirect, not popup)
4. On success: provider redirects to `/tools?connected=:toolId`
5. `/tools` root page reads `?connected=` query param and shows a success toast, then redirects to `/tools/belt`
6. On failure: provider redirects to `/tools?error=oauth_failed&tool=:toolId` — show error toast

Toast pattern: fixed position bottom-right, background `--bo-card`, border `1px solid var(--bo-teal)` (success) or `1px solid var(--error)` (failure), auto-dismiss after 4 seconds, DM Sans 13px.

### Re-auth for Expired Connections

The "Re-auth" button on an expired connection in the Tool Belt calls the same `startOAuth(toolId)` function as the initial connect. It is not a separate code path. Label: "Re-authorise" (not "Connect" — context-specific label).

### Disconnect

1. User clicks "Disconnect" on a connected tool
2. `Modal` component opens with confirmation: "Disconnect [Tool Name]?"
3. User confirms → `DELETE /api/akasa/tool-connections/:id`
4. On success: tool card updates to disconnected state, status badge changes to DISCONNECTED
5. On failure: error toast, modal closes

### Copy Webhook URL

1. Webhook URL is displayed in a read-only `<input>` with a "Copy" button
2. Click → `navigator.clipboard.writeText(url)` — no library required
3. Button label changes to "Copied" for 2 seconds, then reverts

### Create Routing Rule

1. User fills rule form in SlidePanel: event type (dropdown), condition (optional text input), assign-to agent (dropdown)
2. Agent dropdown populated from `GET /api/companies/:companyId/agents`
3. Event type dropdown is a static map per tool (hardcoded for v6.0):
   - HubSpot: `deal.created`, `contact.created`, `company.created`
   - Slack: `message`
   - Google Sheets: `row.added`
4. Submit → `POST /api/akasa/webhook-routing-rules`
5. On success: SlidePanel closes, rule appears in list
6. Validation: event type required, agent required; condition is optional

### Delete Routing Rule

1. "Delete" button on a rule row opens `Modal` confirmation
2. User confirms → `DELETE /api/akasa/webhook-routing-rules/:id`
3. Row removed from list on success

## States Required

Every data surface must implement all four states:

| Surface | Loading | Empty | Populated | Error |
|---------|---------|-------|-----------|-------|
| Tool catalog | Skeleton cards (3 per category, `--bo-card` background, animated shimmer via opacity pulse) | "No tools available" | Tool grid by category | "Failed to load integrations. Refresh to retry." |
| Tool Belt | Skeleton list rows | "No tools connected" empty state | Connected tool rows | "Failed to load connected tools." |
| Routing rules list | Skeleton rows | "No routing rules" empty state | Rule rows | "Failed to load routing rules." |
| Webhook event log | Skeleton rows | "No webhook events yet" empty state | Log entries with Accordion expansion | "Failed to load webhook events." |

Skeleton animation: `opacity` pulses from 0.4 to 0.7 on a 1.2s ease-in-out loop, `background: var(--bo-card)`, `border-radius: --radius-sm`. No external skeleton library — implement with `@keyframes`.

## Accessibility Contracts

- All interactive elements minimum 44px touch target height
- Status badges use both color and text (not color alone) — CONNECTED/EXPIRED text appears alongside the color
- Connect button text is never "Click here" — always the specific action label
- Error messages are associated with their form fields via `aria-describedby`
- Modal traps focus while open (existing Modal.svelte handles this per Phase 3 implementation)
- SlidePanel traps focus while open (existing SlidePanel.svelte handles this per Phase 3)
- Webhook URL input is `readonly` with explicit `aria-label="Webhook URL"`
- Event log table has `<th>` elements with scope attributes if rendered as a table; if rendered as a list, each row has a visible label
