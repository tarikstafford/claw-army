| Property | Value |

## Spacing Scale

The project spacing scale from `app.css` is authoritative. Phase 8 uses it without deviation.

This spec references spacing tokens by CSS custom property name only. Raw pixel values are defined in `services/ui/src/app.css` lines 54–61 and are outside this phase's jurisdiction.

| Token | Usage |
|-------|-------|
| `var(--space-xs)` | Icon gaps, inline padding, badge internal spacing, score delta indicator gap |
| `var(--space-sm)` | Between timeline event icon and label, between class count and class name, gap within ledger table cells |
| `var(--space-md)` | Default element spacing, form field gap, timeline event row padding, benchmark card padding |
| `var(--space-lg)` | Section card internal padding, fleet class grid cell padding |
| `var(--space-xl)` | Between dashboard sections (fleet grid, pending verdicts, benchmark list), page content gap |
| `var(--space-2xl)` | Page top padding, between major section breaks (timeline vs ledger on bot detail page) |
| `var(--space-3xl)` | Reserved for major page-level top padding on first section |

Exceptions:
- Touch targets for approve/reject verdict buttons minimum 44px height — use `min-height: 44px` inline.
- Lineage tree SVG: internal node spacing is controlled by `d3-hierarchy tree().size([480, 240])` — not CSS spacing tokens. Node radius is fixed at 10px per RESEARCH.md §Pattern 3.

**Source:** `services/ui/src/app.css` lines 54–61, RESEARCH.md §Pattern 3

## Typography

Evolution Dashboard is a Back Office surface showing data-dense technical information. DM Sans is primary. Cormorant Garamond for section headings. Press Start 2P for class/status badges only.

Exactly 4 font sizes declared. The 13px size covers body text, table cells, and all UI interactive elements.

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Body / UI text | DM Sans | 13px | 400 | 1.5 | Timeline event summaries, ledger table cells, benchmark values, verdict evidence text, button labels, form inputs |
| Section heading | Cormorant Garamond | 18px | 600 | 1.2 | Page section titles ("Fleet Overview", "Pending Verdicts", "Category Benchmarks"), bot detail page heading |
| Caption | DM Sans | 11px | 400 | 1.55 | Timestamps in timeline and ledger, "First in [category]" pioneer date, score delta values — color `var(--bo-caption)` |
| Status / class tag | Press Start 2P | 7px | 400 | 1.0 | Agent class badges (NOVICE, UNDERSTUDY, ARTISAN, RETIRED), verdict type tags (PROMOTE, MAINTAIN, MONITOR, DEMOTE, RETIRE), pioneer badge |

Weight set: 400 (regular) + 600 (semibold). No other weights permitted.

Design guide exceptions carried forward from Phase 3:
- ChatBubble sender label uses 5px Press Start 2P — only applies in chat context, not Evolution Dashboard.
- MetricTile value uses 20px Press Start 2P — MetricTile component may be reused for fleet class counts (e.g. "12 NOVICE"); if MetricTile is used, its 20px value rule applies to that component only.

**Source:** design guide §4.2, STATE.md Phase 03 decisions (Press Start 2P 6-8px rule, MetricTile 20px exception)

## Color

Evolution Dashboard is a Back Office world surface. All colors reference `--bo-*` tokens. The dominant semantic accent for evolution is `--bo-violet` (coordination/mechanics). Pioneer treatments use `--bo-amber` exclusively.

| Role | Token | Hex | Usage |
|------|-------|-----|-------|
| Dominant (60%) | `--bo-bg` | `#06050E` | Page background, timeline track background |
| Secondary (30%) | `--bo-card` | `#100F20` | Fleet class cells, benchmark cards, ledger rows, timeline event rows, verdict confirmation widgets |
| Accent (10%) | `--bo-violet` | `#7C3AED` | Evolution accent — specific elements listed below |
| Pioneer accent | `--bo-amber` | `#FBBF24` | Pioneer badge, pioneer tree nodes, benchmark pioneer row highlight — amber is non-negotiable per REQUIREMENTS.md DASH-07 |
| Destructive | `--error` | `#f87171` | Reject verdict confirmation only |

**Accent (`--bo-violet`) reserved exclusively for:**
- Active tab indicator on the FLEET / AGENTS / BENCHMARKS tab bar within `/evolution`
- "EVOLUTION" tab in the global NavBar (active state underline)
- Lineage tree node default stroke (`--bo-vb` / `#A78BFA` per RESEARCH.md §Pattern 3)
- Verdict type tag backgrounds for PROMOTE and MAINTAIN verdicts (`rgba(124, 58, 237, 0.10)`)

**Amber (`--bo-amber`) reserved exclusively for:**
- Pioneer badge text and border in BenchmarkCard
- Pioneer benchmark row left border accent (3px solid `--bo-amber`)
- Lineage tree archetype node stroke and pioneer node fill overlay (`rgba(251, 191, 36, 0.15)`)
- "PIONEER" label tag text color

**Semantic verdict colors (not accent):**
- `PROMOTE` → `--bo-violet` (`#7C3AED`) — positive/advancement
- `MAINTAIN` → `--bo-muted` (`rgba(236, 232, 255, 0.52)`) — neutral
- `MONITOR` → `--bo-teal` (`#2DD4BF`) — watching/attention
- `DEMOTE` → `--bo-rose` (`#F472B6`) — negative signal
- `RETIRE` → `--error` (`#f87171`) — end-of-life signal

**Semantic class colors:**
- `ARTISAN` → `--bo-amber` (`#FBBF24`) — peak class, gold treatment
- `UNDERSTUDY` → `--bo-vb` (`#A78BFA`) — progressing
- `NOVICE` → `--bo-muted` — base class, no emphasis
- `RETIRED` → `--bo-faint` (`rgba(236, 232, 255, 0.24)`) — inactive

**Text colors:**
- Primary text: `--bo-text` (`#ECE8FF`)
- Secondary / descriptions: `--bo-muted` (`rgba(236, 232, 255, 0.52)`)
- Captions / timestamps: `--bo-caption` (`rgba(236, 232, 255, 0.42)`)
- Faint labels: `--bo-faint` (`rgba(236, 232, 255, 0.24)`)

Border: `--bo-border` (`rgba(148, 110, 255, 0.13)`) default, `--bo-bhi` on hover/active states.

**Source:** `app.css` lines 22–36, design guide §3.1, REQUIREMENTS.md DASH-07, RESEARCH.md §Pattern 3

## Layout Contract

### Global NavBar Extension

The global NavBar (`lib/components/NavBar.svelte`) requires a 6th tab entry:

```typescript
{ href: '/evolution', label: 'EVOLUTION', key: 'evolution' }
```

The `activeTab` type union must include `'evolution'`. Tab font is Press Start 2P 7px. Active underline uses `--bo-violet` (not `--bo-rose` — evolution is violet-domain). No special treatment in the global nav beyond the standard active underline pattern.

**Source:** RESEARCH.md §NavBar Extension

### Sub-navigation (`/evolution` layout)

Three tabs rendered as a horizontal tab bar immediately below the global NavBar:

```
[ FLEET ]  [ AGENTS ]  [ BENCHMARKS ]
```

- Font: Press Start 2P, 7px, letter-spacing 0.10em
- Active tab: border-bottom 2px solid `--bo-violet`, color `--bo-text`
- Inactive tab: color `--bo-faint`, no border
- Tab bar background: `--bo-bg`, border-bottom: `1px solid var(--bo-border)`
- Tab height: 44px (touch target compliance)
- Tab padding: `0 var(--space-xl)` horizontal

### Fleet Overview Page (`/evolution`)

Composed of three stacked sections:

**Section 1 — Class Distribution Grid:**
- Layout: CSS grid, `grid-template-columns: repeat(4, 1fr)`, `gap: var(--space-md)`
- Each class cell: `--bo-card` background, `var(--space-lg)` padding, `--radius-lg` border-radius, `1px solid var(--bo-border)`
- Class count: MetricTile component with 20px Press Start 2P value
- Class name: Press Start 2P 7px below the count, color per class semantic color mapping above
- ARTISAN cell exception: `border-color: rgba(251, 191, 36, 0.32)`, count color `--bo-amber`
- RETIRED cell: opacity 0.6 on entire cell (visually de-emphasized)

**Section 2 — Pending Verdicts:**
- Only rendered when `pendingVerdictCount > 0`
- Heading: Cormorant Garamond 18px, weight 600, color `--bo-text`
- Verdict rows: vertical list, `gap: var(--space-sm)`
- Each row: `--bo-card` background, `var(--space-lg)` padding, `--radius-md` border-radius, `1px solid var(--bo-bhi)`
- VerdictConfirm widget inline within each row

**Section 3 — Agent List:**
- Layout: vertical list using MechanicCard for each bot
- Shows bot name, current class badge, composite score, last verdict timestamp
- Clickable — navigates to `/evolution/[botId]`

Page padding: `var(--space-2xl)` top, `var(--space-xl)` horizontal.
Section gaps: `var(--space-xl)` between sections.

### Bot Detail Page (`/evolution/[botId]`)

Three stacked sections on one page:

**Section 1 — Lineage Tree (DASH-03):**
- Width: 480px fixed SVG within a scrollable card container
- SVG background: `--bo-card`, `--radius-md`, `var(--space-md)` padding
- Section heading: "Soul Lineage", Cormorant Garamond 18px, weight 600

**Section 2 — Evolution Timeline (DASH-02):**
- Vertical list of timeline events, sorted newest-first
- Timeline track: 2px vertical line using `--bo-border`, left-aligned
- Event dot: 8px circle on the track line, color by event type:
  - `verdict` → `--bo-violet`
  - `class_transition` → `--bo-amber`
  - `dna_capture` → `--bo-teal`
- Event row: summary text DM Sans 13px `--bo-text`, timestamp DM Sans 11px `--bo-caption`
- Section heading: "Evolution Timeline", Cormorant Garamond 18px, weight 600

**Section 3 — Experiment Ledger (DASH-04):**
- Table layout: CSS grid with fixed columns: Run Date | Score | Delta | Verdict | Status | Mutation | Outcome
- Table header: Press Start 2P 6px, color `--bo-faint`, letter-spacing 0.10em
- Table rows: DM Sans 13px, `var(--space-sm)` vertical padding, `var(--border-md)` separator
- Score delta: positive values color `--bo-teal`, negative values color `--bo-rose`, zero/null renders "—"
- Outcome cell: `keep` → `--bo-teal`, `discard` → `--bo-rose`, `pending` → `--bo-faint`
- Section heading: "Experiment Ledger", Cormorant Garamond 18px, weight 600

Section gaps: `var(--space-2xl)` between sections.

### Benchmarks Page (`/evolution/benchmarks`)

- Layout: vertical list of BenchmarkCard rows
- Category filter tabs (inline pill buttons): task category names, `--bo-card` default, `--bo-violet` border active
- Each BenchmarkCard: `--bo-card` background, `var(--space-lg)` padding, `--radius-md` border-radius
- Pioneer row treatment: left border `3px solid var(--bo-amber)`, pioneer badge rendered in top-right corner
- Non-pioneer row: no left border
- Thin-data row treatment: italic caption "Fewer than 3 confirmed runs — benchmark unverified" in `--bo-caption`
- Mature benchmark indicator: "CONFIRMED" tag in Press Start 2P 6px, `--bo-teal` color

## Interaction Contract

### Approve Verdict (DASH-06)

1. User sees a pending verdict row on the Fleet Overview page with bot name, verdict type, and composite score
2. Accordion expansion (using existing Accordion.svelte) reveals the evidence fields (reasoning, scores)
3. User clicks "Approve" button → `PATCH /api/akasa/verdicts/:id/confirm` with `{ confirmedBy: 'user' }`
4. On success: row disappears from pending list (optimistic removal), pending count decrements
5. On failure: error toast, row state restored

### Reject Verdict (DASH-06)

1. User clicks "Reject" button on a pending verdict row
2. `Modal` opens: "Reject [VerdictType] verdict for [BotName]?"
3. User confirms → `PATCH /api/akasa/verdicts/:id/reject` with `{ confirmedBy: 'user' }`
4. On success: row disappears from pending list
5. On failure: modal closes, error toast, row state restored

### Navigate to Bot Detail

1. Clicking any agent row in the Fleet Overview agent list navigates to `/evolution/[botId]`
2. Bot detail page loads timeline, lineage, and ledger data server-side via `Promise.allSettled`
3. Lineage tree SVG renders client-side only — `d3-hierarchy` tree layout computed in `$derived.by()` after hydration

### Lineage Tree Node Click

1. User clicks or focuses a node in the `LineageTree.svelte` SVG
2. A SlidePanel opens (if a SlidePanel pattern is used) or an inline tooltip appears showing soul label, generation number, and whether it is archetype/pioneer
3. Implementation decision: inline tooltip preferred over SlidePanel for this context (SlidePanel is for form flows; soul inspection is read-only). Use a Svelte `$state()` selected node + absolutely-positioned tooltip card.
4. Tooltip card: `--bo-card` background, `1px solid var(--bo-bhi)`, `var(--space-md)` padding, `--radius-md`

## States Required

Every data surface must implement all four states:

| Surface | Loading | Empty | Populated | Error |
|---------|---------|-------|-----------|-------|
| Fleet class grid | Skeleton cells (4 cells, `--bo-card` bg, shimmer animation) | "No agents yet" | Class count tiles | "Failed to load fleet data. Refresh to retry." |
| Pending verdicts list | Skeleton rows | Hidden (section absent) | Verdict rows with approve/reject controls | "Failed to load pending verdicts." |
| Agent list on fleet overview | Skeleton rows (3 rows) | Rendered below class grid with no rows — empty state text | Bot rows clickable to detail | "Failed to load agents." |
| Bot timeline | Skeleton event rows (5 rows) | "No events recorded" empty state | Chronological event list | "Failed to load timeline. Refresh to retry." |
| Lineage tree | Skeleton SVG placeholder (same dimensions, `--bo-card` fill) | Hidden — lineage section omitted if no soul data | SVG tree | "Lineage data unavailable." (inline caption, not error toast) |
| Experiment ledger | Skeleton table rows (5 rows) | "No runs recorded" empty state | Ledger table | "Failed to load experiment ledger. Refresh to retry." |
| Benchmarks list | Skeleton cards (3 cards) | "No benchmarks established" empty state | BenchmarkCard rows | "Failed to load benchmarks. Refresh to retry." |

Skeleton animation: `opacity` pulses from 0.4 to 0.7 on a 1.2s ease-in-out loop, `background: var(--bo-card)`, `border-radius: --radius-sm`. No external library — implement with `@keyframes pulse-skeleton`. Same pattern as Phase 7.

## Accessibility Contracts

- All approve/reject buttons minimum 44px touch target height
- Class badges and verdict badges use both color and text — color alone is never the sole differentiator
- Pioneer treatment uses both amber color AND the "PIONEER" text label
- Score delta uses both color AND sign (positive/negative prefix or explicit "—")
- Lineage tree nodes have `role="button"` and `tabindex="0"` for keyboard navigation
- Lineage tree SVG has `role="img"` with `aria-label`
- Node tooltip has `role="tooltip"` with id linked via `aria-describedby` on the node
- Modal traps focus while open (existing Modal.svelte handles this)
- Error states provide a clear recovery action ("Refresh to retry") not just an error label
- Timeline events rendered as a `<ul>` list for screen reader traversal
- Ledger rendered as a `<table>` with `<th scope="col">` headers
