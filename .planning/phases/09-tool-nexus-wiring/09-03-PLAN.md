**Keep unchanged (already works):**
```json
"@paperclipai/shared": ["../../../paperclip/packages/shared/dist/index.d.ts"],
"@paperclipai/shared/*": ["../../../paperclip/packages/shared/dist/*.d.ts"]
```

**Why this works despite rootDir: ./src:**
- `moduleResolution: Bundler` resolves the paths for type-checking only
- tsc only emits files matching the `include` glob (`src/**/*.ts`)
- Files referenced via `paths` outside `src/` are used for type resolution but not emitted
- The `rootDir` constraint only applies to files that are actually compiled and emitted
- `skipLibCheck: true` skips type-checking of `.d.ts` files, but `.ts` source files referenced via paths are used for their type exports without being emitted to `dist/`

**IMPORTANT:** The previous approach pointed to `.d.ts` files to avoid a rootDir violation. That approach fails because those `.d.ts` files do not exist on disk (packages/db has never been built, akasa-server is not a library that emits declarations). Pointing to `.ts` source files works because `moduleResolution: Bundler` treats path-mapped files as external type sources, not compilation targets.
