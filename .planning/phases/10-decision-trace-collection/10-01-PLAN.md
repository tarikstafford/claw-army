Add a unique constraint on `decision_traces.decision_id` and build the post-hoc attribution compiler that runs after every execution completion — producing per-decision attribution records linking tool invocations, output steps, and reasoning branches to soul directives.

Purpose: The Council (Phase 11) needs causal attribution records in `decision_traces` to evaluate whether agent behavior was driven by specific soul directives. Without these rows, the Soul Analyst cannot perform counterfactual verification (CNCL-04). This plan creates the data pipeline that feeds Phase 11.

  <action>
    **Create `services/execution-service/src/performance/attribution-compiler.ts`:**

    Follow the same file structure as `dna-capture.ts` (same directory, same pipeline pattern). The file exports two functions: `runAttributionCompiler(executionId: string)` and `pruneDecisionTraces()`.

    **Imports:**
    ```typescript
    import { generateText } from 'ai';
    import { openai } from '@ai-sdk/openai';
    import { z } from 'zod';
    import { createHash } from 'node:crypto';
    import { db, bots, botSouls, toolInvocations, tasks, decisionTraces } from '@claw/db';
    import { eq, and, inArray, sql } from 'drizzle-orm';
    ```

    **Constants:**
    - `ATTRIBUTION_MODEL = openai('gpt-4o-mini')` — same model used by soul-generator.ts
    - `ATTRIBUTION_TEMPERATURE = 0.1` — low temperature for consistent attribution
    - `MAX_INVOCATIONS_PER_BOT = 50` — cap per bot to control LLM cost (research recommendation)
    - `DECISION_TRACES_TTL_DAYS = 90` — TTL policy from Phase 8 schema JSDoc
    - `DECISION_TRACES_MAX_ROWS = 5_000_000` — row threshold from Phase 8 schema JSDoc

    **Zod schema for LLM attribution output:**
    ```typescript
    const AttributionSchema = z.object({
      directiveText: z.string(),
      confidence: z.number().min(0).max(1),
      outcome: z.enum(['success', 'failure', 'partial']),
      reasoning: z.string(),
    });
    ```

    **Helper: `makeDeterministicId(seed: string): string`**
    - SHA-256 hash of seed, take first 32 hex chars, format as UUID (8-4-4-4-12)
    - This produces deterministic decision_id values for idempotency

    **Helper: `toUUIDFormat(hex: string): string`**
    - Splits 32 hex chars into UUID format segments joined by hyphens

    **Main function: `runAttributionCompiler(executionId: string): Promise<void>`**

    Pipeline:
    1. Log start: `[attribution-compiler] Starting for execution ${executionId}`
    2. Fetch all bots for the execution: `db.select({ id: bots.id, soulId: bots.soulId }).from(bots).where(eq(bots.executionId, executionId))`
    3. Collect all non-null `soulId` values, bulk-fetch from `botSouls` in one query using `inArray(botSouls.id, soulIds)`. Build a `Map<string, BotSoul>` keyed by soul ID. This avoids the N+1 query pitfall (Research Pitfall 3).
    4. For each bot:
       a. If `bot.soulId` is null, log and `continue` (Research Pattern 6 — skip bots without souls)
       b. Look up soul from the map. If not found, warn and `continue`
       c. Call `attributeBot(executionId, bot.id, bot.soulId, soul)` (see below)
    5. Log completion: `[attribution-compiler] Complete for execution ${executionId}`

    **Wrap the entire function body in try/catch** — log errors but never throw. This function runs inside `runPerformancePipeline` which is already fire-and-forget, but an unhandled error in attribution should not crash the scoring pipeline. Log: `[attribution-compiler] Error: ${err}` and return.

    **Per-bot function: `attributeBot(executionId, botId, soulId, soul)`**

    1. Fetch tool invocations for this bot: `db.select().from(toolInvocations).where(eq(toolInvocations.botId, botId)).orderBy(toolInvocations.invokedAt).limit(MAX_INVOCATIONS_PER_BOT)`
       - Include BOTH accepted and rejected invocations (Research anti-pattern: rejected calls matter for Soul Analyst counterfactual in CNCL-04)
    2. Fetch completed tasks for this bot: `db.select().from(tasks).where(and(eq(tasks.claimedByBotId, botId), eq(tasks.executionId, executionId)))`
    3. If invocations is empty AND completed tasks is empty, log and return (Research Pitfall 6 — bots with no activity)
    4. Extract `soulContent` from `soul.soulContent` (the full SOUL.md markdown)

    **Tool call attribution (decision_type: 'tool_call'):**

    For each invocation (up to MAX_INVOCATIONS_PER_BOT):
    - Find the task description: match `invocation.botId` against tasks where `claimedByBotId = botId`. Use the first task's description as context (approximate — exact task-to-invocation mapping is not tracked in the current schema). If no tasks found, use empty string.
    - Call `attributeInvocation(invocation, soulContent, taskDescription)` — see below
    - Validate verbatim: if `attribution.confidence > 0.5` and `soulContent` does NOT include `attribution.directiveText`, degrade confidence to `Math.min(confidence, 0.3)` and add `validationWarning: 'directive_not_verbatim_in_soul'` to metadata (Research Pitfall 2)
    - Write to `decision_traces` with `onConflictDoNothing()`:
      ```typescript
      await db.insert(decisionTraces).values({
        executionId,
        botId,
        soulId,
        decisionId: makeDeterministicId(`tool_call:${invocation.invocationId}`),
        decisionType: 'tool_call',
        directiveReferenced: attribution.directiveText || null,
        attributionConfidence: attribution.confidence.toFixed(3),
        outcome: attribution.outcome,
        decidedAt: invocation.invokedAt,
        metadata: {
          toolName: invocation.toolName,
          durationMs: invocation.durationMs,
          rejected: invocation.rejected,
          attributionReasoning: attribution.reasoning,
          ...(validationWarning ? { validationWarning } : {}),
        },
      }).onConflictDoNothing();
      ```

    **Output step attribution (decision_type: 'output_step'):**

    For each completed task (`status === 'completed'`):
    - Write one `decision_traces` row:
      ```typescript
      decisionId: makeDeterministicId(`output_step:${task.id}`),
      decisionType: 'output_step',
      directiveReferenced: null,       // no specific directive for output delivery
      attributionConfidence: null,
      outcome: 'success',
      decidedAt: task.updatedAt,
      metadata: { taskId: task.id, taskDescription: task.description.slice(0, 200) },
      ```
    - Use `onConflictDoNothing()` for idempotency

    **Reasoning branch attribution (decision_type: 'reasoning_branch'):**

    One synthesized row per bot — an LLM call that sees the full tool call sequence and attributes the overall reasoning approach to a Decision Priorities directive.

    - Build a tool sequence summary: `invocations.map((inv, i) => \`${i + 1}. ${inv.toolName} (${inv.rejected ? 'rejected' : 'accepted'}, ${inv.durationMs}ms)\`).join('\n')`
    - Count completed vs total tasks for this bot
    - Call `generateText` with system prompt: "You are a soul attribution analyst. Given a SOUL.md and the complete tool call sequence for an agent, identify which Decision Priorities directive most drove the agent's overall approach. Return JSON: { directiveText, confidence, outcome, reasoning }"
    - Parse response with `AttributionSchema`
    - Apply verbatim validation (same as tool_call)
    - Write to `decision_traces`:
      ```typescript
      decisionId: makeDeterministicId(`reasoning_branch:${executionId}:${botId}`),
      decisionType: 'reasoning_branch',
      ```
    - Use `onConflictDoNothing()`

    **LLM attribution helper: `attributeInvocation(invocation, soulContent, taskDescription)`**

    - Wrap in try/catch — on failure, return low-confidence fallback `{ directiveText: '', confidence: 0, outcome: 'partial', reasoning: 'Attribution failed — LLM error' }`. NEVER throw from this function.
    - System prompt: "You are a soul attribution analyst. Given a SOUL.md and a tool invocation, identify which directive VERBATIM from the soul most likely drove this tool call. Return JSON with fields: directiveText (exact quote from SOUL.md), confidence (0-1), outcome (success|failure|partial), reasoning (1 sentence)."
    - User prompt includes: soulContent, invocation toolName, requestSummary (truncated to 500 chars), durationMs, rejected status, task description (truncated to 200 chars)
    - Temperature: `ATTRIBUTION_TEMPERATURE` (0.1)
    - Parse response with `JSON.parse(text)` then `AttributionSchema.parse()`

    **TTL function: `pruneDecisionTraces(): Promise<{ deleted: number }>`**

    Exported for use by the admin route (Plan 02):
    1. Count total rows: `db.select({ total: sql<number>\`cast(count(*) as int)\` }).from(decisionTraces)`
    2. If total < `DECISION_TRACES_MAX_ROWS`, log "below threshold, no pruning" and return `{ deleted: 0 }`
    3. Compute cutoff: `new Date(Date.now() - DECISION_TRACES_TTL_DAYS * 24 * 60 * 60 * 1000)`
    4. Delete: `db.delete(decisionTraces).where(sql\`${decisionTraces.decidedAt} < ${cutoff}\`).returning({ id: decisionTraces.id })`
    5. Log pruned count and return `{ deleted: result.length }`
