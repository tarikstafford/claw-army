  <files>

  <action>
    **1. Import checkExecutionCompletion:**
    ```ts
    import { checkExecutionCompletion } from '../orchestrator/completion-checker';
    ```

    **2. After task success (inside the try block, after updating task to 'completed' and bot to 'idle'):**
    Add a fire-and-forget completion check:
    ```ts
    // Check if all tasks for this execution are now done
    checkExecutionCompletion(executionId).catch((err) => {
      console.error('[openclaw-dispatcher] Completion check failed (non-fatal):', err.message);
    });
    ```
    This is important because the existing completion-checker runs on a polling interval (every 5s). Adding an explicit check after each task completion makes the transition snappier and ensures no race condition where the poller misses the final task.

    **3. In the catch block (task failed), add similar completion check:**
    ```ts
    // A failed task still counts as terminal — check if execution is complete
    checkExecutionCompletion(executionId).catch((err) => {
      console.error('[openclaw-dispatcher] Completion check failed (non-fatal):', err.message);
    });
    ```

    **4. Add explicit logging for the full round-trip to confirm BOT-05:**
    In the success path, add a log line:
    ```ts
    console.log('[openclaw-dispatcher] Round-trip complete — task sent, completed, bot released to idle:', {
      taskId,
      botId,
      executionId,
      durationMs: Date.now() - taskStartMs,
    });
    ```

    **5. In the catch block, write `errorMessage` to the bot if the error is a connection-level failure** (not just a task failure):
    ```ts
    const errMsg = (err as Error).message;
    if (errMsg.includes('not connected') || errMsg.includes('Connection closed')) {
      await db.update(bots).set({
        errorMessage: `Lost connection to OpenClaw during task execution: ${errMsg}`,
        updatedAt: new Date(),
      }).where(eq(bots.id, botId));
    }
    ```
    This ensures connection-level failures during dispatch are surfaced in errorMessage (BOT-04/BOT-06).

    **6. In `waitForAvailableBot`, when the timeout is reached and no bot is available:**
    Do NOT set errorMessage here — the spawn timeout checker (Plan 02) already handles stale spawning bots. The "no bot available" error is a dispatcher-level issue, not a per-bot issue.
