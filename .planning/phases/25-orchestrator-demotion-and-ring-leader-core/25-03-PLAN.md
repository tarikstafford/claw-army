Replace with the new flow:

```
planObjectiveAsTaskGraph -> validatePreFlight -> (reject 400 if invalid) -> spawnRingLeader -> transition to running -> TODO: Ring Leader takes over in Phase 26+
```

**Specific changes:**

1. Add new imports:
   - `planObjectiveAsTaskGraph` from `../services/planner.service`
   - `validatePreFlight` from `../services/preflight-validator`
   - `spawnRingLeader` from `../services/ring-leader-spawner`

2. Remove imports that are no longer used in the POST handler:
   - `generateSoulPopulation` from `../services/soul-generator` (move to unused — keep import only if other routes need it)
   - `addTaskToQueue` from `../queue/task-queue` (task insertion moves to Ring Leader in Phase 28)
   - `spawnBotsForExecution`, `startIdleChecker`, `startQueueEventListener` from `../orchestrator/bot-orchestrator` (bot spawning moves to Ring Leader)
   - `startCompletionPoller` from `../orchestrator/completion-checker`

3. Replace the `setImmediate` block with:

   ```typescript
   setImmediate(async () => {
     try {
       // 1. Parse objective into task graph (ORCH-01)
       const taskGraph = await planObjectiveAsTaskGraph(objective, allowedTools, maxBots);

       // 2. Pre-flight validation (ORCH-02)
       const preflight = validatePreFlight(taskGraph, allowedTools, budgetCapCents);
       if (!preflight.valid) {
         fastify.log.warn({ executionId, errors: preflight.errors }, 'Pre-flight validation failed');
         await transitionExecution(executionId, 'queued', 'failed');
         // Store first error message on execution for UI display
         await db.update(executions)
           .set({ updatedAt: new Date() })
           .where(eq(executions.id, executionId));
         // TODO: Store preflight errors on execution row (needs schema column — Phase 32 dashboard)
         return;
       }

       // 3. Determine campaign type: 'campaign' if objectiveId is present, 'ad_hoc' otherwise
       const campaignType = objectiveId ? 'campaign' : 'ad_hoc';

       // 4. Spawn Ring Leader — creates ring_leader_runs row with mission brief (ORCH-03)
       const { ringLeaderRunId, missionBrief } = await spawnRingLeader({
         executionId,
         objective,
         taskGraph,
         toolGrants: allowedTools,
         budgetCapCents: budgetCapCents ?? 0,
         runtimeLimitSeconds: runtimeLimitSeconds ?? 3600,
         campaignType,
       });

       // 5. Transition execution to running
       const transitioned = await transitionExecution(executionId, 'queued', 'running');
       if (!transitioned) {
         fastify.log.error({ executionId }, 'Failed to transition to running');
         return;
       }

       await publishExecutionStatusChanged({
         type: 'execution_status_changed',
         executionId,
         fromStatus: 'queued',
         toStatus: 'running',
         timestamp: new Date().toISOString(),
       }).catch((err: Error) => {
         fastify.log.error({ err, executionId }, 'Failed to publish execution_status_changed (non-fatal)');
       });

       fastify.log.info(
         { executionId, ringLeaderRunId, taskCount: taskGraph.tasks.length },
         'Ring Leader spawned — Orchestrator handoff complete (ORCH-04)',
       );

       // ORCH-04: Orchestrator steps back here.
       // Soul selection, agent spawning, coordination, and synthesis
       // will be driven by the Ring Leader in Phases 26-29.
       // The old flow (generateSoulPopulation -> spawnBots -> idleChecker -> completionPoller)
       // is removed — those responsibilities transfer to the Ring Leader.

     } catch (err) {
       fastify.log.error({ err, executionId }, 'Failed during execution pipeline');
       await transitionExecution(executionId, 'queued', 'failed').catch(() => {});
       await transitionExecution(executionId, 'running', 'failed').catch(() => {});
     }
   });
   ```
