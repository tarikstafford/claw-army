**Export interfaces:**

```typescript
import type { SoulSearchResult } from './soul-library-search';
import type { SoulSelectionEntry } from '@claw/shared-types';

export interface PoolSelectionParams {
  pool: SoulSearchResult[];           // ranked search results from soul-library-search
  requiredPopulation: number;         // how many to select
  varianceIntent: string | null;      // rationale for multi-soul assignment (SOUL-07), null if not applicable
}

export interface SelectedSoul extends SoulSelectionEntry {
  soulContent: string;   // needed downstream for SOUL.md injection
  embedding: number[];   // needed for differentiation checks
}

export interface MutationResult {
  mutatedContent: string;
  mutatedEmbedding: number[];
  operation: string;
  rationale: string;
}
```

**Export function `selectFromPool(params: PoolSelectionParams): SelectedSoul[]`:**

1. **Sort pool by class priority (SOUL-04):** Re-sort the pool so Artisans come first, then Understudies, then Novices. Within each class tier, preserve the finalRank ordering from the search.

2. **Greedy selection with differentiation enforcement:** Iterate through the sorted pool. For each candidate:
   - Compute cosine similarity (use `cosineSimilarity` from `ai` package — same as soul-generator.ts) against ALL already-selected souls.
   - If ANY pairwise similarity >= `SOUL_DIFFERENTIATION_THRESHOLD` (0.85 from shared-types), SKIP this candidate.
   - Otherwise, add to selected set.
   - Stop when `requiredPopulation` souls are selected or pool is exhausted.

3. **Build SoulSelectionEntry for each selected soul:**
   - `soulId`: from search result
   - `agentClass`: from search result
   - `source`: 'library'
   - `parentSoulId`: from search result
   - `mutationApplied`: null (mutations applied separately)
   - `selectionRationale`: "Rank #{N} in pool (similarity: {score}, class: {class})" plus varianceIntent if provided
   - `differentiationScore`: minimum cosine distance (1 - max similarity) from any other selected soul. For the first soul, set to 1.0.

4. If fewer than `requiredPopulation` souls could be selected (pool exhausted or all too similar), return what was selected — caller handles the shortfall in pioneer path.

**Export function `applyPreDeploymentMutation(soul: SelectedSoul, operation: 'substitution' | 'amplification', rationale: string): Promise<MutationResult>`:**

(SOUL-05) Apply a single targeted mutation to a selected soul.

1. Only allow 'substitution' or 'amplification' as operations (the two pre-deployment mutations from the PRD). Throw if another operation is passed.

2. Use `generateText` from `ai` with `openai('gpt-4o-mini')` to apply the mutation. System prompt should follow the same pattern as `mutateSoul` in `soul-generator.ts`:
   - For 'substitution': "Replace one Decision Priority with an equally valid alternative that changes the behavior profile. Do not touch Constitution lines."
   - For 'amplification': "Choose one directive from Decision Priorities or Tool Usage Doctrine and rewrite it to be more specific and restrictive. Do not touch Constitution lines."
   - Include the inviolable constitution lines from the soul content (parse `## Ethical Hard Stops` section or extract lines starting with "INVIOLABLE:").

3. Re-embed the mutated content using `embed` from `ai` with `openai.embeddingModel('text-embedding-3-small')`.

4. Return `{ mutatedContent, mutatedEmbedding, operation, rationale }`.

The caller is responsible for updating the `SelectedSoul` entry's `mutationApplied` and `soulContent` fields after mutation.

Import `cosineSimilarity` from `ai`, `generateText` and `embed` from `ai`, `openai` from `@ai-sdk/openai`.
Import `SOUL_DIFFERENTIATION_THRESHOLD` from `@claw/shared-types`.
Import `SoulSearchResult` from `./soul-library-search`.

Add console.log statements for observability: log each selection decision and each skip due to similarity violation.
