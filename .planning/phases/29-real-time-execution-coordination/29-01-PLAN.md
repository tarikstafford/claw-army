Create coordination-loop.ts implementing COORD-01:

1. **CoordinationContext interface** — passed to each coordination module on every poll cycle:
```typescript
interface CoordinationContext {
  runId: string;
  executionId: string;
  missionBrief: RingLeaderMissionBrief;
  registry: ActiveSessionRegistry;
  runState: RingLeaderRunState;
  pollIntervalMs: number;
  startedAt: Date;
}
```

2. **CoordinationModule interface** — extension point for plans 29-02 through 29-05:
```typescript
interface CoordinationModule {
  name: string;
  execute(ctx: CoordinationContext): Promise<void>;
}
```

3. **`buildRunState(ctx)`** — constructs a `RingLeaderRunState` by:
   - `elapsedTimeSeconds`: `(Date.now() - ctx.startedAt.getTime()) / 1000`
   - `budgetConsumedCents`: query `tool_invocations` table for total tokens consumed by bots in this execution, multiply by cost-per-token estimate (use constant `COST_PER_1K_TOKENS_CENTS = 0.3` — placeholder). Sum `totalTokens` from tool_invocations WHERE executionId matches and toolName='llm_call'.
   - `taskStates`: iterate over `missionBrief.taskGraph.tasks`, for each task query the session registry for sessions matching that taskId, categorize by session.status into activeAgents/completedAgents/failedAgents, derive TaskRunStatus from agent states.
   - `objectiveDriftScore`: default to 0 (Plan 29-04 will compute this)
   - `anomalies`: empty array (populated by coordination modules)

4. **`startCoordinationLoop(params)`** — accepts `{ runId, executionId, missionBrief, pollIntervalMs?, modules? }`:
   - Default `pollIntervalMs` to `Number(process.env.COORDINATION_POLL_INTERVAL_MS ?? 30_000)` (COORD-01: configurable, default 30s)
   - Retrieve registry via `getActiveSessionRegistry(runId)`
   - If no registry found, log error and return
   - Start a `setInterval` that on each tick:
     a. Retrieves current registry state
     b. Builds run state via `buildRunState`
     c. Runs each registered coordination module via `module.execute(ctx)`
     d. Persists run state to `ring_leader_runs.runState` via `db.update(ringLeaderRuns).set({ runState, updatedAt: new Date() }).where(eq(ringLeaderRuns.id, runId))`
     e. Checks termination conditions: all tasks completed/failed -> call `stopCoordinationLoop` and transition status to 'synthesizing'
   - Returns a `CoordinationHandle` with `{ stop(), addModule(module) }`

5. **`stopCoordinationLoop(handle)`** — clears the interval, calls `clearCoordinationLog(runId)`

6. **Module-level map** of active coordination handles keyed by runId, with `getCoordinationHandle(runId)` export.

Import from: `agent-spawner.ts` (getActiveSessionRegistry, ActiveSessionRegistry, ActiveSession), `@claw/shared-types` (RingLeaderRunState, TaskState, RingLeaderMissionBrief, TaskRunStatus), `@claw/db` (db, ringLeaderRuns, toolInvocations), `drizzle-orm` (eq, sql, and, sum).

Handle errors in each poll cycle with try/catch — a single failed poll must not crash the loop. Log errors with `[coordination-loop]` prefix.
