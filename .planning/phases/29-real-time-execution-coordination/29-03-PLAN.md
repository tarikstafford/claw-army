Create failure-reallocator.ts implementing COORD-03, COORD-04, COORD-05:

1. **`createFailureReallocator()`** — factory returning a `CoordinationModule` with `name: 'failure-reallocator'`.

2. **Module-level state** per runId:
   - `processedFailures: Set<string>` — sessionIds of failed agents already handled
   - `processedCompletions: Set<string>` — sessionIds of early completions already evaluated

3. **`execute(ctx: CoordinationContext)`** implementation:

   **A. Failure reallocation (COORD-03):**
   - Scan registry for sessions with `status === 'failed'` not in `processedFailures`
   - For each failed session:
     - Determine the taskId from the session
     - Count remaining active agents on the same task
     - **Decision logic:**
       - If remaining active agents >= 1: log reallocation event with `action: 'redistributed'` and rationale "Task {taskId} still has {N} active agents; no replacement needed"
       - If remaining active agents === 0 AND `ctx.runState.budgetConsumedCents < ctx.missionBrief.budgetCapCents * 0.8`: attempt replacement spawn
         - Look up the failed session's soulId and agentClass
         - Query bot_souls for the soul content
         - Call `spawnBot(executionId, soulId, soulContent)` from bot-orchestrator
         - Register the new session in the ActiveSessionRegistry (same pattern as agent-spawner.ts)
         - Log reallocation event with `action: 'replacement_spawned'`
       - If budget too high for replacement: log with `action: 'redistributed'` and rationale "Budget at {X}% — cannot afford replacement spawn"
     - Add to processedFailures

   **B. Early completion evaluation (COORD-04):**
   - Scan registry for sessions with `status === 'completed'` not in `processedCompletions`
   - For each completed session:
     - Determine the taskId
     - Count remaining active agents on the SAME task
     - If all agents for this task are done (no active), check if there are other tasks with active agents that have fewer agents than their `recommendedPopulation` in the mission brief
     - **Decision logic:**
       - If a task exists with active agents below recommended population AND budget allows (< 80% consumed):
         - Log reallocation event with `trigger: 'early_completion'`, `action: 'capacity_redirected'`, rationale explaining which task benefits
         - NOTE: Actually spawning a new agent for a different task would require a new soul assignment. For v1, log the evaluation and recommendation but do NOT auto-spawn (the coordination loop is advisory, not fully autonomous on capacity redirection yet). Mark rationale as "Capacity redirect recommended for {taskId} — manual intervention or future auto-spawn required."
       - If no tasks need additional capacity: log with rationale "No active tasks need additional capacity"
     - Add to processedCompletions

   **C. Guardrail evaluation (COORD-05):**
   - On each failed session, check if the bot row in DB has an `errorMessage` containing guardrail-related keywords ("guardrail", "safety", "blocked", "restricted", "constitution")
   - If guardrail detected:
     - Classification heuristic: if errorMessage contains "constitution" or "INVIOLABLE" -> `soul-driven`; otherwise -> `context-driven`
     - Log reallocation event with `trigger: 'guardrail_trigger'`, `action: 'paused_for_review'` (for soul-driven) or `action: 'redistributed'` (for context-driven)
     - Add the guardrail event description to `ctx.runState.anomalies`

Import: CoordinationContext, CoordinationModule from coordination-loop.ts; logCoordinationEvent from coordination-events.ts; ReallocationEvent from @claw/event-schemas; db, bots, botSouls, tasks from @claw/db; eq from drizzle-orm; spawnBot from ../orchestrator/bot-orchestrator; ActiveSession from agent-spawner.ts; AGENT_COST_CENTS from budget-validator.ts.

All operations wrapped in try/catch — reallocation failure is non-fatal (log WARN, continue).
