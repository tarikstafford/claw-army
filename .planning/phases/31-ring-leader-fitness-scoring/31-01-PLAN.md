  <action>
Create `coordination-scorer.ts` that exports `scoreCoordinationQuality()`.

**Params interface (CoordinationScoringParams):**
- synthesis: RingLeaderSynthesis (from run-synthesis)
- coordinationLog: CoordinationLogEntry[] (from coordination-events)
- missionBrief: RingLeaderMissionBrief (for runtime/budget context)
- runState: RingLeaderRunState (for final state snapshot)

**Return type:** CoordinationScore (from @claw/shared-types)

**Implementation approach — single LLM call (same pattern as performance-judge.ts):**

1. Define a Zod output schema for 4 dimension scores (each z.number().min(0).max(1)):
   - collectiveOutcome
   - driftPrevention
   - reallocationEffectiveness
   - budgetManagement

2. Build a prompt that provides the LLM with:
   - Objective and whether it was achieved (from synthesis.objectiveAchieved + synthesis.achievementRationale)
   - Task completion rate (count synthesis.taskSummary completed vs total)
   - Coordination event counts (intelligenceRoutingEvents, reallocationEvents, reanchoringEvents from synthesis)
   - Drift score (runState.objectiveDriftScore — final value; lower is better)
   - Budget variance (synthesis.budgetVarianceCents — negative is under budget, positive is over)
   - Budget cap and consumed (missionBrief.budgetCapCents, runState.budgetConsumedCents)
   - Runtime limit vs elapsed (missionBrief.runtimeLimitSeconds, runState.elapsedTimeSeconds)
   - Anomalies list (runState.anomalies)
   - Coordination event highlights (last 15 entries from coordinationLog, type + timestamp)
   - Ring Leader self-assessment (synthesis.ringLeaderSelfAssessment)

3. System prompt: "You are a Ring Leader fitness evaluator. Score coordination quality across four dimensions on a 0 to 1 scale. Be evidence-driven — cite specific metrics."

4. Scoring rubric included in prompt (guidelines for the LLM):
   - collectiveOutcome (40%): Based on task completion rate, objective achievement, output quality signals. 1.0 = all tasks complete + objective achieved. Below 0.5 = majority of tasks failed.
   - driftPrevention (25%): Based on final objectiveDriftScore and reanchoring event count. 1.0 = drift stayed below 0.1. 0.0 = drift exceeded 0.5 with no reanchoring attempts.
   - reallocationEffectiveness (20%): Based on reallocation events vs failures. 1.0 = all failures recovered via reallocation. 0.0 = failures occurred with no reallocation response.
   - budgetManagement (15%): Based on budget variance and degradation events. 1.0 = finished under budget with no hard stops. 0.0 = exceeded budget cap.

5. Use `generateText` + `Output.object` with the Zod schema (temperature 0.2). Use `resolveModel()` with env var `COORDINATION_SCORER_MODEL` defaulting to `claude-sonnet-4-6`.

6. On LLM failure: return a fallback CoordinationScore with all dimensions computed deterministically:
   - collectiveOutcome: (completed tasks / total tasks) from synthesis.taskSummary
   - driftPrevention: 1.0 - runState.objectiveDriftScore (clamped 0-1)
   - reallocationEffectiveness: 0.5 (neutral default when LLM unavailable)
   - budgetManagement: budgetVarianceCents <= 0 ? 1.0 : Math.max(0, 1 - (budgetVarianceCents / missionBrief.budgetCapCents))

7. Log: `[coordination-scorer] Scored runId={runId} collectiveOutcome={n} driftPrevention={n} reallocation={n} budget={n}`

Do NOT import from coordination-loop.ts or any module that would create circular dependencies. Only import types from @claw/shared-types and the CoordinationLogEntry type from coordination-events.ts.
