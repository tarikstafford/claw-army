The tests verify route registration and response shape, NOT full end-to-end data flow (that requires a running DB and Pub/Sub). Use `app.inject()` which exercises Fastify routing without a network connection.

**Test cases:**

1. **API-01: Ring Leader routes exist and respond** (4 sub-tests)
   - `GET /ring-leader/runs/by-execution/${uuid}` — expect 404 (no data) not 400/405 (route missing)
   - `GET /ring-leader/runs/by-execution/${uuid}/state` — expect 404 not 400/405
   - `GET /ring-leader/runs/by-execution/${uuid}/events` — expect 404 not 400/405
   - `GET /ring-leader/runs/by-execution/${uuid}/synthesis` — expect 404 not 400/405
   - Use a random valid UUID. A 404 proves the route exists and the handler ran (queried DB, found nothing). A 400 or 405 would mean the route isn't registered.

2. **API-04: Execution SSE route exists**
   - `GET /executions/${uuid}/events` — verify the route is registered by checking response is NOT 404/405. The SSE route with `{ sse: true }` may return differently via inject (Fastify inject may not fully support SSE streaming), so check that statusCode is NOT 405 (method not allowed) and the route is found. If inject returns 200, verify content-type includes `text/event-stream`.
   - Also verify BILLING_EVENTS_TOPIC appears in the sse.ts source (a code-level assertion using a simple grep or import check).

3. **API-05: Lifecycle SSE route exists**
   - `GET /events/lifecycle` — same approach as API-04, verify route registration.

4. **API-06: Calibration endpoint shape**
   - `GET /verdicts/calibration?userId=test-user` — with no DB data, this should return 200 with `{ total: 0, confirmed: 0, rate: 0, warningTriggered: false }` (the aggregate query returns 0 counts for a nonexistent user).
   - Assert response body has all 4 fields: `total`, `confirmed`, `rate`, `warningTriggered`.
   - Assert `warningTriggered` is `false` when total is 0.

**Important:** The tests that query the database (ring-leader lookups, calibration) need the DB connection from `@claw/db`. If the test environment cannot connect to the DB, these tests should be skipped with a clear message. Use a try/catch around `buildApp()` — if it throws due to DB connection failure, skip all tests.

Do NOT mock the database — these are smoke tests meant to verify the real route registration and handler behavior.
