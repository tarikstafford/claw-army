**Part A: api.ts additions**

Add the following functions to `services/ui/src/lib/api.ts` after the existing Phase 17 objectives section:

```typescript
// Phase 37 — Objective Mutations (used by server actions and client-side code)

export async function updateObjective(
  id: string,
  body: Partial<{
    name: string;
    description: string;
    defaultMaxBots: number;
    defaultBudgetCapCents: number;
    defaultRuntimeLimitSeconds: number;
    defaultAllowedTools: string[];
    isArchived: boolean;
  }>,
): Promise<Objective> {
  return apiFetch(`${BASE}/objectives/${id}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  });
}

export async function archiveObjective(id: string): Promise<Objective> {
  return updateObjective(id, { isArchived: true });
}

export async function unarchiveObjective(id: string): Promise<Objective> {
  return updateObjective(id, { isArchived: false });
}
```

Note: These client-side helpers are exported for completeness. However, PATCH /objectives/:id requires auth (verifyAuthToken preHandler). On Vercel, the browser calls VITE_API_URL (which is the execution service directly or an /api proxy). Since PATCH needs an Authorization header and the session token is in an httpOnly cookie (inaccessible to JS), mutations in Plan 37-02 will use SvelteKit server actions that read the cookie server-side. These helpers are still useful if a future API proxy is added.

**Part B: +page.server.ts — Server action for create**

Create `services/ui/src/routes/objectives/new/+page.server.ts` following the exact pattern from `/new-execution/+page.server.ts`:

- `load` function: check `event.locals.auth()`, redirect to /login if no session
- `actions.default`:
  1. Re-check auth
  2. Parse formData: `name` (required, trim), `description` (optional, trim), `defaultMaxBots` (Number, default 5), `budgetCapDollars` (if empty string → omit; else Math.round(Number * 100) for cents), `runtimeLimitMinutes` (if empty string → omit; else Number * 60 for seconds), `allowedTools` via `formData.getAll('allowedTools')`
  3. Validate: if !name → `return fail(400, { error: 'Name is required.', field: 'name' })`
  4. Extract session token from cookies (same pattern as /new-execution)
  5. `fetch(\`${process.env.EXECUTION_SERVICE_URL}/objectives\`, { method: 'POST', ... })` with Bearer token
  6. On success (201): `const created = await res.json() as { id: string }; redirect(303, \`/objectives/${created.id}\`)`
  7. On failure: `return fail(res.status, { error: text || 'Failed to create objective.' })`
  8. On fetch error (catch): `return fail(503, { error: 'Could not reach execution service.' })`

**CRITICAL — Budget/Runtime null handling (Research Pitfall 1):**
- `formData.get('budgetCapDollars')` returns empty string `''` when user clears the field
- Check: `const budgetRaw = formData.get('budgetCapDollars') as string | null; const budgetCapCents = budgetRaw && budgetRaw.trim() !== '' ? Math.round(Number(budgetRaw) * 100) : undefined;`
- Same for runtime: `const runtimeRaw = formData.get('runtimeLimitMinutes') as string | null; const runtimeLimitSeconds = runtimeRaw && runtimeRaw.trim() !== '' ? Number(runtimeRaw) * 60 : undefined;`
- When undefined, omit from JSON body entirely (do NOT send null or 0)
