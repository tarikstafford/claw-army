**Backend — services/execution-service/src/routes/admin.ts:**

Add a `POST /waitlist` handler inside the existing `adminRoutes` function, below the existing `/cleanup/decision-traces` handler. Import `Type` from `@sinclair/typebox`.

The handler:
- Accepts `{ email: string }` body (use `Type.Object({ email: Type.String({ minLength: 3 }) })` — do NOT use `format: 'email'` because AJV v8 ignores format validation by default)
- Validates that `email` contains `@` in handler code (simple check)
- Logs the email: `request.log.info({ email }, 'waitlist signup')` — Cloud Logging captures this in prod
- Returns `{ ok: true }` with status 200
- On validation failure, returns `{ error: 'A valid email address is required.' }` with status 400

Do NOT create a new DB table or migration — logging satisfies the POLISH-01 "stores or forwards" requirement with zero schema churn.

**UI server action — services/ui/src/routes/+page.server.ts (NEW file):**

Create this file following the Phase 37 pattern (`objectives/new/+page.server.ts`) BUT:
- Do NOT add a `load` function — the landing page is public, no auth check
- Do NOT check `event.locals.auth()` — unauthenticated users must be able to submit
- Export a named action `requestAccess` (not `default`)
- Extract `email` from formData, trim, validate contains `@`
- On invalid email: `return fail(400, { error: 'A valid email address is required.' })`
- POST to `${process.env.EXECUTION_SERVICE_URL}/admin/waitlist` with `{ email }` JSON body (note the `/admin` prefix — the admin routes are registered at `/admin`)
- On fetch failure: `return fail(503, { error: 'Could not reach server. Please try again.' })`
- On non-ok response: `return fail(res.status, { error: 'Failed to submit. Please try again.' })`
- On success: `return { success: true }`
