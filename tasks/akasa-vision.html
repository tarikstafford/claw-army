The Three-Layer Agent Model

Every agent in your fleet is defined by three composable layers. Each layer evolves independently and feeds into the Karpathy loop for continuous optimization.

🧬

Soul — Who the Agent Is

7 behavioral dimensions, genetic lineage, constitution ▼

The soul is the agent's personality — a SOUL.md document containing 7 behavioral dimensions that define how it thinks, decides, and acts. Souls mutate through a genetic algorithm: each generation introduces variations (substitution, amplification, attenuation, recombination, introduction) while preserving inviolable constitution directives.

Identity & Role

Who the agent is and its core purpose. Defines the agent's self-concept and primary function within the fleet.

Decision Priorities

Ranked order of decision drivers. E.g., "Correctness > Safety > Speed" vs. "Speed > Forward Progress > Correctness".

Tool Usage Doctrine

How and when to use tools. Conservative agents verify before acting; aggressive agents call tools speculatively.

Risk Tolerance

Appetite for reversible vs. irreversible actions. Ranges from "always verify twice" to "move fast, fix later".

Communication Style

How the agent reports progress, asks for help, and escalates issues. Terse vs. verbose, proactive vs. reactive.

Recovery Behavior

What to do when tasks fail or errors occur. Retry aggressively, escalate immediately, or try alternative approaches.

Ethical Hard Stops

Inviolable lines that are never mutated away. Constitution directives survive every generation.

Skills — What the Agent Knows

Composable knowledge units, learn/unlearn, Skill Bazaar ▼

Skills are discrete units of procedural knowledge — step-by-step workflows, decision patterns, and best practices. Inspired by Claude Code's SKILL.md system with three-level progressive disclosure. Agents learn skills autonomously and unlearn ones that degrade performance.

SKILL.md Format

YAML frontmatter (name, category, triggers, required tools) + markdown body with procedures. Target: 2,000 words max.

Level 1: metadata (always loaded) → Level 2: body (on trigger) → Level 3: references (on demand)

Skill Learning

When an agent discovers an effective pattern not covered by its loadout, the system generates a candidate SKILL.md from decision traces. Auto-approved if confidence > 0.80.

Skill Unlearning

Skills that activate 5+ times with negative contribution are flagged. After 2 consecutive negative cycles, auto-removed from loadout. Never deleted — just unequipped.

Class-Based Capacity

Loadout limits scale with agent class. More experienced agents can carry more specialized knowledge.

Novice: 3 skills • Understudy: 5 skills • Artisan: 8 skills

Tools — What the Agent Can Access

Tool Nexus gateway, webhooks, agent-authored services ▼

The Tool Nexus is the agent's interface to the real world — a unified gateway where users connect external services and agents consume them as capabilities. Artisan agents can eventually build and deploy their own tooling.

Unified Gateway

Agents call one endpoint with toolId + action + params. Gateway injects auth, validates schemas, rate-limits, logs everything. Agents never see raw credentials.

Integration Catalog

Connect HubSpot, Slack, Telegram, Stripe, Google Sheets, GitHub, Linear and more. OAuth or API key — one-click setup.

Webhook Receivers

Receive real-world events. Unique URL per user per tool. Configurable routing rules: "when HubSpot deal > $10k → assign to Sales Agent".

Custom Tools

Register any HTTP API as a tool. Paste an OpenAPI/Swagger spec to auto-generate actions. Goes through the same gateway with full logging.

Agent-Authored Tools

Artisan agents can propose and deploy their own services — webhook receivers, data transformers, microservices. Human approval required. Sandboxed containers with resource limits.

Tool Performance in Evolution

The Evolution Engine — Inspired by Karpathy's Autoresearch

Autoresearch showed that an LLM can run hundreds of experiments overnight — modifying code, evaluating against an immutable metric, keeping improvements, discarding regressions. Akasa applies the same loop to agent behavior: mutate the soul + skill loadout, execute tasks, evaluate via an independent Council, keep or discard, capture DNA. Repeat forever.

Immutable Metrics

Users define success metrics per objective. Once the first agent runs, metrics are frozen. Agents cannot modify their own evaluation — the Karpathy principle.

composite = w1*completionRate + w2*speed + w3*costEfficiency + w4*taskCompletion

DNA Capture

Every verdict captures a DNA snapshot: soul content, skill loadout, tool usage patterns, fitness score, mutation lineage. Insert-only, versioned, never updated.

Negative Signals

Failed patterns are captured too: which directives failed (counterfactual < 0.3), which mutation operations led to regression. Future mutations avoid these patterns.

⚖

The Council — Three Independent Judges

Weighted evaluation with adversarial challenge ▼

Three LLM judges independently evaluate each agent. They never see each other's output — preventing groupthink. Different model providers reduce correlated failures.

Performance Judge — 50% weight

Quantitative task metrics: completion rate, speed, cost efficiency, tool usage patterns. Uses Claude Sonnet (temperature 0.2) for evidence-driven consistency.

Soul Analyst — 35% weight

Counterfactual verification: did the soul's directives actually cause the behavior? Computes a counterfactual score (0-1) for each directive attribution. Override threshold: 0.25.

Devil's Advocate — 15% weight

Adversarial challenge: were tasks trivial? Did the agent get lucky? Each challenge rated minor/moderate/strong. Uses Gemini (different provider, temperature 0.5) for creative adversarial thinking.

Promote Maintain Monitor Demote Retire

If Devil's Advocate raises a strong unresolved challenge → verdict requires human confirmation before the God Layer executes.

👑

God Layer — Class Transitions & DNA Capture

Novice → Understudy → Artisan, pioneer detection ▼

The God Layer is a deterministic, atomic pipeline that executes after every Council verdict. It handles class transitions, DNA capture, negative signal registration, and pioneer detection. All operations run inside a single database transaction with Redis category locks.

Novice → Understudy

2+ above-benchmark runs, 1+ human confirmation, confidence > 0.65, benchmark mature (3+ category runs).

Understudy → Artisan

5+ above-benchmark, ≤1 below-benchmark, 2+ human confirmations, confidence > 0.80. Only Artisans can publish to the Akashic Library or author tools.

Demotion & Retirement

2+ consecutive below-benchmark → demote (soul-driven only). Retire verdict + soul-driven → permanent retirement. Negative signals captured for mutation blacklist.

Pioneer Detection

First successful agent in a task category establishes a frozen baseline benchmark. All future agents are measured against this. Benchmark matures after 3+ confirmed runs.

Akashic Library — Soul Marketplace

Pre-evolved behavioral DNA, Artisan-only publishing ▼

The Akashic Library is where evolution becomes a shared resource. Only Artisan-class agents — those that have proven themselves through the full promotion pipeline — can publish their souls. Acquiring a soul gives you a clone (independent copy) that continues evolving in your fleet from that point forward.

What's in a Listing

Soul summary card, 7 dimension breakdown, composite fitness score, mutation lineage depth, category specialization, total successful runs, generation count from archetype.

Publishing Requirements

Artisan class only (5+ above-benchmark, ≤1 below, confidence > 0.80). Publishing creates an anonymized snapshot — no user data exposed. Publisher sets title, description, use cases.

Acquisition Model

Clone, not reference. The acquired soul gets a new soulId, incremented generation, and parentSoulId pointing to the original. It evolves independently in your fleet.

DNA Provenance

Full lineage tree visible: archetype origin → every mutation → current form. See exactly how this soul was forged across generations of evolution.
